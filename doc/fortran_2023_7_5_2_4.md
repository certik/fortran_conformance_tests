### S7.5.2.4-001: References to the same derived-type definition establish the same type

**Source:** 7.5.2.4 p2, first sentence; J3/24-007, 18 December 2023, PDF 90, printed 76, line 6. NOTE 1 continues on PDF 91. **Class:** Effect.

**Definition:** Data entities declared by reference to the same derived-type definition have the same
derived type. A different local USE name does not create another definition. Type
identity is distinct from type-parameter equality, rank, allocation/association state,
directional type compatibility and the additional conditions on a particular assignment
or call. The unambiguous finite witnesses here use ordinary extensible definitions; the
private-component/SEQUENCE interaction in the last p2 sentence is separately pending
interpretation.

**Diagnostic obligation:** not-required.

**Facets:** `local-definition`, `host-associated-definition`, `use-renamed-definition`, `parameter-values-not-type-identity`.

**Oracle:** Local assignment, internal dummy association and renamed uses of one definition have
initialized value checks. SAME_TYPE_AS is used only with ordinary extensible types. The
PDT run explicitly distinguishes small KIND/LEN values (1,2) and (2,3) while requiring
the same dynamic type; the KIND discriminator never selects an intrinsic representation
and no mismatching-parameter assignment is attempted.

**Oracle limitation:** These are run-effect oracles, not compile-only substitutions when a compiler lacks PDTs
or inquiries. SAME_TYPE_AS is processor dependent when neither dynamic type is
extensible and is not used to judge SEQUENCE/BIND equivalence. Same type alone does not
make differing KIND/LEN/rank or pointer/allocatable associations valid. No negative twin
or undefined-value assertion is inferred.

(PDF 339-343); 16.9.177 p3-p5/NOTE 2 (PDF 452).

### S7.5.2.4-002: Separate derived-type definitions match only under the specified structural conditions

**Source:** 7.5.2.4 p2, remaining sentences; PDF 90, printed 76, lines 6-11, with NOTE 2 and NOTE 3 on PDF 91. **Class:** Effect.

**Definition:** For entities referring to different definitions, sameness requires the same type name in
the definitions, all definitions having SEQUENCE or all having BIND, no PRIVATE
components, and components agreeing in order, name and attributes. Otherwise the derived
types differ. The name comparison is not a comparison of local USE aliases. Agreement of
physical storage, C representations or numeric kind codes cannot replace any of these
conditions.

The paragraph additionally ends with an exclusion involving a SEQUENCE/BIND data entity
and a type with PRIVATE components. That qualification is retained explicitly. Its
interaction with the first same-definition sentence, in particular a same-definition
private-SEQUENCE case, remains source-interpretation work rather than an asserted
self-inequality. No disputed private-type executable is supplied by this draft.

**Diagnostic obligation:** not-required.

**Facets:** `ordinary-definitions-remain-distinct`, `matching-sequence-definitions`, `matching-bind-definitions`, `definition-name-versus-alias`, `component-order-distinction`, `component-name-distinction`, `component-kind-distinction`, `component-rank-distinction`, `pointer-allocatable-attribute-distinction`, `uniform-sequence-or-bind-condition`, `private-component-interpretation`, `canonical-distinguishability-evidence`.

**Oracle:** Matching public SEQUENCE/BIND definitions exchange defined members through explicit
typed Fortran argument association. Other scalar-generic runs distinguish definition
names, component order/names/kinds/ranks/attributes and nonuniform SEQUENCE/BIND flags
without outer-rank or optional-argument shortcuts. Nonextensible cases do not use
SAME_TYPE_AS. The canonical C1514 pair changes only the second SEQUENCE definition
component name and remains separate pending linkage. The private-component final
sentence remains unresolved and has no fixture.

**Oracle limitation:** SAME_TYPE_AS is processor dependent when neither dynamic type is extensible, and SELECT
TYPE guards cannot name SEQUENCE/BIND types under C1166; neither is a substitute here.
Intrinsic == is not defined for general derived values. Intrinsic assignment and
argument association additionally constrain parameters, rank, attributes and defined
state. No layout/size/model comparison, C interoperability coincidence, f2018-only
observation or malformed actual argument is a type-identity oracle.
