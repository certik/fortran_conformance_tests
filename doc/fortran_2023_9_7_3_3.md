### S9.7.3.3-001: Pointer allocate-objects in DEALLOCATE shall have defined association status

**Source:** 9.7.3.3 p1, J3/24-007, 18 December 2023, physical PDF166. **Class:** Restriction.

status; it does not create a portable oracle for querying an undefined pointer.

### S9.7.3.3-003: Pointer targets that are allocatable or associated with dummy arguments or associate names shall not be deallocated

### S9.7.3.3-004: A deallocated pointer shall designate the whole allocated object with matching characteristics

**Source:** 9.7.3.3 p2, J3/24-007, 18 December 2023, physical PDF166. **Class:** Restriction.

**Definition:** If a pointer appears in a DEALLOCATE statement, it shall be associated with the whole of
an object that was created by allocation. The pointer shall have the same dynamic type
and type parameters as the allocated object, and if the allocated object is an array the
pointer shall be an array whose elements are the same as those of the allocated object

### S9.7.3.3-005: Deallocating a pointer target makes other associated pointer statuses undefined

**Source:** 9.7.3.3 p2, J3/24-007, 18 December 2023, physical PDF166. **Class:** Effect.

**Definition:** When a pointer target is deallocated, the pointer association status of any other
pointer that is associated with that target or with a portion of that target becomes
undefined. The listed pointer used for deallocation becomes disassociated through
9.7.3.1 p1; other pointers with undefined association status are not portable inquiry
operands.
