Eight append-only S IDs separate the real restriction and seven effect
requirements. Definitions do not become synthetic executable controls.
Pending canonical source/use evidence is retained for ordering exclusions
and nonextensible dynamic-type contexts.

Allocations and pointers are state-checked before values or ordinary
inquiries. The inactive-state witnesses instead first confirm the inactive
state and then use only the specifically permitted SAME_TYPE_AS inquiry,
with extensible types and defined pointer status. No deferred parameter or
inactive payload is read, and no concrete type is invented for inactive
CLASS(*). TYPE IS checks include kind; character LEN is checked separately.

The finite programs distinguish a declared root from dynamic extensions,
effective arguments from pointer actuals, and selector attributes from
associate-name attributes. SAME_TYPE_AS is used only within its extensible
argument/result premises, never as a compatibility test. TYPEOF/CLASSOF,
universal numerical kind identifiers and representation assumptions are
unnecessary. Unsupported cases keep their original runtime assertions.

### S7.3.2.3-001: Named CLASS declarations require a previously defined derived type

**Source:** 7.3.2.3 p2, PDF 79, printed 65, lines 4-7. **Class:** Restriction.

**Definition:** The derived type in a named CLASS type declaration must already be defined. For a
function result, the FUNCTION statement may specify a type defined within that function
or accessible there by use or host association. CLASS(*) is outside this named-type
premise. Extensibility and dummy/allocatable/pointer eligibility remain separately
required.

**Diagnostic obligation:** context-dependent.

**Facets:** `previous-derived`, `function-prefix-host`, `function-prefix-use`, `ordering-source-use`.

**Oracle:** Two positive controls return allocated initialized CLASS results with a type defined
earlier in the host or imported only inside the function. The use-only control renames
the type in the caller so its prefix cannot succeed merely through that host spelling.

**Oracle limitation:** Every named CLASS type is extensible and every result is ALLOCATABLE. Allocation is
checked before data use. Neither control relies on TYPEOF/CLASSOF or redeclares the
result type after specifying it in the prefix.

**Dependencies:** 7.3.2.1/C705/C708 (PDF 77), 7.5.7.1 (PDF 104), 15.6.2.2 p3-p4 (PDF 354), 19.5.1 use/host
association; 4.1.2/4.2 (PDF 45-46).

### S7.3.2.3-002: A function-prefix CLASS result follows its body-local derived type

**Source:** 7.3.2.3 p2, PDF 79, printed 65, lines 5-9. **Class:** Effect.

**Definition:** A CLASS result whose FUNCTION prefix names a derived type defined inside the function is
interpreted as declared immediately after that definition. The result remains
polymorphic; its ALLOCATABLE or POINTER attribute must be specified as required for a
nondummy CLASS entity and must not redundantly restate the result type.

**Diagnostic obligation:** not-required.

**Facets:** `body-local-polymorphic-result`.

**Oracle:** The function defines a local root and extension, gives its prefix-declared result
ALLOCATABLE, allocates the extension and checks initialized components in a TYPE IS
branch. It sets a checked output sentinel from the result and returns it through a
SOURCE allocation of CLASS(*); the caller checks allocation and rank. The local type is
not moved to the host to appease an implementation.

**Oracle limitation:** The caller cannot name the function-local type, so its allocation/rank observations are
not an independent named-type identity test. The function's actual branch and component
checks supply the local result oracle. The output sentinel starts negative, preventing a
skipped function body from passing. No unsupported result is converted to an empty
compile control.

**Dependencies:** C705/C708; 7.5.7.1 (PDF 104); 9.7.1.1/C937/C950-C951 (PDF 160-161); 11.1.11.2 (PDF
225-226); 15.6.2.2 p3-p4 (PDF 354). The ordinary OUT sentinel is not an assumed-type or
polymorphic dummy.

### S7.3.2.3-003: An allocated polymorphic allocatable has its allocation's type

**Source:** 7.3.2.3 p5, PDF 79, printed 65, line 14. **Class:** Effect.

**Definition:** While an allocatable polymorphic object is allocated, its dynamic type is the type
established by its allocation. The declared type of named CLASS does not become that
extension. Unlimited polymorphic allocation can establish an intrinsic dynamic type.
Allocation eligibility, parameter agreement, rank and SOURCE/MOLD rules are separate
premises.

**Diagnostic obligation:** not-required.

**Facets:** `declared-type-allocation`, `extension-allocation`, `source-dynamic-type`, `unlimited-real-kinds`, `unlimited-character-lengths`.

**Oracle:** Four effect programs distinguish root and multilevel-extension allocations, SOURCE
allocation from an already allocated polymorphic extension, separate default/double REAL
allocations, and CHARACTER allocations of different lengths. SELECT TYPE includes
failing defaults and checks initialized payloads; length is checked separately from type
and kind.

**Oracle limitation:** STAT and ALLOCATED checks precede each object inquiry or access. Explicitly allocated
payloads are initialized before reads; SOURCE payloads are already defined.
Default/double kinds come from KIND literals, not storage sizes, and their mandated
precision distinction is not generalized to arbitrary kind numbers. TYPE IS tests type
plus kind, not LEN or a universal compatibility relation.

**Dependencies:** 7.2 and 7.3.3 (PDF 76,79); 7.4.3.2 p5 and 7.4.4.2 (PDF 82,84-85); 7.5.7.1-.2 (PDF 104);
9.7.1.1-.2 (PDF 160-163); 11.1.11.1/C1164-C1168 and 11.1.11.2 p3/p5 (PDF 225-226).

### S7.3.2.3-004: An associated polymorphic pointer takes its target's dynamic type

**Source:** 7.3.2.3 p5, PDF 79, printed 65, lines 14-15. **Class:** Effect.

**Definition:** An associated polymorphic pointer has the dynamic type of its target, not necessarily
the target's declared type. Reassociation to a different eligible target can change that
dynamic type. This rule presupposes a live target and defined associated pointer status;
it does not authorize access after target deallocation or a forbidden type/kind/rank
association.

**Diagnostic obligation:** not-required.

**Facets:** `concrete-extension-target`, `sibling-reassociation`, `polymorphic-target-dynamic`, `unlimited-character-targets`.

**Oracle:** Three programs associate with initialized sibling extension targets, with an allocated
polymorphic target whose dynamic type differs from its declared root, and with
fixed-length character targets through CLASS(*). Each checks ASSOCIATED before SELECT
TYPE or length/value inquiry, with explicit failing defaults.

**Oracle limitation:** Pointers are initialized to NULL and nullified before a target is deallocated. No target
is reallocated while an alias is used. Character kind and length are not taken as type
identity, and no intrinsic argument restriction is bypassed by SAME_TYPE_AS.

**Dependencies:** 7.3.3 and 7.5.7 (PDF 79,104); 10.2.2.2/C1016-C1029 and 10.2.2.3 p1-p6 (PDF 194-195);
11.1.11.2 (PDF 225-226); 15.5.2.4 (PDF 339).

### S7.3.2.3-005: An ordinary polymorphic dummy takes its effective argument's dynamic type

**Source:** 7.3.2.3 p5, PDF 79, printed 65, lines 15-16. **Class:** Effect.

**Definition:** A polymorphic dummy without ALLOCATABLE and without POINTER has its effective argument's
dynamic type. A pointer actual can supply its target as that effective argument. The
dummy's own rank and parameter declarations and the argument-association restrictions
still apply; this is not the rule for allocatable or pointer dummies.

**Diagnostic obligation:** not-required.

**Facets:** `concrete-effective-argument`, `polymorphic-effective-argument`, `pointer-target-effective-argument`, `unlimited-kind-and-length`.

**Oracle:** Three effect programs pass a concrete extension and an allocated CLASS(root) extension
to the same ordinary CLASS(root) dummy, pass a guarded associated pointer actual, and
pass initialized REAL and CHARACTER actuals to CLASS(*). TYPE IS branches set checked
result tags and examine defined components or values.

**Oracle limitation:** Actual allocation/association is checked at the call sites; the ordinary dummies
themselves have neither attribute. No absent OPTIONAL actual is queried, no TYPE(*)
actual is illegally passed to CLASS(*), and the exact-kind and assumed-length guards
satisfy C1165. Tags distinguish missing dispatch from successful zero-initialization.

**Dependencies:** 15.5.2.4 p1-p6 and 15.5.2.5 p2-p7 (PDF 339-340), contrasted with 15.5.2.6 (PDF 342);
11.1.11.2 (PDF 225-226).

### S7.3.2.3-006: Inactive objects with a declared type have that dynamic type

**Source:** 7.3.2.3 p5, PDF 79, printed 65, lines 16-17. **Class:** Effect.

**Definition:** An unallocated allocatable object or a disassociated pointer has its declared type as
its dynamic type. Undefined pointer association is not disassociation. CLASS(*) has no
declared type, so this sentence supplies no invented concrete type for an inactive
unlimited entity.

**Diagnostic obligation:** not-required.

**Facets:** `initial-unallocated`, `after-deallocation`, `initial-disassociated`, `after-nullify`, `nonpolymorphic-inactive`.

**Oracle:** Three programs first establish the expected inactive state using ALLOCATED or
ASSOCIATED, then use SAME_TYPE_AS only with extensible declared types and initialized
extensible molds. Allocatable and pointer witnesses are also observed while active with
a different dynamic type and then after DEALLOCATE or NULLIFY. A nonpolymorphic inactive
control covers the sentence's broader object scope.

**Oracle limitation:** The intrinsic explicitly permits these objects when polymorphic pointer status is
defined. It does not read components, deferred parameters or elements of inactive
objects. At least one extensible dynamic type makes the equality result determinate. No
such equality is asserted for two inactive CLASS(*) objects, and EXTENDS_TYPE_OF's
special unlimited cases are not reinterpreted as general compatibility.

**Dependencies:** 7.3.2.3 p3-p4; 9.7.3 and pointer association status in 19.5.2; 16.1 p2's explicit
inactive/undefined-value inquiry permission (PDF 364); 16.9.177 p3/p5 and NOTE 1 (PDF
452), contrasted with 16.9.86 (PDF 409). These inquiry clauses are dependencies, not
owned intrinsic test coverage.

### S7.3.2.3-007: An associate-name entity has its selector's dynamic type

**Source:** 7.3.2.3 p5, PDF 79, printed 65, lines 17-18. **Class:** Effect.

**Definition:** The entity identified by an associate name has the dynamic type of the selector with
which it is associated. Declared type, polymorphism and other attributes are governed by
the defining construct. In particular an ASSOCIATE name does not simply inherit its
selector's ALLOCATABLE or POINTER attribute.

**Diagnostic obligation:** not-required.

**Facets:** `polymorphic-array-selector`, `pointer-selector`, `unlimited-character-selector`, `nonpolymorphic-expression-selector`.

**Oracle:** Four programs associate names with an allocated polymorphic array, an associated
polymorphic pointer, an allocated unlimited character object, and a nonpolymorphic
derived constructor expression. Exact branch/type checks and initialized payload checks
are made inside the association. The array's size is checked before element access, and
its rank is distinguished from type.

**Oracle limitation:** Dynamic selector state is guarded before entering ASSOCIATE. The associate name is never
queried with ALLOCATED or ASSOCIATED merely because the selector has that attribute. The
expression selector is read only, and no selector is deallocated, nullified or absent
while associated.

**Dependencies:** 11.1.3.1-.3 (PDF 204-205), especially declared type, polymorphism, rank and
absent-OPTIONAL premises; 11.1.11.2 p3-p8 (PDF 225-226); 19.5.1.6. No coarray/CHANGE
TEAM execution is claimed.

### S7.3.2.3-008: A nonpolymorphic object's dynamic type is its declared type

**Source:** 7.3.2.3 p5, PDF 79, printed 65, line 19. **Class:** Effect.

**Definition:** For a nonpolymorphic object, dynamic type is its declared type. Type parameters and rank
remain distinct attributes. Associating a nonpolymorphic pointer with the declared-type
part of a polymorphic target does not make that pointer's dynamic type the target's
extension.

**Diagnostic obligation:** not-required.

**Facets:** `intrinsic-declared-kind-length`, `derived-declared-identity`, `ancestor-part-pointer`, `nonextensible-source-use`.

**Oracle:** Three programs inspect initialized intrinsic actuals through eligible CLASS(*) dummies,
distinguish two same-shaped but separately defined extensible types with SAME_TYPE_AS,
and associate a TYPE(root) pointer with a CLASS(root) target allocated as an extension.
The last case verifies root identity and inherited-component aliasing while preserving
an extension-component sentinel.

**Oracle limitation:** The derived molds have extensible declared and dynamic types, so the equality inquiry
has a defined result; no claim about kind, length or compatibility follows from it. The
ancestor association is permitted because the pointer and target have the same declared
root, with no differing kind or rank. The extended payload is initialized before the
root alias is formed and checked before the target dies.

**Dependencies:** 7.5.2.4 (PDF 90), 7.5.7.1-.2 (PDF 104), 10.2.2.2/C1016 and 10.2.2.3 p1 (PDF 194-195),
11.1.11.2 (PDF 225-226), 15.5.2.4-.5 (PDF 339-340), 16.9.177 (PDF 452).
