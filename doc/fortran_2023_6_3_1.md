### S6.3.1-001: A program unit uses one source form

**Source:** 6.3.1 p3, fourth sentence; J3/24-007, 18 December 2023, PDF page 71, printed page 57, lines 8-9. **Class:** Restriction.

**Definition:** An individual program unit cannot switch between free-form and fixed-form conventions.
This restriction is per program unit, not per complete program. The processor selects
how a unit's source form is specified; neither a filename suffix nor a command-line
spelling is standardized.

**Diagnostic obligation:** required.

**Facets:** `free-unit`, `fixed-unit`, `separate-unit-forms`, `mixed-continuation`.

**Oracle:** The source_forms_separate_units manifest explicitly selects free and fixed form for
different compilation inputs, then links and runs them together. The free input contains
a main program and a following external subroutine; another external subroutine is fixed
form. Calls must produce 37 and then 43. These are positive controls, including
uncredited INCLUDE and comment context. The mixed-continuation negative has unmistakably
free-form lines starting in column one but imports a fixed-form column-six continuation
after a complete, uncontinued assignment. Require a diagnostic on the imported
continuation line. Its positive control adds just the missing trailing free-form
ampersand to the preceding line and checks the result 3.

**Oracle limitation:** This is one concrete mixed-convention witness, not detection of every possible mixture
or a processor-independent way to request an in-unit mode switch. Text that happens to
be legal in both forms is not a violation. The diagnostic is also explained by 6.3.2.4;
that later section is necessary, uncredited context, not a newly authored continuation
requirement. The standard requires reporting capability under 4.2 p2(5), not necessarily
rejection. The existing runner checks located errors and supported reference-warning
classes; unsupported nonfatal reporting paths must not be mistaken for absence of a
diagnostic. No exhaustive comment-character, INCLUDE, END, or compiler-selection
semantics are claimed.

**Dependencies:** 4.2 p2(1)/(5), PDF 46, supplies conforming execution and Clause 6 diagnostic
obligations. 5.2.1 and 14.1/15.6.2.3 define the program units used here. 6.3.2.1,
6.3.2.4 p1-p2, and 6.3.3.1/6.3.3.3 supply the contrasting layout contexts. Fixed input
uses exactly 72 default-kind ASCII characters per line without a continuation case. 6.4
p3-p5, PDF 73, keeps INCLUDE separate from statements. 3.21, PDF 21, defines character
contexts; 6.1.1, 6.1.6, and 7.4.4.2 retain character-set ownership.
