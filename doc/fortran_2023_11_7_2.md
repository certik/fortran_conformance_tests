### S11.7.2-001: Segments are statement sequences before, between, or after image control statements on an image

**Source:** 11.7.2 p1; J3/24-007 PDF p231. **Class:** Effect.

**Definition:** On each image, the sequence of statements before the first image control statement,
between two image control statements, or after the last image control statement is a
segment. The immediately preceding segment includes expression evaluation within the
image control statement; if no image control statement executes before termination, the
whole statement execution sequence is one segment.

**Diagnostic obligation:** not-required.

**Facets:** `segment-before-between-after-image-control`, `preceding-segment-includes-ics-expression-evaluation`, `no-image-control-entire-execution-single-segment`.

**Oracle:** These definitions are needed by later ordering rules but do not by themselves provide an
executable single-image observation.

**Oracle limitation:** This source-only catalogue records pending plans only. Local source-form or value-domain
facts may become implementable only through a future reviewed fixture that observes a
purely local property without duplicating the feature under test and without using
unregistered STAT=/ERRMSG= semantics or multi-image synchronization as the oracle.

**Dependencies:** 11.7.1 in this packet; 5.3.5 execution sequence NOT YET REGISTERED.

### S11.7.2-002: Programs can establish segment ordering; otherwise cross-image segments are unordered and may overlap

**Source:** 11.7.2 p2; J3/24-007 PDF p231. **Class:** Effect.

**Definition:** By image control statements or user-defined ordering, a program can ensure that one
image segment precedes or succeeds a segment on another image. If the program does not
ensure this, the segments are unordered; depending on relative execution speeds, some or
all execution of the unordered segments may take place at the same time.

**Diagnostic obligation:** not-required.

**Facets:** `image-control-or-user-defined-ordering-source-control`, `unordered-segments-source-control`, `unordered-segment-overlap-permission`.

**Oracle:** The overlap sentence is processor/scheduler latitude, not an obligation. No runtime
timing or interleaving observation is a portable oracle.

**Oracle limitation:** This source-only catalogue records pending plans only. The specified synchronization,
segment delay, segment precedence, or cross-image memory-order effect is not approved as
an executable oracle in the current single-image suite: a one-image run would be vacuous
and multi-image timing, scheduling, interleaving, progress, deadlock, race, or failure
observations are not portable evidence.

### S11.7.2-004: Unordered cross-image segments are restricted for ordinary variables, coarray subobjects, and effective arguments

**Source:** 11.7.2 p3 otherwise bullets; J3/24-007 PDF p231. **Class:** Restriction.

**Definition:** Except for the specified atomic, event, notify, and satisfied NOTIFY= cases, unordered

### S11.7.2-005: Actions on a variable are ordered when their containing segments are ordered

**Source:** 11.7.2 p4; J3/24-007 PDF p231. **Class:** Effect.

**Definition:** If an action regarding X occurs in segment Pi on image P, segment Pi precedes segment Qj
on image Q, and an action regarding X occurs in segment Qj, then the action regarding X
in Pi precedes the action regarding X in Qj.

**Diagnostic obligation:** not-required.

**Facets:** `ordered-segment-actions-precedence`.
