## Meaning and ownership

Three separate questions must not be conflated:

| Question | Defining source |
| --- | --- |
| Is the parameter KIND or LEN? | R734 and p3 |
| What INTEGER kind represents the parameter itself? | R732, p2 and canonical INTEGER rules |
| Does the parameter have a default integer value? | R733 and p4 |

The source's p2 second sentence specifically names a KIND parameter.
An omitted INTEGER selector on a LEN declaration also denotes default
INTEGER through R705 and 7.4.3.1 p4; that conclusion is not a silent
rewriting of p2. Explicitly selected integer kinds are permitted and need
not differ from default. Intrinsic KIND and CHARACTER LEN rules are not
indiscriminately applied to PDT parameters.

A KIND parameter need not select an intrinsic representation, and a LEN
parameter need not measure a physical component length. A header with new
parameter names makes the type parameterized, but an extended type can
also inherit parameters without listing new names locally.

R726 owns the placement of parameter definitions before components.
R733 defaults and constant-only uses retain scalar/integer/constant and
prior-declaration conditions. Header parameter order is not definition
statement order; 7.5.3.2 is catalogued separately. Inheritance, component
specifications/default initialization, allocation, assignment and dummy
contexts keep their canonical owners. The definition and identity
catalogues in 7.5.1/7.5.2 have separate source and fixture adjudications.

## Oracle and diagnostic boundaries

Runtime witnesses use small exact integers, explicit matching
integer dummies and parameter inquiries, not physical encodings or real
approximation. SELECTED_INT_KIND(18) supplies a supported method, not a

### R732: A type parameter definition has an integer specification, category attribute and declaration list

**Source:** 7.5.3.1 R732, J3/24-007, 18 December 2023, PDF 91, printed 77, lines 3-4. **Class:** Syntax.

**Definition:** A type-param-def-stmt starts with an integer-type-spec, followed by a comma, one
type-param-attr-spec, a double colon and a type-param-decl-list. The integer
specification may itself have its canonical kind selector. That selector chooses the
integer kind of the parameter, whereas the separate KIND or LEN attribute chooses the
parameter category. This is not an ordinary component declaration or a PARAMETER
attribute statement.

**Diagnostic obligation:** required.

**Facets:** `default-integer-kind-parameter`, `default-integer-length-parameter`, `selected-integer-specification`, `declaration-list`, `comma-separator`, `double-colon-separator`, `integer-prefix-required`.

**Oracle:** The finite corpus has independent compile-only category/selector/list controls and three
one-token repairs. Every parameter declaration precedes the component part under R726,
and all controls satisfy C746/C747. Negative contracts identify the defining statement's
actual separator or integer-prefix condition.

**Oracle limitation:** R705/R706/C717 retain INTEGER specification, expression and representation-support
ownership. R401 owns list expansion; R733 and R734 own the local descendants. An invalid
attempted definition can also strand a header name under C747 or resemble an invalid
component statement; those consequences are not substitute R732 causes. Fixture
contracts distinguish observed causal messages from prospective parser predicates;
observations do not replace independent source and fixture adjudication. Required
reporting is not mandatory fatal rejection.

**Dependencies:** 4.1.2-4.1.3 and 4.2 p2(3), PDF 45-46; R705/R706/C717 and 7.4.3.1 p2/p4, PDF 80;

### C746: Every defined parameter name belongs to the same type header

**Source:** 7.5.3.1 C746 (R732), PDF 91, printed 77, lines 6-7. **Class:** Restriction.

**Definition:** A parameter name in a type parameter definition statement must occur in the
derived-type-stmt of that same derived-type definition. A name in another type header, a
host entity or an inherited parameter does not supply a local header entry for a new
local declaration. This membership condition is distinct from C747's requirement to
define every header name exactly once.

**Diagnostic obligation:** required.

**Facets:** `listed-kind-name`, `listed-length-name`, `unlisted-local-name`, `missing-local-header-list`.

**Oracle:** Two positive controls and a bounded KIND/LEN membership family use fresh names, complete
TYPE/END TYPE pairs and no dependent components. Each negative's only repair is to its
own header. A diagnostic must connect the offending parameter definition to that header,
at an exact use point or explicitly justified bounded definition relation.

**Oracle limitation:** Use names absent from any parent to avoid turning the unlisted-name case into an
inherited-name collision. Inherited parameters retain their original definitions and
attributes under 7.5.7.2; no new local declaration is manufactured for them. Generic
type/name/kind errors, unsupported facilities, crashes, verifier and resource failures
cannot establish membership. No compiler observation or self-approval is claimed.

**Dependencies:** R732/R733; R727 and C736, PDF 88; 7.5.7.2 p1 and its name/inheritance notes, PDF
104-105; 4.2 p2(3), PDF 46. The canonical inheritance and header-definition owners
remain outside this catalogue.

### C747: Each local header parameter has exactly one definition in that type

**Source:** 7.5.3.1 C747 (R732), PDF 91, printed 77, lines 8-9. **Class:** Restriction.

**Definition:** Every type parameter name in a type's derived-type-stmt appears exactly once as a

missing and repeated definitions violate the condition. The constraint does not
prescribe definition-statement order or add inherited names to a child's local header
list.

**Diagnostic obligation:** required.

**Facets:** `complete-kind-list`, `complete-length-list`, `mixed-categories`, `missing-definition`, `duplicate-in-one-statement`, `duplicate-in-separate-statements`, `definition-order-independent`.

**Oracle:** The finite controls count every local header name once. Missing-definition diagnoses
need the particular header name and the matching TYPE definition; repeated-definition
diagnoses need the same parameter identity at its repeated declaration. Repairs add one
missing definition or remove one repeated name/statement. The header and all unrelated
definitions remain unchanged.

**Oracle limitation:** Missing definitions cannot be bound to a nonexistent declaration line: a header/END TYPE
or related declaration span needs explicit source justification. Do not accept a
whole-unit recovery range or generic symbol/constant/function complaint. A duplicate
definition can also implicate canonical declaration/name rules; it is one
repeated-definition defect, not proof of a distinct internal C747 check. R726 still
orders the parameter-definition block before components, and constant-expression
dependencies still require their own prior-declaration premises.

**Dependencies:** R726/R727/C736, PDF 88; R732/R733/C746; 10.1.12 p1(12), PDF 187, for dependent default
