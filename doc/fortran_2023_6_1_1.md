### R601: Alphanumeric characters have three alternatives

**Source:** 6.1.1 R601 (J3/24-007 PDF page 67, printed page 53, lines 9-11). **Class:** Syntax.

**Definition:** An alphanumeric-character is a letter, a digit, or an underscore. Special characters and
other graphic characters are not alternatives of this syntax class. The definitions of
the three alternatives remain in 6.1.2, 6.1.3, and 6.1.4. The enclosing syntax
determines where an alphanumeric-character is permitted; R601 does not itself define a
name, a literal, or an operator.

**Diagnostic obligation:** required.

**Facets:** `letter-alternative`, `digit-alternative`, `underscore-alternative`.

**Oracle:** Three independent free-form programs admit the alternatives in name suffix positions
provided by R603. The letter control uses distinct alphabetic suffixes; the digit
control separately assigns and checks ten names ending in 0 through 9; the underscore
control distinguishes a name ending in underscore from the same prefix without it. Every
scalar is defined before comparison.

**Oracle limitation:** These are positive admission controls, not full syntax-rejection coverage. No malformed
name is duplicated here: R603/C601 owns name grammar and length, while literal and
operator spelling remains in their defining sections. No claim is made about character
code values, code distances, source encoding, or glyph rendering. The required
diagnostic capability for syntax violations follows from 4.2 p2(3), not a universal
obligation to reject extensions.

**Dependencies:** 4.1.1 p1 defines the BNF alternatives (PDF pages 44-45); 4.2 p2(3) establishes syntax
diagnostic capability (PDF page 46). 6.1.2 p1-p3, 6.1.3 p1-p3, and 6.1.4/R602 supply the
three alternatives (PDF page 67). 6.2.2/R603/C601 supplies the otherwise legal
short-name context (PDF page 68).

### S6.1.1-001: Character graphics have prescribed forms with explicit exceptions

**Source:** 6.1.1 p3 (J3/24-007 PDF page 67, printed page 53, lines 12-13). **Class:** Effect.

**Definition:** The character graphics follow those specified in 6.1.2 through 6.1.5, except that the
currency symbol is exempt from this prescribed-graphic condition. The style of every
graphic is unspecified. This requirement concerns the graphics, not an ASCII encoding, a
font, an integer code assignment, or a fixed distance between character codes.

**Diagnostic obligation:** not-required.

**Facets:** `letter-graphics`, `digit-graphics`, `underscore-graphic`, `special-character-graphics`.

**Oracle limitation:** No executable fixture is credited to these four facets. A finite source/interface review
must compare the specified graphics while preserving the currency and style exceptions;
there is no portable runtime query that verifies their visual appearance. This processor
obligation does not supply a single isolated invalid program or a mandatory fatal
rejection oracle. The separate 4.2 p2(5) capability to diagnose characters not permitted
by Clause 6 is not a glyph-rendering test.

**Dependencies:** 6.1.2 p2, 6.1.3 p2, and 6.1.4/R602 (PDF page 67); 6.1.5 p1 and Table 6.1 (PDF pages
67-68). 7.4.4.4 p1-p3 (PDF pages 86-87) separates processor collation from graphic
appearance and gives no fixed inter-case code relation.
