### R724: Character literals have matching delimiters and an optional kind prefix

**Source:** 7.4.4.3 R724; J3/24-007, 18 December 2023, PDF 85, printed 71, lines 32-33. **Class:** Syntax.

**Definition:** A character literal uses a matching pair of apostrophes or a matching pair of quotation
marks, surrounding zero or more rep-char occurrences. An optional kind-param precedes
the opening delimiter and is separated from it by an underscore. R709 defines that
prefix as a digit string or scalar integer constant name, not an arbitrary expression.
C718/C719 and C732 retain their own name/type, sign and supported-method conditions. The
source-form definition of rep-char and the doubling/empty-context rules below are part
of interpreting this syntax.

**Diagnostic obligation:** required.

**Facets:** `apostrophe-form`, `quotation-form`, `named-prefix-form`, `digit-prefix-form`, `prefix-category-premises`, `prefix-separator`, `unterminated-apostrophe`, `unterminated-quotation`, `free-form-control-exclusion`.

**Oracle:** Three compile pairs isolate a missing prefix underscore and each unterminated delimiter,
with one local repair apiece. Repairs directly admit apostrophe/quotation forms and a
supported named prefix. Literal-specific/token-specific causal predicates exclude
generic EOF, missing-END and assignment recovery. Digit prefixes, canonical prefix
categories and source-control rejection remain pending. Direct case IDs:
R724_invalid__apostrophe_closer, R724_invalid__prefix_separator,
R724_invalid__quotation_closer, R724_valid__apostrophe_closer_repair,
R724_valid__prefix_separator_repair, R724_valid__quotation_closer_repair.

**Oracle limitation:** The authored diagnostic predicates are finite source/cause contracts, not approvals or
standard-mandated wording. A kind-selector expression legal in R721 is not automatically
a legal literal prefix. Numbered reporting capability does not prescribe fatal rejection
or wording. Unsupported representation-value reports belong to C732 where that is the
actual condition; unsupported language features, false constancy reports, ASR verifier
errors and wrong-source recovery cannot corroborate another rule.

**Dependencies:** R709/C718/C719 (PDF 80-81), R403/C401 (PDF 45), C732 and p2-p6 (PDF 85-86), 3.21 (PDF
21), 6.1.1/6.1.6 and 6.3 (PDF 67-73), 16.9.118/16.10.2.4 (PDF 424, 472). 4.1.2 p2/4.2
p2(3) (PDF 45-46); doc/source_audits/batch_009.json supplies the corrected per-cause
diagnostic principles.

### C732: A literal kind prefix names a supported character method

**Source:** 7.4.4.3 C732 (R724); PDF 85, printed 71, line 34. **Class:** Restriction.

**Definition:** The literal's kind-param identifies an available character representation method.
R709/C718/C719 independently constrain the prefix syntax, integer constant name and
nonnegative value. A kind supported for another intrinsic type is not thereby a
supported character kind.

**Diagnostic obligation:** required.

**Facets:** `supported-prefix`, `unsupported-nonnegative-prefix`.

**Oracle:** An unprofiled run uses a supported named default kind prefix with both delimiters and
checks literal kind, count and value. No unsupported-nonnegative-prefix case is authored
without an independent absence profile. Direct case IDs: C732_valid__supported.

**Oracle limitation:** A processor that supports character kind zero makes the absent-zero witnesses
unavailable, not passing. Generic kind/constant/expected messages, undefined-name
reports, unsupported character-literal facilities and crashes do not establish the
intended unsupported representation value. Reporting need not be fatal.

**Dependencies:** R724 (PDF 85), R709/C718/C719 (PDF 80-81), 7.4.4.1 p2 and 7.4.4.2 p2 (PDF 84), 16.10.2.4
(PDF 472), 16.9.118 (PDF 424), 4.2 p2(3)-(4) (PDF 46).

### S7.4.4.3-001: Literal kind comes from its prefix or the default method

**Source:** 7.4.4.3 p2; PDF 85, printed 71, lines 35-36. **Class:** Effect.

**Definition:** A supplied kind prefix determines the literal's character kind; without it the literal
is default character. The prefix is not part of the literal value or its represented
length. Prefix selection does not imply distinctness from default, optional-kind
availability, byte width or a source encoding.

**Diagnostic obligation:** not-required.

**Facets:** `omitted-prefix-default`, `named-prefix-value`, `selected-named-methods`.

**Oracle:** Two run programs inquire directly on empty and nonempty literals, with absent,
KIND-derived and SELECTED_CHAR_KIND(DEFAULT)-derived named prefixes and both delimiters.
They check exact kinds and lengths before assignment can convert or pad. Optional
named/source-interface branches remain pending. Direct case IDs:
S7_4_4_3_001_valid__default, S7_4_4_3_001_valid__named_prefix.

**Oracle limitation:** SELECTED_CHAR_KIND support is not proof of arbitrary source bytes or non-Fortran
graphics. The existing iso10646 profile only inquires kind availability. It cannot
certify literal decoding, additional repertoire, or rendering; those dependencies must
be recorded separately.

**Dependencies:** 7.4.4.1 p2-p3 and 7.4.4.2 p2-p3 (PDF 84), R724/C732 (PDF 85), 15.5.2.5 p3 (PDF 340),
16.9.118/16.9.122/16.9.180 (PDF 424, 426, 454).

### S7.4.4.3-002: Literal repertoire is method-specific and source-form-specific

**Source:** 7.4.4.3 p3 and its two bullets; PDF 85, printed 71, lines 37-41. **Class:** Effect.

**Definition:** rep-char is interpreted in the prefixed character method, or default character when no
prefix is present. In free source form it is a graphic character in that
processor-dependent set. In fixed form it can be any character in the corresponding set,
but the processor may restrict some or all control characters. Extra graphics, controls,
nondefault kinds and byte-to-character mappings are not universally required by this
definition.

**Diagnostic obligation:** not-required.

**Facets:** `free-required-graphics`, `fixed-required-graphics`, `free-additional-graphic`, `fixed-additional-graphic`, `fixed-control-policy`.

**Oracle:** Separate free- and fixed-form run fixtures check a finite required-graphic subset with
both literal delimiters, case distinction and exact interior/edge blanks. Every
fixed-form source record is byte-preserved at 72 default-source characters. No
additional graphic/control or decoding/graphics interface premise is inferred. Direct
case IDs: S7_4_4_3_002_valid__fixed_graphics, S7_4_4_3_002_valid__free_graphics.

**Oracle limitation:** The registry has no documentary/interface evidence case type, and the needed
additional-source profiles are not authored. Existing S6.1.6-001 free/fixed
literal-admission gaps and S6.1.1-001 graphics gaps remain honest dependencies. Neither
successful ASCII-source compilation nor iso10646 kind availability closes them.

**Dependencies:** 6.1.1 and 6.1.6 (PDF 67-68); 6.3.1 and 6.3.2.1-.4 (PDF 71-72); 6.3.3.1-.3 (PDF 72-73);
7.4.4.1 p2-p3 (PDF 84); 16.9.52/16.9.122 (PDF 394, 426); 3.21 (PDF 21). B.3.7 (PDF 578)
and 4.2 p2(2), p6-p8 (PDF 46-47) preserve obsolescence and processor-interface
distinctions.

### S7.4.4.3-003: Delimiters are excluded while literal character data is preserved

**Source:** 7.4.4.3 p4; PDF 85, printed 71, line 42, with p3's rep-char domain and canonical character-context premises. **Class:** Effect.

**Definition:** The surrounding delimiter pair is not part of a literal's value. Interior data,
including a delimiter of the other kind, retains its character identity under the
rep-char rules. Character-context case and blank exceptions remain operative; they do
not permit folding letter case, collapsing interior blanks or counting delimiters in the
represented length.

**Diagnostic obligation:** not-required.

**Facets:** `apostrophe-delimiter-exclusion`, `quotation-delimiter-exclusion`, `other-delimiter-data`, `case-and-blank-dependencies`.

**Oracle:** Three run programs check literal lengths 0/1/3 directly and verify nonempty positions.
Opposite delimiters occur undoubled as data, are checked against one-character literals
and are required to be distinct. Canonical case/blank evidence links remain pending.
Direct case IDs: S7_4_4_3_003_valid__apostrophe,
S7_4_4_3_003_valid__opposite_delimiters, S7_4_4_3_003_valid__quotation.

**Oracle limitation:** No negative program follows from excluding delimiters or preserving data. Literal
equality with an identically misprocessed literal is not enough: counts and
distinct-value contrasts are required. This finite plan is neither exhaustive decoding
nor typography evidence.

**Dependencies:** p3/p5/p6 and R724 (PDF 85-86), 3.21 (PDF 21), 6.1.2 p3 (PDF 67), 6.3.2.2 p1 and 6.3.3.1
p2 (PDF 71-72), 6.3.2.4 p4 and 6.3.3.3 (PDF 72-73), 9.4.1 (PDF 151), 10.1.5.5.1 p8 (PDF
180-181), 16.9.122 (PDF 426).

### S7.4.4.3-004: A doubled matching delimiter represents one character

**Source:** 7.4.4.3 p5; PDF 86, printed 72, lines 1-5. **Class:** Effect.

**Definition:** Inside an apostrophe-delimited literal, two immediately consecutive apostrophes denote
one apostrophe value. Inside a quotation-delimited literal, two immediately consecutive
quotation marks denote one quotation-mark value. No intervening blank is part of the
doubling spelling, and each doubled pair contributes one character to LEN, not two. The
other delimiter does not require doubling just because it is punctuation.

**Diagnostic obligation:** not-required.

**Facets:** `apostrophe-doubling-and-count`, `quotation-doubling-and-count`, `boundary-and-repeated-pairs`.

**Oracle:** Three run programs check each matching-delimiter doubling, including boundary and
repeated pairs, using represented counts 3 and 2 and opposite-delimiter identity
controls. The generator preserves exact source quote bytes; no backslash-escape
extension is assumed. Direct case IDs: S7_4_4_3_004_valid__apostrophe,
S7_4_4_3_004_valid__boundaries, S7_4_4_3_004_valid__quotation.

**Oracle limitation:** No artificial invalid twin is added for this value effect. A separated pair would enter
other token/grammar rules and is not a new mandatory rejection oracle under this S ID.
No backslash escape extension is assumed.

**Dependencies:** R724 and p3-p4/p6 (PDF 85-86); 3.21 (PDF 21); 9.4.1 and 16.9.122 (PDF 151, 426). NOTE 1
is explanatory only and does not create another requirement.

### S7.4.4.3-005: An adjacent delimiter pair outside character context denotes an empty literal

**Source:** 7.4.4.3 p6; PDF 86, printed 72, lines 6-7. **Class:** Effect.

**Definition:** Two adjacent apostrophes, or two adjacent quotation marks, with no intervening blank and
beginning outside a character context, denote a zero-length literal. A doubled delimiter
within an already-open literal instead denotes delimiter data under p5. An empty literal
is not the same length as a one-blank literal, even though padded character equality can
consider their values equal.

**Diagnostic obligation:** not-required.

**Facets:** `empty-apostrophe`, `empty-quotation`, `empty-versus-interior-pair`.

**Oracle:** Three run cases distinguish outside-context empty pairs, one-blank literals and
inside-context doubled delimiter data by counts 0/1/1. Empty concatenation has unchanged
value and count. Equality alone is not the empty-length oracle. Direct case IDs:
S7_4_4_3_005_valid__apostrophe, S7_4_4_3_005_valid__context,
S7_4_4_3_005_valid__quotation.

**Oracle limitation:** No negative or trapping behavior is inferred for an empty value. Runtime success would
be a finite effect witness, not proof of every lexer context or source representation.

**Dependencies:** 3.21 (PDF 21), p5/R724 (PDF 85-86), 7.4.4.1 p1 (PDF 84), 10.1.5.3.1 p1-p3 (PDF 178),
10.1.5.5.1 p8 (PDF 180-181), and 16.9.122 (PDF 426).
