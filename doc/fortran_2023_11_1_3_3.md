### S11.1.3.3-001: Associating entities have selector rank and bounds with no ALLOCATABLE or POINTER attributes

**Source:** 11.1.3.3 p1; J3/24-007 PDF p204-p205. **Class:** Effect.

**Definition:** Within ASSOCIATE, CHANGE TEAM, or SELECT TYPE, each associating entity has the same rank
as its selector. Each lower bound is the LBOUND result for the corresponding selector
dimension, and each upper bound is lower bound plus extent minus one. The associating
entity does not have ALLOCATABLE or POINTER.

**Diagnostic obligation:** not-required.

**Facets:** `same-rank-as-selector`, `nondefault-lower-bound`, `upper-bound-from-extent`, `no-allocatable-attribute-source`, `no-pointer-attribute-source`.

**Oracle:** LBOUND/UBOUND/SHAPE inquiries are acceptable only because this paragraph requires the
expected bounds; future plans must avoid circular use of array-section formation as the
sole oracle.

S11.1.3.3-001 ASSOCIATE rank and bounds runtime fixtures: three complete
run/effect/f2023 programs observe rank and bounds with inquiry functions whose expected
results are required by p1. The rank case associates tile with a rank-two section
grid(-1:3:2,8:12:4), assigns SHAPE(tile) to a length-two integer vector, and requires
[3,2]. The lower-bound case checks both a whole-array selector, for which
LBOUND(whole,1) is the nondefault declared lower bound -5, and a section selector
base(-3:3:2), for which LBOUND(sec,1) is 1 even though the selected subscripts run from
-3 to 3. The upper-bound case associates vec with base(12:20:3), whose extent is 3 and
whose LBOUND result is 1, so UBOUND(vec,1) must be 1+3-1 = 3 rather than the selector
subscript upper bound 20 or underlying array upper bound 21.
