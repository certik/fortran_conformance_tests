### S6.3.2.4-001: Continuation skips comment lines and omits continuation markers

**Source:** 6.3.2.4 p1, first four sentences, and p2 next-line selection; J3/24-007 PDF page 72, printed page 58, lines 8-10 and 14-15. **Class:** Effect.

**Definition:** A continuation marker connects a statement to the next noncomment line rather than
necessarily the immediately adjacent physical line. Interposed comment lines remain
commentary. An ampersand occurring in a comment does not continue that comment or
otherwise affect source interpretation. An ampersand serving as a continuation marker
contributes no character to the statement. The pinned subclause specifies no numeric
continuation-line ceiling; its separate statement-size and physical-line restrictions
still apply.

**Diagnostic obligation:** not-required.

**Facets:** `next-noncomment`, `intervening-comments`, `comment-ampersand`, `marker-elision`, `long-chain`.

**Oracle:** An ordinary program checks independently known integer results across
comment-interrupted continuations and verifies that a comment ending in an ampersand
does not swallow the next assignment. A raw character assignment contains exactly 256
continuation lines, each carrying a nonempty part of one token, and checks all 256 x
characters followed by Z. It has 261 logical statement characters and short physical
lines; continuation markers are not character data.

**Oracle limitation:** The long-chain case is a bounded F2023 witness, not a proof of unlimited processor
resources. It intentionally crosses the earlier 255-continuation-line rule, which is not
present in the pinned F2023 text. A reference selected in f2018 mode cannot establish
rejection of this F2023-valid input as a fixture defect. Character resumption and token
splitting are necessary but uncredited dependencies of that witness; their distinct
restrictions and text effects have separate requirements below.

**Dependencies:** 6.3.2.3 defines every skipped comment-line form. 6.3.2.4 p3-p4 define the continued
token and character contexts. 6.3.2.1 and 6.3.2.6 impose 10000-character physical lines
and one-million-character statements. 4.2 p2(1), PDF 46, retains processor
size/complexity qualifications.

### S6.3.2.4-002: An ampersand alone cannot supply the nonblank source of a line

**Source:** 6.3.2.4 p1, final sentence; J3/24-007 PDF page 72, printed page 58, lines 10-12. **Class:** Restriction.

**Definition:** A physical line cannot have an ampersand as its sole nonblank character. Nor can the
only nonblank source before a comment-introducing exclamation point be an ampersand. An
ampersand within an actual comment or character datum is not that forbidden source-line
shape.

**Diagnostic obligation:** required.

**Facets:** `sole-ampersand`, `sole-before-comment`.

**Oracle:** Two raw diagnose manifests isolate the forbidden shapes between complete statements.
Each repair inserts one initial exclamation point, changing that line into commentary
while leaving all other bytes unchanged. The repairs run an initialized scalar check. A
negative requires a diagnostic at the offending physical line, not arbitrary rejection
or a successful compile-only control.

**Oracle limitation:** The source requires reporting capability under 4.2 p2(5), not a fatal exit. Located
errors are accepted independently of ordinary exit status. The bare-ampersand fixture
additionally qualifies the exact observed GNU f951 warning and its parsed line through a
sole, hash-verified free-form compilation input with no INCLUDE or competing source
attribution. That inference is explicit in the manifest and result, not a fabricated
filename in compiler output. Wrong-file/line, unrelated-message, wrong-step, crash and
timeout exclusions remain. No generic warning, portability, or missing-space allowance
is imported from other cases.

**Dependencies:** 6.3.2.3 distinguishes commentary from source and character data. 4.2 p2(5), PDF 46,
supplies Clause 6 diagnostic capability.

### S6.3.2.4-003: Noncharacter continuation requires a terminal marker and a successor line

**Source:** 6.3.2.4 p2; J3/24-007 PDF page 72, printed page 58, lines 13-16. **Class:** Restriction.

**Definition:** For continuation outside character context, the first line's last nonblank source
character must be an ampersand, possibly followed by commentary. A subsequent noncomment
line must exist. On that next noncomment line, a first-nonblank ampersand is optional
for inter-token continuation: if present, resumption is immediately after it; if absent,
resumption includes the line from its first character position. The split-token rule in
p3 is a stricter condition, not an exception that can be ignored.

**Diagnostic obligation:** required.

**Facets:** `terminal-marker`, `marker-before-comment`, `leading-marker`, `no-leading-marker`, `later-line-control`, `missing-terminal-diagnostic`, `nonterminal-marker-diagnostic`, `missing-later-line-diagnostic`.

**Oracle:** One positive-control program exercises terminal markers, markers before comments, and
both optional leading-marker forms with defined arithmetic results. Two diagnose pairs
remove a required trailing marker or transpose it with the preceding plus sign; their
otherwise identical repairs run the value 3. The transposed-marker manifest qualifies
the observed Flang warning about a missing comment introducer. A third pair puts a
terminal ampersand on an otherwise complete END PROGRAM and follows it only with a
comment. Removing exactly that ampersand gives the compile-only repair. The negative's
declared span runs from the END line through the observed one-past-final-record EOF
position, with continuation/EOF/ampersand-specific message predicates. No other program
tokens, literal delimiters or END statements are missing.

**Oracle limitation:** Outside character context, ignoring a few extra inter-token blanks cannot distinguish
all implementation start-column choices; the resumption definition is preserved without
inventing an independent observable effect. The malformed expressions are not merely
alternate legal statements. The missing-successor pair accepts a qualified report at the
terminal marker or its EOF event, not a fictitious physical record, a whole-program
recovery range, or an unlocated driver summary. It neither mandates fatal rejection nor
credits compiler crashes. No nonfatal predicate is allowed without specific evidence of
the relevant message and attribution.

**Dependencies:** 3.21 defines character context. 6.3.2.2 governs noncharacter blanks; p3 governs split
lexical tokens. 6.3.2.5 explains why a missing continuation does not implicitly join
physical lines. 4.2 p2(5), PDF 46, requires source-form reporting, not compulsory
rejection.

### S6.3.2.4-004: A split lexical token resumes immediately after a leading ampersand

**Source:** 6.3.2.4 p3; J3/24-007 PDF page 72, printed page 58, lines 17-18. **Class:** Restriction.

**Definition:** When one lexical token spans physical lines, the first noncomment successor must have an
ampersand as its first nonblank character. The remaining characters of that token start
directly after that marker, with no intervening blank. This mandatory leading marker
differs from the optional marker between tokens in p2.

**Diagnostic obligation:** required.

**Facets:** `split-name`, `split-keyword`, `split-integer`, `split-operator`, `missing-leading-diagnostic`, `gap-after-marker-diagnostic`.

**Oracle:** A positive-control program splits a name, INTEGER keyword, integer literal, and power
operator, with a comment between the name fragments, and checks small defined results.
Two raw name-assignment pairs respectively omit the required leading marker and insert a
blank after it. Their repairs insert that one marker or delete that one blank. Each
negative declares the two-line assignment span, accepting a primary report on either
part or a range contained within those lines. Both pieces are necessary to form the
declared name, so the negative is not a different valid assignment.

**Oracle limitation:** Four token classes are finite representatives, not new ownership of R603, R708, R1008,
labels, or all token spellings. The source also applies to character tokens, whose more
specific context is handled separately by p4. Accepted repairs are positive controls
rather than full effect coverage of a reporting restriction. GNU's first-line reports
and the successor-line reports concern the same isolated assignment. An unrelated
location, competing file, driver summary or whole-program recovery span does not satisfy
the explicitly bounded oracle.

**Dependencies:** 6.2.1 defines lexical tokens (PDF 68), 6.2.2/R603 names, 5.5.2 statement keywords, R708
integer literals, and R1008 the power operator. 6.3.2.2 forbids interior token blanks
outside its exceptions. 4.2 p2(5), PDF 46, supplies source-form reporting.

### S6.3.2.4-005: Character-context continuation requires markers on both sides

**Source:** 6.3.2.4 p4, marker and successor conditions; J3/24-007 PDF page 72, printed page 58, lines 19-21. **Class:** Restriction.

**Definition:** Inside either character context, the final nonblank character of a continued line must
be an ampersand. A later noncomment line is required, and that next noncomment line must
start, apart from blanks, with an ampersand. An exclamation point still inside the
character context is data, not permission to put a comment after an otherwise
nonterminal marker.

**Diagnostic obligation:** required.

**Facets:** `paired-markers`, `later-line-control`, `missing-leading-diagnostic`, `missing-terminal-diagnostic`, `missing-later-line-diagnostic`.

**Oracle:** A positive-control program continues apostrophe and quote literals and a character
string edit descriptor across valid paired markers, including an intervening comment.
Two byte-preserved pairs omit the leading or terminal marker from a short character
assignment. Repaired controls change only that one marker and check the exact value.
Diagnose expects the physical line with the missing marker. The missing-leading-marker
case permits only the observed GNU warning about a missing ampersand in a continued
character constant and the observed Flang portability message about the absent preceding
ampersand; each predicate is family-, severity-, message-, file-, and line-qualified.
These are reporting oracles, not invented fatal-rejection requirements.

**Oracle limitation:** A compiler may diagnose an unterminated literal on the preceding line instead of the
missing leading marker on its successor; the report must preserve that location
difference, not silently broaden the oracle. These positive controls establish
admission, not detection of the separate missing-successor condition. A comment-like
exclamation point in character data must not be treated as actual trailing commentary.

**Dependencies:** 3.21 includes literals and character string edit descriptors. 7.4.4.3/R724 and
13.2.1/13.9 retain literal/FORMAT semantics. 6.3.2.3 supplies comment-line
classification. 4.2 p2(5), PDF 46, supplies reporting capability.

### S6.3.2.4-006: Character continuation preserves data blanks but excludes layout and markers

**Source:** 6.3.2.4 p4, resumption rule under its marker conditions; J3/24-007 PDF page 72, printed page 58, lines 19-21. **Class:** Effect.

**Definition:** With valid character-continuation markers, character text resumes directly after the
successor's leading ampersand. Blanks before the trailing marker within the character
context and blanks after the leading marker belong to the character text. Layout blanks
after the trailing marker or before the leading marker do not. An ampersand that is
ordinary character data is distinct from an adjacent ampersand serving as a continuation
marker.

**Diagnostic obligation:** not-required.

**Facets:** `before-marker-blanks`, `after-marker-blanks`, `trailing-layout-blanks`, `leading-layout-blanks`, `both-literal-delimiters`, `edit-descriptor`, `ampersand-data`.

**Oracle:** A raw fixture preserves two data blanks before and after continuation markers, three
layout blanks after a trailing marker, and four layout blanks before a leading marker.
Both literal delimiter styles must yield the exact eight-character value with four
internal blanks. Positional substring assertions check the suffix positions and the
four-blank regions without using another multi-blank literal as the sole oracle. A
continued FORMAT descriptor produces the specified seven-character internal record after
an IOSTAT guard. A separate literal places a data ampersand immediately before a
continuation marker. In addition to a full value comparison, IACHAR results 38, 33, and
59 independently check its three punctuation positions.

**Oracle limitation:** The fixture deliberately uses external metadata so header injection or whitespace
normalization cannot alter the evidence. All character objects are initialized before
assignment or internal output, and no undefined or out-of-bounds data are inspected. It
does not test doubled-quote spelling or the entire processor character repertoire.

**Dependencies:** 3.21 defines the two contexts; 6.3.2.2 preserves internal character blanks. 7.4.4.3
distinguishes literal delimiters from values; 13.9 supplies the character edit
descriptor output effect. 9.4.1 and 16.9.98 (PDF 151/416) justify fixed in-bounds
substrings and IACHAR on known ASCII characters, without assuming native ASCII encoding.
6.3.2.4 p1 excludes marker characters from the statement.

## Deliberately pending

The missing-successor diagnostic facets in S6.3.2.4-003 and -005 remain
source-only. The current reporting interface requires a file and exact line;
its fatal-rejection EOF adapter cannot be substituted for a reporting oracle.
Character truncation additionally needs isolation from missing-END and generic
unterminated-literal failures. The catalogue records concrete next steps.

Separate pending reporting-adapter concerns remain visible: GNU's bare-marker
warning names a line but no source file, and its malformed split-name errors
point to the statement's first line rather than the required successor-line
anchor. Neither shape is silently accepted by this draft's exact-line oracles.
Three narrowly matched nonfatal predicates handle the located continuation
reports that the existing interface can already represent.

`python3 tools/generate_free_source_boundaries.py` regenerates the raw 256-line
continuation and significant-blank witnesses; `--check` detects changed bytes.
The chain contains 256 continuation lines, not 256 total physical lines.
No obsolete continuation-count cap or permissive compiler flag is imposed.
The f2018 reference-mode limitation remains part of the observation record.
