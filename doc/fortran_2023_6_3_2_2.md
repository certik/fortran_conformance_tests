# 6.3.2.2 Blank characters in free form

Draft catalogue: `doc/catalogues/free_form_blanks.json`. Source: checksum-pinned
J3/24-007 (18 December 2023), PDF page 71 / printed page 57. The original visual
Table 6.2 contains 28 entries in three columns of 10, 10, and 8 entries.

The source accounting distinguishes token interiors, inter-token permissions,
both character contexts, FORMAT, the compound complex-literal example, blank-run
equivalence, required separators, and every optional table boundary. All four
END BLOCK DATA gap combinations are explicit. The four positions illustrated
by the unnumbered note remain informative rather than extra S obligations.

Keyword-spelling programs are **positive controls**, not complete semantics of
the constructs that enclose them. Canonical token/keyword/construct definitions
remain with their defining sections. The blank-equivalence cases alone claim
their narrowly stated **effects**. END TEAM has a compile-only oracle and never
executes an undefined team value. No fixture or catalogue is self-approved.

Two reporting-oracle facets are explicitly pending: the existing runner does not
recognize uncoded, source-located Flang portability diagnostics when compilation
succeeds. Required diagnostic capability does not mean that rejection is mandatory.
Those observations remain failures in the unmodified report, not claims that Flang
was silent. Compiler crashes and unrelated feature failures never corroborate a
required diagnostic.

### S6.3.2.2-001: Free-form token interiors exclude blanks outside the stated exceptions

**Source:** 6.3.2.2 p1, first two sentences; J3/24-007 PDF page 71, printed page 57, lines 15-17. **Class:** Restriction.

**Definition:** A free-form lexical token cannot contain an inserted blank unless the blank is in a
character context or a format specification. This does not prohibit blanks between
separate tokens. In particular, a complex literal is compound syntax rather than one
lexical token, so its constituent tokens can be separated by blanks. Character context
means a character literal or a character string edit descriptor, not every
quoted-looking construct.

**Diagnostic obligation:** required.

**Facets:** `name-interior`, `integer-interior`, `real-interior`, `logical-interior`, `boz-interior`, `keyword-interior`, `operator-interior`, `label-interior`, `double-colon-interior`, `character-literal`, `character-edit-descriptor`, `format-specification`, `inter-token`, `compound-complex`.

**Oracle:** Nine isolated diagnostic cases insert one blank into otherwise legal tokens; nine
one-blank-removal repairs execute small independent checks. The selected tokens are a
name, integer, real exponent spelling, logical literal, BOZ digit sequence in DATA,
INTEGER keyword, power operator, label, and double colon. A quoted BOZ constant is not
the 3.21 character-context exception. Separate positive controls admit ordinary
inter-token blanks and a complex literal with blanks next to its parentheses, comma, and
unary minus. The character/FORMAT control checks two internal blanks in both a literal
and a character edit descriptor, and a blank inside I2 in a labeled FORMAT
specification.

**Oracle limitation:** These are representative blank insertions, not complete spelling/kind/operator/delimiter
coverage; canonical token owners remain unchanged. The negative sources must not simply
become legal assignments to names that resemble keywords. FORMAT and character contexts
are positive-control exceptions, not negative character blacklists. Character data
values and formatting mechanics are uncredited enclosing context. No split across
physical lines, comment termination, or statement-continuation obligation is authored.
Diagnostic capability comes from 4.2 p2(5), even without a numbered C item; a crash,
timeout, or unrelated feature failure is not corroboration.

**Dependencies:** 3.21, PDF 21; 5.5.2 p1, PDF 65; 6.2.1 and R603-R611/C601-C603, PDF 68-70;
R708/R714/R718-R720/R724/R725/R772-R776 retain lexical and literal definitions. 7.7 and
8.6.7 permit the small positive BOZ DATA value. 13.2.1 p1/R1301-R1302/C1301, PDF 289,
permits blanks inside FORMAT but preserves character string edit descriptors. R1033 and
the existing Clause 10 rules supply the arithmetic and assignment contexts. 4.2
p2(3)/(5) supplies diagnostic capability.

### S6.3.2.2-002: A run of blanks outside character context has the effect of one blank

**Source:** 6.3.2.2 p1, final sentence; J3/24-007 PDF page 71, printed page 57, lines 17-18. **Class:** Effect.

**Definition:** Replacing one blank by several consecutive blanks outside a character context preserves
the interpretation. The equivalence does not collapse the characters stored in a
character literal or emitted by a character string edit descriptor.

**Diagnostic obligation:** not-required.

**Facets:** `ordinary-statements`, `format-spacing`, `character-context-exclusion`.

**Oracle:** Separate programs compare compact and expanded inter-token spacing against the
independently known integer result 17, compare I2 with I followed by three blanks and 2
against the exact internal record ' 7', and check the literal length and internal-record
content of 'a  b'. The character-context case also distinguishes the one-blank spelling;
all substrings are statically in bounds.

**Oracle limitation:** Agreement between two equally wrong computations is insufficient: each effect has an
independent expected value or exact character record. The FORMAT rule is a canonical
dependency, not new coverage of all edit descriptors. These three finite contexts are
not a matrix of every statement and keyword.

**Dependencies:** 3.21 distinguishes the two character contexts. 13.2.1 p1, PDF 289, controls FORMAT
spacing and its character-string exception. 7.4.4 and 10.2.1.3 define character values
and assignment; ordinary integer addition and multiplication use Clause 10. This effect
is not a standalone negative diagnostic obligation.

### S6.3.2.2-003: Names, constants, and labels need separators from adjacent word-like tokens

**Source:** 6.3.2.2 p2; J3/24-007 PDF page 71, printed page 57, line 19. **Class:** Restriction.

**Definition:** Where the enclosing syntax places a name, constant, or statement label next to a
keyword, name, constant, or label, a separating blank is required. The rule is
conditional on that token adjacency being otherwise grammatical; inserting a blank
cannot repair missing commas, operators, or other syntax. A named constant is spelled as
a name. A quote delimiter does not by itself waive the separator before a character
literal.

**Diagnostic obligation:** required.

**Facets:** `keyword-name`, `keyword-named-constant`, `keyword-integer-constant`, `keyword-character-constant`, `keyword-label`, `label-keyword`, `label-name`, `keyword-prefix-name-control`, `nonfatal-diagnostic`.

**Oracle:** Seven negatives remove exactly one required blank from REAL x, STOP code, STOP 0, PRINT
'(A)', GO TO 10, 10 CONTINUE, or DO 10 i. Their repaired programs are minimal positive
controls with defined values, finite forward branches/loops, or normal STOP 0
termination. Six byte-preserved compile-only manifests use a diagnose expectation: a
located error or a specifically matched Flang missing-space portability report is
sufficient, independent of ordinary exit status. Their original source bytes and
execution IDs are retained. The character-constant case retains the ordinary rejection
contract. The labeled DO uses its matching labeled END DO, not a deleted shared or
nonblock terminal action. A separate legal program assigns to realx, stop0, goto10, and
endprogramx, showing why such names in assignment contexts must not be treated as
malformed keywords.

**Oracle limitation:** The seven role subdivisions are source accounting, not a claim that every Cartesian pair
occurs in valid Fortran syntax or that every semantic context was exercised.
Already-invalid adjacent constants are not used as separator tests. The source's
REAL/READ/30/DO note is illustrative, not an independent obligation. Fatal rejection is
not mandated by 4.2. The nonfatal-diagnostic facet checks a reporting oracle that
permits relevant nonfatal reports; it does not require processors to choose that
severity. Compiler family, file, line, severity and message constrain each nonfatal
predicate, and crashes, timeouts, unlocated or unrelated reports, and earlier build
failures cannot satisfy it.

**Dependencies:** 6.2.2/R603, 6.2.3/R604/R606, and 6.2.5/R611 retain the name/constant/label definitions.
5.5.2 permits names with keyword spellings. R801 supplies REAL x; R1162 and 11.4 supply
STOP; R1212 supplies PRINT (PDF 257); R1159 supplies GO TO; R1121/R1123/R1134 and C1137
supply the three-iteration labeled DO. 4.2 p2(5), PDF 46, requires Clause 6 diagnostic
capability.

### S6.3.2.2-004: Adjacent keywords outside Table 6.2 need one or more blanks

**Source:** 6.3.2.2 p3 before the exception list; J3/24-007 PDF page 71, printed page 57, lines 20-21. **Class:** Restriction.

**Definition:** Distinct adjacent keywords require at least one intervening blank unless their
combination is an exception listed in Table 6.2. Similar spelling or analogy with a
listed combination is not permission to join a different pair.

**Diagnostic obligation:** required.

**Facets:** `implicit-none`, `error-stop`, `select-rank`, `nonfatal-diagnostic`.

**Oracle:** Isolate IMPLICITNONE, ERRORSTOP, and SELECTRANK in byte-preserved diagnose manifests and
require a relevant report at the joined spelling. Their original source bytes and
execution IDs are retained. A located error or an explicitly matched Flang missing-space
portability diagnostic satisfies the reporting contract without requiring an
unsuccessful process exit. Each positive repair inserts one blank. ERROR STOP is in a
false action-IF branch so the control terminates normally, not by deliberate error
termination. SELECT RANK has an explicit assumed-rank dummy and a scalar actual; the
value is used only in RANK(0). An expanded-blank IMPLICIT NONE control demonstrates that
more than one separating blank is allowed.

**Oracle limitation:** Only three unlisted combinations are tested. SELECT CASE and SELECT TYPE being listed
does not license SELECT RANK. The assumed-rank feature can mask the latter negative if
it fails elsewhere, which is why its repair and exact source location are retained.
Compiler-specific severity/message predicates qualify nonfatal observations; wrong or
unlocated reports, earlier build failures, compiler crashes and timeouts do not pass.
The nonfatal facet permits a nonfatal report but does not require that processor choice.
This source-form diagnostic obligation is not inferred solely from the prose word
'shall'; 4.2 p2(5) applies directly.

**Dependencies:** R866 defines IMPLICIT NONE. R1163 defines ERROR STOP and R1141 provides the action-IF
context. R1151/C1155, R1152, and 11.1.10.2 define the SELECT RANK selector and guarded
scalar case (PDF 222-223); R827/C840 defines the assumed-rank dummy. Table 6.2 is the
exhaustive exception list for this separator rule, not a complete keyword grammar.

### S6.3.2.2-005: The listed keyword combinations admit omitted or inserted internal blanks

**Source:** 6.3.2.2 p3 and Table 6.2; J3/24-007 PDF page 71, printed page 57. Original visual table: 10 entries in the left column, 10 in the middle, 8 in the right. **Class:** Syntax.

**Definition:** Each combination enumerated in Table 6.2 has optional blanks at its listed internal word
boundaries in free form. This is a spelling exception, not permission to insert blanks
at arbitrary positions within an individual word or omit the separator before a
following name or label. END BLOCK DATA has two optional boundaries, so all four
omission/insertion combinations are included.

**Diagnostic obligation:** context-dependent.

**Facets:** `block-data`, `double-precision`, `else-if`, `else-where`, `end-associate`, `end-block`, `end-block-data-no-gaps`, `end-block-data-first-gap`, `end-block-data-second-gap`, `end-block-data-both-gaps`, `end-critical`, `end-do`, `end-enum`, `end-file`, `end-forall`, `end-function`, `end-if`, `end-interface`, `end-module`, `end-procedure`, `end-program`, `end-select`, `end-submodule`, `end-subroutine`, `end-team`, `end-type`, `end-where`, `go-to`, `in-out`, `select-case`, `select-type`.

**Oracle:** A finite set of separately executable positive controls places compact and separated
spellings in minimal legal enclosing constructs. Scalar results, three-iteration sums,
statically sized two-element arrays, guarded polymorphic selection, and initialized
named COMMON values give small independent checks. The block-data case contains all four
END BLOCK DATA variants. Explicit ordered compilation supplies the module/submodule/END
PROCEDURE context. END FILE uses a guarded scratch-file round trip. END TEAM is
deliberately a compile-only subroutine accepting a TEAM_TYPE dummy: require the declared
object, do not execute an undefined team value. Its form could be included in a
conforming caller using FORM TEAM. All these cases are labeled positive-control, not
effect coverage of the enclosing constructs.

**Oracle limitation:** One or a few legal contexts per table entry do not establish every semantic context,
optional clause, construct name, language binding, or keyword use. ELSE WHERE uses
unmasked alternatives; END SELECT uses SELECT CASE; IN OUT uses ordinary scalar
nonpointer dummies. END TEAM does not claim runtime team or multi-image semantics.
CRITICAL uses the existing coarray flags without an optional feature profile and does
not claim cross-image exclusion. BLOCK DATA and FORALL remain valid but obsolescent
contexts. Feature failures in any preceding module or construct are evidence of masking,
not disproof of an optional spelling. Unlisted keyword pairs and splits within a word
belong to the separate restriction cases.
