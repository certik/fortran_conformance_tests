### S7.1.5-001: Intrinsic types have their specified intrinsic operations

**Source:** 7.1.5 p1, PDF 75, printed 61, lines 31-33. **Class:** Effect.

**Definition:** Each intrinsic type has the operation set defined in Clause 10, with that clause's
operand type, kind, rank and value conditions. This does not admit every
intrinsic-operator token for every type or overload an already applicable intrinsic
operation with an incompatible interpretation.

**Diagnostic obligation:** not-required.

**Facets:** `integer-operation`, `real-operation`, `complex-operation`, `character-operation`, `logical-operation`, `intrinsic-operation-use-graph`.

**Oracle:** Five independently compiled programs check one admitted operation in each intrinsic
category: small default-integer addition, real unary identity of zero, complex unary
identity of zero, default-character concatenation and logical negation. Expected values
are specified independently in each source.

**Oracle limitation:** These finite effects do not close the operation-use graph. Zero-valued real/complex
controls do not test precision, rounding, signed-zero distinctions or IEEE arithmetic.
Character equality and concatenation assume no collating-code ordering. The existing
R608-R611 syntax catalogue remains the owner of operator-token alternatives.

**Dependencies:** 7.4.2 (PDF 80); 10.1.5.1/Table 10.2 (PDF 175-176), 10.1.5.2.1/Table 10.3 (PDF 176),
10.1.5.3-.4 (PDF 178-179), 10.1.9.3 (PDF 184-185).

### S7.1.5-002: Derived types have no intrinsic operations

**Source:** 7.1.5 p2, PDF 75, printed 61, lines 34-35. **Class:** Restriction.

**Definition:** There is no intrinsic operation on derived-type values. Operations on those values
require a program definition under the defined-operation rules. Intrinsic assignment of
a derived object is separately provided by 10.2.1 and is not an intrinsic operation in
this sense; availability of assignment does not imply intrinsic equality or arithmetic.

**Diagnostic obligation:** context-dependent.

**Facets:** `defined-derived-operator`, `intrinsic-assignment-not-operation`, `derived-operation-exclusion`.

**Oracle:** One positive control gives an ordinary derived type a scalar binary + through a
two-argument function with INTENT(IN) dummies and an OPERATOR interface, then checks its
initialized integer payload. A separate positive control uses only intrinsic derived
assignment, with no operator interface, to preserve that important distinction.

**Oracle limitation:** Both programs are restriction controls, not tests of absent operations or proof of
universal type semantics. Neither reads an uninitialized component. Assignment itself
and the exact defined-operator interface restrictions retain their canonical owners.

**Dependencies:** 7.5.11 p1 (PDF 109) explicitly distinguishes intrinsic assignment from operations and
requires explicit definitions for derived operations. 10.1.5.1/Table 10.2 (PDF 175-176),
10.1.6 and 15.4.3.2/.4.2 (PDF 326-329) supply the operator premises; 10.2.1.3 p15
supplies ordinary-component intrinsic assignment.

### S7.1.5-003: Enum and enumeration types have specified intrinsic operations

**Source:** 7.1.5 p3, PDF 76, printed 62, lines 1-2; this paragraph continues the section that starts on PDF 75. **Class:** Effect.

**Definition:** Enum and enumeration types have the intrinsic operation sets specified in Clause 10.
Their relational premises differ: enumeration operands have the same enumeration type
and compare ordinal positions; enum operands have the same enum type or involve an
integer expression with an enumerator primary of that enum type. Neither category
acquires intrinsic integer arithmetic merely from its representation or ordinal mapping.

**Diagnostic obligation:** not-required.

**Facets:** `enum-relations`, `enumeration-relations`, `nonintrinsic-operation-use-graph`.

**Oracle:** Separate F2023 programs compare two known values of a named enum type and two ordinal
values of an enumeration type. Enum integer comparisons use actual enumerator names, not
unqualified integer literals. Constructor arguments are within values already supported
by the enum or within the enumeration's declared ordinal range.

**Oracle limitation:** These cases may remain source-supported only if the available references do not
implement the F2023 types. No fall back to integer declarations, unnamed ENUM/BIND(C),
or weaker compile-only expectation is permitted. An F2018-mode parser failure is
retained as such, not treated as fixture invalidity.

**Dependencies:** 7.6.1 p1-p3/p7 (PDF 109-110); 7.6.2 p1/p3/p5 (PDF 111-112); 10.1.5.1 p6/Table 10.2 and
its continued legend (PDF 175-176); 10.1.5.5.1 p9-p10 (PDF 181).
