## Semantic and oracle boundaries

Logical has two values and requires one or more representation methods,
not multiple kinds. Both logical literal spellings support an optional
kind suffix; omission selects default logical. The selector-free LOGICAL
declaration uses KIND(.FALSE.). Result type is checked with an explicit
default-integer dummy, not just equality of potentially aliased kind codes.

The pending inventory witness has at most sixteen logical methods; a
second distinct logical kind is an optional profile, not a requirement.
The six numeric-suffix candidate branches also remain pending. The
default named-true/named-false effects have separate subset facets; they
do not close the full-inventory named-literal plans.
Different selector names may denote the same kind, and a numeric kind code
shared with integer or real does not make those types interchangeable.

Truth tests use defined logical values and logical operations, never
numeric equality, TRANSFER, arbitrary bit patterns or true-as-one
assumptions. Literal KIND is checked before receiving-object conversion.
Runtime effects stay run-phase when an implementation lacks support.

## Diagnostic boundary

Authored DATA negatives isolate abbreviated spellings, a missing dot and
an empty suffix, each with a minimal conforming control and an exact token
point. C733 separately uses four true/false, digit/name absent-zero pairs,
qualified by the existing logical-kind inventory profile.

Unsupported LOGICAL kind zero is an intended reporting cause when zero
is independently known to be absent; zero is not universally invalid.
Generic type/kind/constant messages, constancy complaints about already
constant selectors, unsupported facilities, crashes, verifier and resource
failures cannot substitute. Nonfatal cause-specific reporting may qualify;
fatal rejection is not required. There is no invented prose-rejection
policy or negative based on undefined logical representations.

GNU's full logical-constant bad-kind report is qualified by its observed
kind-value validation route, not by a generic `kind` substring. The
original literal point and an independent zero-absence profile bind the
actual value. Flang's explicit LOGICAL(KIND=0) report remains eligible,
while undeclared-variable-zero complaints and silent acceptance do not
qualify. Required case mode stays f2023; an f2018 reference result is
recorded only in its actual mode.

### R725: Logical literals use complete dotted TRUE or FALSE spellings with an optional kind suffix

**Source:** 7.4.5 R725, PDF 87, printed 73, lines 15-16. **Class:** Syntax.

**Definition:** A logical literal has the complete .TRUE. or .FALSE. spelling and may have an underscore
followed by kind-param. The canonical letter rule permits corresponding lower and mixed
case outside character contexts. The suffix syntax is R709, not an arbitrary
kind-selector expression. I/O abbreviations do not add logical-literal spellings to
program source.

**Diagnostic obligation:** required.

**Facets:** `true-unsuffixed`, `false-unsuffixed`, `true-named-suffix`, `false-named-suffix`, `digit-suffix`, `letter-case-use`, `true-spelling`, `false-spelling`, `closing-dot`, `suffix-needs-kind`.

**Oracle:** Compile controls cover complete spellings, named default suffixes and case variants.
Four one-defect DATA pairs check abbreviated true/false, a missing closing dot and an
empty suffix. The target's exact defined-operator token, unrecognized-dot and
orphan-underscore routes distinguish those lexical defects; GNU's missing-kind-parameter
route also qualifies the genuinely empty suffix. Generic DATA/expected-values recovery
is not credited.

**Oracle limitation:** R709/C718/C719 retain literal-kind grammar, named-constant type/constancy and sign
ownership; R704/R706/C717 retain declaration selectors. A unary minus or relational
comparison of logical values is not manufactured as a logical-literal negative. Only
cause-specific located token routes qualify; generic logical/type/constant/kind nouns,
unsupported language facilities, crashes, verifier and resource failures cannot pass.
Reporting may be nonfatal when specifically qualified.

**Dependencies:** 6.1.2 p3 and S6.1.2-002, PDF 67; R709/C718/C719, PDF 80-81; 8.6.7/R848 and p8/p10, PDF
137-138; C733; 4.2 p2(3), PDF 46. Formatted/list-directed input syntax is not the
source-literal grammar.

### C733: A logical literal kind value identifies an available logical method

**Source:** 7.4.5 C733 (R725), PDF 87, printed 73, line 17. **Class:** Restriction.

**Definition:** The kind-param of a logical literal identifies a logical representation method available
on the processor. The condition applies to either truth-value spelling and to
digit-string or named selectors. A nonnegative number need not be supported, and support
for the same number as an integer or real kind does not establish logical support.

**Diagnostic obligation:** required.

**Facets:** `supported-true`, `supported-false`, `unsupported-true-digit`, `unsupported-false-digit`, `unsupported-true-name`, `unsupported-false-name`.

**Oracle:** Four isolated compile-only pairs use nonnegative unsupported logical kind zero and
minimal supported repairs. The unchanged LOGICAL_KINDS profile establishes absence
without compiling the candidate. Flang's explicit LOGICAL(KIND=0) report qualifies.
GNU's observed full logical-constant bad-kind report was checked against its kind-value
validation path, distinct from preceding selector parsing; the exact literal point and
already-constant zero parameter bind the value. The target's undeclared-variable-zero
report and silent named-zero acceptance do not qualify.

**Oracle limitation:** Zero is not universally unsupported and may be a valid kind value. If it is supported,
this finite negative family is unavailable rather than passing; the mandatory named
controls still run. A later independently qualified absent code can extend the finite
family without claiming all integers were searched. C719 owns negative kind values. Do
not exclude all unsupported messages: distinguish unsupported kind values from
unimplemented facilities, parser recovery, already-constant-expression errors, crashes,
ASR verifier and resource failures.

**Dependencies:** R725/R709/C718/C719; 16.10.2.20 LOGICAL_KINDS, PDF 475; 16.9.118 KIND, PDF 424; 4.2
p2(3)-(4), PDF 46. Existing profile:
tests/profiles/integer_literal_absent_zero_logical.f90. Declaration support remains
C717.

### S7.4.5-001: Logical methods represent true and false as logical values

**Source:** 7.4.5 p1, PDF 87, printed 73, line 8. **Class:** Effect.

**Definition:** The two logical values represent truth and falsity. Their meaning is independent of the
chosen logical kind and is not an integer-value, bit-pattern or storage-size convention.
The domain statement does not license inspecting undefined logical storage or invent a
third logical value from a transferred bit pattern.

**Diagnostic obligation:** not-required.

**Facets:** `default-truth-values`, `selected-truth-values`, `kind-independent-values`.

**Oracle:** Exact logical truth assertions observe values directly. Cross-kind assignment is only a
dependent context for preservation of the two values, not an attempt to own the whole
assignment rule or establish storage compatibility.

**Oracle limitation:** The finite checks do not claim to test every stored bit pattern. Uninitialized values,
raw integer aliases, TRANSFER encodings and assumptions that true equals one or minus
one are excluded. Code must not rely on short-circuit evaluation to make an invalid
branch safe. These are runtime effects even when a compiler lacks a selected logical
method.

**Dependencies:** 10.1.5.4.1 and its logical truth tables, PDF 179; 10.2.1.3 p10, PDF 191; 16.10.2.20, PDF
475. The two-value domain is separately classified as a definition.

### S7.4.5-002: One or more logical methods are identified by KIND

**Source:** 7.4.5 p2, PDF 87, printed 73, lines 9-11, excluding the separately linked default-integer parameter-type restatement. **Class:** Effect.

**Definition:** At least one logical representation method is available. Each method is identified by a
KIND value, and KIND returns that parameter for an entity of the method. The
default-integer type of the parameter named KIND is already owned by S7.4.1-001; its
numeric identifier is not a portable representation description.

**Diagnostic obligation:** not-required.

**Facets:** `one-method-minimum`, `kind-inquiry`, `default-integer-inquiry-result`, `finite-method-inventory`.

**Oracle:** Runtime inventory membership, explicit type/kind agreement and both truth values
establish a finite supported-method witness. A bounded inventory entry is selected
without assuming order or a numeric code, and no distinct-kind assertion is made unless
the profile establishes it.

**Oracle limitation:** The logical type need not have multiple kinds. Kind codes may coincide numerically with
integer/real codes without making their types interchangeable. A failed advertised
method is a failed effect, not a profile skip based on missing compiler facilities.
Inquiry results and actual truth values do not promise a specific bit layout.

**Dependencies:** 7.4.1 p2/S7.4.1-001, PDF 80; 16.9.118, PDF 424; 16.10.2.20, PDF 475; 10.1.12, PDF
187-188, permits constant inquiry and array-constant-subobject selectors.

### S7.4.5-003: A LOGICAL declaration without a selector has the kind of the default false literal

**Source:** 7.4.5 p4, PDF 87, printed 73, lines 13-14. **Class:** Effect.

**Definition:** LOGICAL without a kind-selector denotes default logical, with the kind value
KIND(.FALSE.). This declaration-default rule is separate from the grammar of LOGICAL and
from the kind of a literal assigned to the object.

**Diagnostic obligation:** not-required.

**Facets:** `omitted-selector-kind`, `explicit-default-agreement`.

**Oracle:** The declaration's inquiry and an explicit matching dummy supply the exact type/kind
oracle. No numeric kind code or storage-sized constant is required.

**Oracle limitation:** R704/R706/C717 retain declaration syntax and support ownership. Assignment can convert a
logical value from another kind and therefore cannot alone establish the literal's
original kind. No default kind is assumed to be one, four or any other fixed number.

**Dependencies:** R704/R706/C717, PDF 80; 16.9.118, PDF 424; 10.2.1.3 p10, PDF 191; 15.5.2.5 supplies
explicit intrinsic dummy agreement.

### S7.4.5-004: A logical literal takes its explicit suffix kind or the default logical kind

**Source:** 7.4.5 p5, PDF 87, printed 73, lines 18-19. **Class:** Effect.

**Definition:** A logical literal with a kind suffix has the specified supported logical kind. Without
that suffix it has default logical kind. Both truth-value spellings obey the same rule.
Selected kind values can coincide; different selector spellings need not mean different
representations.

**Diagnostic obligation:** not-required.

**Facets:** `unsuffixed-true`, `unsuffixed-false`, `named-true`, `named-false`, `digit-suffixed`, `coincident-selectors`, `default-named-true`, `default-named-false`.

**Oracle:** The unprofiled run cases inquire KIND on both unsuffixed literals and on named
default-kind true/false literals before assignment, with logical truth and explicit
dummy checks. An alias case uses two names for the same supported default kind and
separately named procedures. The two added default-named facets identify the bounded
subset without closing the original full-inventory named-true/named-false plans.

**Oracle limitation:** R709 owns suffix spelling alternatives and C733 owns support. These value/kind effects
do not establish byte counts, true/false integer encodings or a kind relation to other
intrinsic types. The finite numeric-code family can be unavailable on a conforming
processor; unprofiled named/default cases still apply and broader numeric spelling
coverage remains bounded.

**Dependencies:** R725/C733 and R709/C718/C719, PDF 87 and 80-81; 16.9.118, PDF 424; 16.10.2.20, PDF 475;
10.2.1.3 p10, PDF 191, separates subsequent assignment conversion.
