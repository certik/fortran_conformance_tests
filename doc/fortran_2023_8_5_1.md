### C815: Explicit attribute specification is unique within a scoping unit

**Source:** 8.5.1 C815, physical PDF119, printed105, line27 **Class:** Restriction.

**Definition:** An entity cannot be explicitly given an attribute more than once in a scoping unit. The
scope-wide relation includes repetitions across statements; C801 remains the specific
same-type-declaration-statement attr-spec owner. An implication or default is not a
second explicit specification, and an authorized override/confirmation must retain its
own premises. Repeated identical values are not exempt, and changing the explicit value
does not automatically make a second specification an allowed override.

**Diagnostic obligation:** required.

**Facets:** `repeat-allocatable`, `repeat-dimension`, `repeat-intent`, `repeat-save`, `repeat-public`, `opposite-access-values`, `mixed-single-specification`, `implicit-confirmation`, `permitted-overrides`, `scope-and-association`, `same-statement-owner`, `remaining-attributes-source-use`.

**Oracle:** The selected cross-statement negatives need actual entity/property repetition, a source
span identifying the first and second specifications, and a minimally repaired
conforming control. Numbered reporting capability accepts ordinary0/nonzero reporting
rather than mandatory fatal rejection. The old valid case remains a real run; no current
coverage is claimed from its mere presence.

Cross-statement implementation: five retained isolated complete inputs each have one
facet, a first/second-statement source span and a located attribute/entity-repetition
diagnose predicate. Their five compile-only positive controls delete only the second
attribute statement's syntax, preserving its indentation, marker comment, newline and
every other byte. The existing C815_valid body keeps its run/effect role, m=1/get_p()=2
and size3/2/2 observations, with only additive facet metadata. Retained
standard/evidence/profiles remain unchanged; new controls use f2023. Native cause
phrases are finite calibration, not prescribed wording; ordinary zero/nonzero reporting
does not require fatal rejection or printed rule codes.

**Oracle limitation:** Six C815 facets have these explicit fixture roles; six other C815 facets and all other
source plans remain pending. Representation is not approval. The invalid grouped key is
retired as history; each negative uses its full-ID key. C815_valid retains its key and
can receive a legitimate content-bound current review. Source, case, link and inventory
adjudications are independent and are preserved by generation. Schema-limited nonfatal
warnings remain raw report/noncredit evidence, not proof of absent reporting capability.
Source echoes, bare keywords, wrong attributes/entities, implicit confirmation,
unsupported facilities, Internal/verifier/resource failures and recovery are not causal
corroboration. No C801, C816, accessibility, source-use or diagnostic-policy coverage is
added.

### C816: A nonallocatable nonpointer function result uses an explicit-shape list

**Source:** 8.5.1 C816, physical PDF120, printed106, line1 **Class:** Restriction.

**Definition:** When an array-spec is supplied for a function result that is neither ALLOCATABLE nor
POINTER, that array-spec is an explicit-shape-spec-list. The exact syntactic category
matters: a vector explicit-shape-bounds-spec is not that list, even though other
contexts can use it to describe explicit shape. Explicit shape need not have constant
bounds. Result attributes and the definition of the returned value retain15.6.2.2's
requirements.

**Diagnostic obligation:** required.

**Facets:** `explicit-list-admission`, `specification-bound-list`, `vector-upper-bounds`, `vector-lower-and-upper-bounds`, `mixed-scalar-vector-bounds`, `nonresult-vector-source-use`, `other-array-spec-source-use`, `result-and-scalar-edge-source-use`.

**Oracle:** Finite complete function-result grammar/report contrasts with shape-preserving list
repairs, plus qualified admissions and original-owner source comparisons. Every
nonpointer result is defined if the function is invoked; no repair has an unallocated
result, undefined pointer association or an expired target.

**Oracle limitation:** All eight facets are pending. R818/C833 vector properties come from the original syntax
and expression rules, not compiler consensus, direct RANK of a constructor/value
expression or a fixed-rank destination proxy. An unsupported feature, scalar/result-role
change, missing result definition or unrelated interface error cannot count for C816. No
compiler probe or fixture is created.

**Dependencies:** 8.2 R803/C809;8.5.8.1 R814;8.5.8.2 R815-R819,C831-C833;8.5.8.3-.7;8.5.17
C864;10.1.11/.12;15.4.2.2;15.6.2.2p3/p4,C1570.

## Exact cross-statement corpus

isolated legacy inputs, not reconstructed programs. Exactly the second
