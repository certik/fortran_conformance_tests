### S11.1.3.2-001: ASSOCIATE execution evaluates selectors before executing the block

**Source:** 11.1.3.2 p1 first sentence; J3/24-007 PDF p204. **Class:** Effect.

**Definition:** Executing an ASSOCIATE construct evaluates every expression within every selector that
is a variable designator and evaluates every other selector, followed by execution of
the block. This establishes selector values or variable associations before block
execution; it does not prescribe expression evaluation order among selectors or
authorize side-effect/count oracles.

**Diagnostic obligation:** not-required.

**Facets:** `expression-selector-value-before-block`, `variable-designator-subexpressions-before-block`, `block-executes-after-selector-evaluation`.

**Oracle:** Use side-effect-free selector expressions and direct values. Do not infer order among
multiple selector evaluations or count evaluations.

S11.1.3.2-001 ASSOCIATE selector-evaluation runtime fixtures: two complete
run/effect/f2023 programs observe selector evaluation before ASSOCIATE block execution
without side-effect or call-count oracles. The expression-selector case evaluates
seed+17 while seed is 23, then changes seed to -900 inside the block and reads the
associate name as literal 40; a rule that re-evaluated after the block assignment would
produce -883. The variable-designator case uses a(idx) with idx=2, changes idx to 4
inside the block, assigns through cell, and checks that a(2) becomes 77 while a(4)
remains 44; a deferred-subscript rule would update the wrong element. The selector
expressions are ordinary integer expressions and the observations are final scalar
values plus exact completion stdout.

**Oracle limitation:** This source-only catalogue records pending plans only. It creates no Fortran test
program, invokes no processor, approves no fixture or oracle, and claims no coverage.
Future ASSOCIATE fixtures must use non-vacuous selectors and sentinels: lower bounds
must differ where bounds are asserted, character length must be checked with LEN rather
than inferred from padded comparison, outer homonyms must start with values different
from any inner assignment, and assignment through an associate name is credited only
after the selector is established definable. No plan may count selector evaluations,
depend on function side effects, assume a real or complex kind exists, or use compiler
agreement as an oracle.

S11.1.3.2-001 ASSOCIATE selector-evaluation fixture boundaries: only
expression-selector-value-before-block and
variable-designator-subexpressions-before-block are represented.
block-executes-after-selector-evaluation remains pending because this packet does not

### S11.1.3.2-003: ASSOCIATE associating entities assume selector declared type, type parameters, and polymorphic status

**Source:** 11.1.3.2 p1 final sentences; J3/24-007 PDF p204. **Class:** Effect.

**Definition:** The associating entity assumes the declared type and type parameters of the selector. If
and only if the selector is polymorphic, the associating entity is polymorphic. Dynamic
type and additional attributes are owned by 11.1.3.3.

**Diagnostic obligation:** not-required.

**Facets:** `declared-type-control`, `character-length-type-parameter`, `kind-type-parameter-source`, `polymorphic-selector-control`, `nonpolymorphic-selector-control`.

**Oracle:** LEN/KIND or source admissibility may observe type parameters only when the expected
value is required by declarations in the same test. Do not assume processor-dependent
kind availability.

S11.1.3.2-003 ASSOCIATE type-parameter runtime fixture: one complete run/effect/f2023
program observes a required character type parameter directly with LEN. The selector is
the substring parent(3:8) of a CHARACTER(LEN=9) variable, so the selector's length type
parameter is 6 by the substring endpoints and the associating entity must assume that

is used as a length oracle. A rule copying the parent length 9, using default length 1,
