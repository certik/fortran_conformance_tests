# Fortran 2023: 7.4.3.1 Integer type

Draft catalogue: `doc/catalogues/integer_type.json`.
Pinned J3/24-007, 18 December 2023: PDF 80-81, printed 66-67.
The seventeen base units include p1-p7, R707-R712, C718-C720 and the
unnumbered note. Every declared fine subdivision is accounted.

The INTEGER keyword restatement stays with R705. Representation methods,
zero, mandatory range-18 support, default range five, signed-literal
denotation, literal kind and decimal interpretation have separate
append-only S IDs. Definitions and informative examples do not manufacture
effects or invalid twins.

The generator `tools/generate_integer_literal_fixtures.py` owns the new
scoped programs, isolated compile-only pairs and profiles; use `--check`
to compare their exact deterministic bytes. Local index registrations are
needed for rendering and validation, but are not part of the author commit.

## Bounded numerical evidence

The mandatory unprofiled cases use supported inquiries and never replace
missing range-18 support with a default kind or optional skip. A separate
at-most-sixteen-kind inventory branch directly checks the maximum RANGE
over every advertised integer method. This avoids substituting a selected
kind code, storage size or default range for the actual mandatory threshold.
Larger inventories remain explicit follow-on work.

Five static boundary branches cover radix-two models with 7, 15, 31, 63
and 127 digits. The 31-digit branch specifically qualifies the default
method; the others use SELECTED_INT_KIND with requests 2, 4, 18 and 38.
Only request 38 is optional support. Each profile safely reconstructs HUGE
using small values and pre-operation bounds checks. Profiles do not compile
the candidate boundary literal to decide whether it fits.

The literal programs independently check the upper endpoint, its
predecessor, plus and negative model endpoints. Separate decimal effects
test 48 leading zeros at each boundary and 64 leading zeros on small values.
These are symmetric numeric-model endpoints, not a claim of two's-complement
representation or the complete actual machine range. Extra-model values,
all-method denotation and versioned value-set evidence remain explicit
pending work. Out-of-model calibration probes are not conformance cases,
required-diagnostic assertions or permissive extension controls.

## Diagnostic and evidence boundary

Every negative has one edited defect and a minimally repaired compile
control. Reports must be causal and at the exact defective statement;
source echoes, recovery ranges, wrong files/steps, unlocated summaries,
unrelated implementation errors, crashes and resource failures do not pass.
Unsupported-kind reports are intentionally eligible for C719/C720, unlike
unsupported implementation features masking a different rule.

C719's negative named value necessarily also fails integer-kind support;
this overlap is recorded, not presented as proof of an independent internal
compiler check. The nonnegative unsupported-value C720 pairs distinguish
support separately. Zero is qualified as absent by an independent inventory
probe, never assumed to be unsupported universally.

All catalogues and fixtures are drafts for independent parent review.
Source accounting, authored facets, runtime effects, positive controls,
diagnostic observations and optional-profile availability remain separate.
This unit neither approves fixtures nor completes whole-standard coverage.

### R707: A signed integer literal has at most one leading sign

**Source:** 7.4.3.1 R707, PDF 80, printed 66, line 38. **Class:** Syntax.

**Definition:** A signed-int-literal-constant is an int-literal-constant with an optional sign. The sign
can be omitted, plus or minus through R712; the literal may have the R708 kind suffix.
An expression containing unary operators is not automatically an occurrence of this
syntactic class.

**Diagnostic obligation:** required.

**Facets:** `unsigned`, `plus`, `minus`, `kind-suffix`, `single-sign-only`.

**Oracle:** A DATA control supplies six distinct small values with omitted, plus and minus signs,
with and without a supported named suffix, and independently checks each value. A
compile-only pair changes a double minus sign to a single minus in one DATA value.

**Oracle limitation:** R848 explicitly admits signed-int-literal-constant, so the negative is not an attempt to
outlaw a legitimate unary expression in ordinary assignment. There is one malformed sign
prefix, not a negative repetition count or mismatched DATA object count. Case-specific
DATA/delimiter syntax predicates exclude an invalid-kind complaint because no kind
suffix occurs, as well as implementation and magnitude failures. The repair is a
positive compile control. Literal denotation effects retain S7.4.3.1-005 ownership.

**Dependencies:** R708/R712; 8.6.7/R848 and p8/p10, PDF 137-138, establish the signed-literal context,
one-to-one initialization and value interpretation. 4.2 p2(3), PDF 46, requires
reporting capability, not fatal rejection.

**Source:** 7.4.3.1 p7, PDF 81, printed 67, line 10. **Class:** Effect.

**Definition:** An integer constant's value is interpreted in decimal. Successive digits have decimal

kind, or consume the numeric magnitude range. This is distinct from kind selection and

**Diagnostic obligation:** not-required.

**Oracle:** An unprofiled program checks all ten digit values with a counter, a five-digit
positional value by a weighted sum, and a leading-zero value containing 8 and 9. It
checks dynamic array bounds before indexing. Another uses a named range-selected kind
and an independent split-value calculation. A third tests 64 leading zeros on a small
value and a long all-zero literal. Five model-qualified boundary programs separately
check 48 leading zeros on explicit positive and negative model-endpoint literals.

**Oracle limitation:** Leading-zero tests check unchanged mathematical value at small magnitudes and exact
separately qualified model limits, not a maximal processor source-length claim. Every
generated source line remains within 132 characters. No out-of-range literal is
mislabeled as a conforming extension control. The selected/boundary profiles and model
limitations remain distinct from the unprofiled decimal obligation.

supplies initialization. Model inquiries and pre-operation guards have the same
