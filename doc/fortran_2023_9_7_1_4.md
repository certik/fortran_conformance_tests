### S9.7.1.4-001: Successful pointer allocation creates a target and associates the pointer with it

**Source:** 9.7.1.4 p1, J3/24-007, 18 December 2023, physical PDF164. **Class:** Effect.

**Definition:** Allocation of a pointer creates an object that implicitly has the TARGET attribute.
After successful ALLOCATE for a pointer, the pointer is associated with the target and
can be used to reference or define it. Additional pointers can become associated with
that pointer target or a part of it by pointer assignment, and ASSOCIATED can be used to
determine whether a pointer with defined association status is associated.

**Diagnostic obligation:** not-required.

### S9.7.1.4-002: Allocating an already associated pointer creates a new target and breaks the previous association

**Source:** 9.7.1.4 p1, J3/24-007, 18 December 2023, physical PDF164. **Class:** Effect.

**Definition:** It is not an error to allocate a pointer that is already associated with a target. A new
pointer target is created as required by the pointer attributes and ALLOCATE-specified
array bounds, type, and type parameters; the pointer becomes associated with the new
target; any previous association is broken; and a previous target created by allocation
becomes inaccessible unless other pointers remain associated with it.

**Diagnostic obligation:** not-required.

### S9.7.1.4-003: Pointer function results must return with associated or disassociated status

**Source:** 9.7.1.4 p2, J3/24-007, 18 December 2023, physical PDF164. **Class:** Restriction.

**Definition:** At the beginning of execution of a function whose result is a pointer, the association
status of the result pointer is undefined. Before such a function returns, it shall
either associate a target with this pointer or cause this pointer association status to
become disassociated.

**Diagnostic obligation:** not-required.
