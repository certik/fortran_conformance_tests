### S5.5.7-001: Processors have at least one companion processor

**Source:** 5.5.7 p1.one-or-more-companions, J3/24-007, 18 December 2023, physical PDF66. **Class:** Effect.

**Definition:** A Fortran processor has one or more companion processors. The companion set can include
the Fortran processor itself, so this concept does not by itself require a distinct C
compiler, a linker convention, a storage layout or a named external tool.

**Diagnostic obligation:** not-required.

**Facets:** `companion-processor-existence`.

**Oracle:** No direct execution oracle is assigned here. Future fixtures observe only the concrete
interoperable relation required by their owning Clause 15 or 18 rule.

**Oracle limitation:** A pure Fortran program cannot portably distinguish a self companion from a separate
processor or enumerate the companion set. Linker names, object formats and toolchain
banners are processor dependent.

**Dependencies:** 15.6.3 covers procedures defined by means other than Fortran; Clause 18 covers C
interoperability and C descriptors; 4.2 processor conformance governs the processor
concept.

### S5.5.7-002: Processors may select among multiple companion processors by processor-dependent means

**Source:** 5.5.7 p1.multiple-selection-latitude, J3/24-007, 18 December 2023, physical PDF66. **Class:** Effect.

**Definition:** If a processor has more than one companion processor, the standard grants processor
latitude for the means by which the Fortran processor selects among them. It fixes no
portable selector name, priority order, ABI choice, command-line option or header path
in this overview.

**Diagnostic obligation:** not-required.

**Facets:** `multiple-companion-selection-permission`.

**Oracle:** This is processor permission, not a required observable behavior. Future valid programs
and oracles must be invariant across any companion-selection means the processor
provides.

**Oracle limitation:** No Fortran-only program can portably require, enumerate or compare a particular
selection mechanism among multiple companion processors. Companion choice, ABI naming,
object formats, headers, library search order and command-line switches are processor
dependent.

**Dependencies:** 18.3, 18.5 and 18.9 specify concrete C interoperability requirements; 15.6.3 defines
non-Fortran procedure definitions; processor dependency terminology is governed by
Clause 4.
