### S7.5.2.2-001: Type-name, component and binding accessibility are independent

**Source:** 7.5.2.2 p1; J3/24-007, 18 December 2023, PDF 89, printed 75, lines 13-14. **Class:** Effect.

**Definition:** The type name's accessibility is determined by 8.5.2 independently of the accessibility
of components and type-bound procedures. Making a name public does not make all its
members public, and private members do not make the type name private. A private type
name does not prevent access to an otherwise accessible object and its public members.
Component PRIVATE and binding PRIVATE have separate scopes and defaults.

**Diagnostic obligation:** not-required.

**Facets:** `public-name-public-members`, `public-name-private-members`, `private-name-public-members`, `private-name-private-members`, `component-private-binding-public`, `binding-private-component-public`.

**Oracle:** Six ordered provider/client runs exercise public/private type names, component defaults
and binding defaults independently. A public module object with a private type name is
accessed without importing that name. Initialization precedes public member or method
observations, and real passed-object dummies are scalar CLASS(record) with appropriate
intent. Public components do not expose private bindings and component PRIVATE does not
change public binding defaults.

**Oracle limitation:** These finite positive effects are not inaccessible-name diagnostic evidence or proof of
every visibility path. No invalid twin is invented for an independence effect. Private
component/binding exclusions keep their 7.5.4.8/7.5.5/19.3.4 owners; private type-name
use and constructor questions remain in S7.5.2.2-002. Existing 7.1.2/7.2/7.3 controls
are unchanged and receive no new credit.

**Dependencies:** 8.5.2 p1-p4/R807/C817 (PDF 120); 7.5.4.5/C765, 7.5.4.8/R745/C771 and
7.5.5/R746-R747/C772/p8-p9/NOTE 2 (PDF 96, 99, 101); 19.3.4 p1/p3/p5 and 19.5.1.4 p4

### S7.5.2.2-002: A module-private type name and its constructor are confined to that module and descendants

**Source:** 7.5.2.2 p2; PDF 89, printed 75, lines 15-17. **Class:** Restriction.

**Definition:** If a type is defined in a module scoping unit and its name is private there, the type
name and its corresponding structure constructor are accessible only within that module
and its descendants. This does not hide every object of that type or its public
components/bindings. Host/import/shadowing rules still govern a particular reference;
being in an allowed region is not a waiver of those rules. A descendant obtains private
names through the appropriate host path, not a general exemption from the
public-identifier requirement on USE.

**Diagnostic obligation:** context-dependent.

**Facets:** `module-constructor-access`, `descendant-constructor-access`, `private-name-import-exclusion`, `constructor-use-graph`.

**Oracle:** A module construction service and a root/intermediate/descendant submodule chain
construct the private type only in allowed host scopes and return defined integer
values. The canonical C1409 pair changes only provider type-name privacy, preserving
consumer source; it exists under its own primary owner, while the local semantic-link
facet and broader constructor use graph remain pending.

**Oracle limitation:** This prose does not by itself prescribe fatal rejection. Numbered C1409/C795/C7107 or a
proven Clause 19 source relation can supply reporting capability; an unbound
generic-looking call cannot supply it merely because a similarly named private type
exists elsewhere. A public factory or accessible object is not the private constructor
name. No approved semantic link is created.
