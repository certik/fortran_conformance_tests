### S12.6.4.8.1-001: Defined input/output can override default derived-type data transfer handling

**Source:** S12.6.4.8.1, J3/24-007, 18 December 2023, physical PDF268. **Class:** Effect.

**Definition:** Defined input/output allows a program to override the default handling of derived-type
objects and values in data transfer statements described in 12.6.3.

**Diagnostic obligation:** not-required.

**Facets:** `defined-io-overrides-default-derived-type-transfer`.

**Oracle:** Plans are pending and source-derived. Positive plans establish a non-default state first
(for example by writing known records, initializing variables to nonzero/nonblank
sentinels, or using a compile-only conforming control) and then observe only portable
properties: exact internal records, successful IOSTAT zero, nonzero IOSTAT or named
status values where the standard names them, required dummy characteristics through a
conforming interface, or required diagnosis of a numbered syntax rule or constraint.
Negative plans change one source property from a conforming control and do not require a
particular diagnostic message, severity, exit status, printed rule number, IOMSG
wording, or processor-dependent numeric status value.

**Oracle limitation:** Source accounting only. This packet creates no Fortran fixture, compiler invocation,
execution evidence, evidence link, fixture approval, oracle approval, or coverage claim.
IOMSG wording and processor-dependent numeric status values are never an oracle. A
diagnostic facet is only a future source-control plan when the cited numbered rule alone
is violated and the invalid program reaches that rule; unnumbered program restrictions
are not assumed to be diagnosed.
