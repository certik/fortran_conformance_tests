### S9.7.5-001: An ERRMSG variable is independent of allocation actions, allocate-object properties, and STAT value

**Source:** 9.7.5 p1, J3/24-007, 18 December 2023, physical PDF167. **Class:** Restriction.

**Definition:** The errmsg-variable shall not be an allocate-object of the ALLOCATE or DEALLOCATE
statement in which it appears. Its denotation shall not depend on the value, bounds,
deferred type parameters, allocation status, or association status of any
allocate-object in that statement, and shall not depend on the value of the
stat-variable. The scalar default character variable form for ERRMSG= is owned by
9.7.1.1 R931 for ALLOCATE and by the corresponding DEALLOCATE syntax owner; this
requirement owns the shared independence restriction.

**Diagnostic obligation:** not-required.

### S9.7.5-002: ERRMSG assignment occurs on ALLOCATE or DEALLOCATE error and is unchanged on success

**Source:** 9.7.5 p2, J3/24-007, 18 December 2023, physical PDF167. **Class:** Effect.

**Definition:** If an error condition occurs during execution of an ALLOCATE or DEALLOCATE statement
with an ERRMSG= specifier, the errmsg-variable is assigned an explanatory message as if
by intrinsic assignment. If no such error condition occurs, the definition status and
value of the errmsg-variable are unchanged. The exact explanatory message content is
processor dependent or otherwise not specified by this subclause; this requirement owns
only assignment on error and unchanged definition status and value on success.
