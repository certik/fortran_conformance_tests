### S10.1.3-001: Intrinsic and extension operation categories have the Table 10.1 precedence order

**Source:** 10.1.3 p1 and Table 10.1; J3/24-007 PDF p172. **Class:** Effect.

**Definition:** For expressions formed under 10.1.2, intrinsic and extension operations are interpreted
according to the relative precedence categories in Table 10.1 unless parentheses change
the order in which operands are combined. The order is: defined unary, exponentiation,
multiplication/division, unary plus/minus, binary plus/minus, character concatenation,
relational, logical NOT, logical AND, logical OR, logical EQV/NEQV, and defined binary.

**Diagnostic obligation:** not-required.

**Facets:** `power-before-unary-minus`, `multiply-before-binary-plus`, `unary-before-binary-plus`, `character-before-relational`, `relational-before-logical-or`, `not-before-and`, `and-before-or`, `or-before-eqv`, `defined-binary-lowest`, `parentheses-override-category-precedence`.

**Oracle:** Use integer, character, and logical literals or non-associative defined operations to
make precedence observable. Do not infer grouping from an associative intrinsic
operation whose value would be unchanged.

### S10.1.3-002: A defined operation has the precedence of its operator

**Source:** 10.1.3 p2; J3/24-007 PDF p172. **Class:** Effect.

**Definition:** When an operation is a defined operation, its precedence is not determined by the
defining procedure but by the operator token used for the operation. A defined operation
that extends an intrinsic operator uses that intrinsic operator's Table 10.1 precedence,
while dotted defined unary and defined binary operators use their extension rows.

**Diagnostic obligation:** not-required.

**Facets:** `extended-intrinsic-operator-precedence`, `defined-unary-operator-highest`, `defined-binary-operator-lowest`, `dotted-name-not-intrinsic-symbol-precedence`.

**Oracle:** Defined-operation precedence must be observed only through valid defined-operation
interfaces with literal-distinguishable, non-associative results. The future case may
not attribute generic resolution, distinguishability, or procedure binding failures to
this subclause.

### S10.1.3-003: The general expression form establishes same-class operand grouping for interpretation

**Source:** 10.1.3 p3; J3/24-007 PDF p172. **Class:** Effect.

**Definition:** Within a syntactic class, the general expression form in 10.1.2 establishes the order in
which operands are combined for interpreting the expression, unless parentheses change
that order. This is an interpretation rule; it does not require any particular runtime
evaluation order for operand computations.

**Diagnostic obligation:** not-required.

**Facets:** `left-grouped-subtraction`, `left-grouped-division`, `right-grouped-exponentiation`, `left-grouped-concatenation-boundary`, `logical-same-class-grouping-boundary`, `parentheses-override-same-class-grouping`.

**Oracle:** Use non-associative integer operations or valid non-associative defined extensions when
grouping must be observable. Literal equality for associative intrinsic operations is
not evidence of grouping.
