### S10.1.6.1-001: A unary defined operation is established by an applicable one-argument function and generic operator interface

**Source:** 10.1.6.1 p1-p3; J3/24-007 PDF p181-p182. **Class:** Effect.

**Definition:** A unary defined operation has the form defined-unary-op x2 or intrinsic-operator x2 and
is defined only when a one-dummy FUNCTION or ENTRY is supplied through an OPERATOR
generic interface or corresponding type-bound generic binding, with dummy type, type
parameters, rank or elemental rank route, and array shape satisfying the stated operand
conditions.

**Diagnostic obligation:** not-required.

**Facets:** `unary-defined-operation-forms`, `one-dummy-function-definition`, `operator-generic-interface-route`, `type-bound-generic-binding-route`, `dummy-compatible-with-dynamic-operand-type`, `dummy-type-parameters-match-operand`, `specific-rank-match`, `elemental-no-other-function-rank-route`, `unary-array-shape-match`, `intrinsic-unary-operator-extension`.

**Oracle:** Future positives compare the operation value with the defining function result for
literal-bearing operands. Future negatives must isolate the p2/p3 applicability
condition and not an OPERATOR interface constraint, grammar error, generic ambiguity, or
unsupported dynamic-type feature.

**Oracle limitation:** This source-only catalogue records pending plans only. It creates no Fortran test
program, invokes no processor, approves no fixture or oracle, and claims no coverage.
Future cases must not infer which operand was evaluated, the order of evaluation, or
whether an optional evaluation was omitted; must not assert a result that a permitted
mathematically or logically equivalent rewrite could change; must not use floating-point
tolerance as an escape hatch; must not rely on compiler agreement, address arithmetic,
TRANSFER, emitted assembly, or undefined reads; and must attribute every negative to the
cited requirement rather than to an independently invalid rule owned elsewhere.

### S10.1.6.1-002: A binary defined operation is established by an applicable two-argument function and generic operator interface

**Source:** 10.1.6.1 p4-p6 and NOTE; J3/24-007 PDF p182. **Class:** Effect.

**Definition:** A binary defined operation has the form x1 defined-binary-op x2 or x1 intrinsic-operator
x2 and is defined only when a two-dummy FUNCTION or ENTRY is supplied through an
OPERATOR generic interface or a corresponding type-bound generic binding in the declared
and dynamic type of either operand, with dummy type, type parameters, ranks or elemental
conformability route, and array shapes satisfying the stated conditions. Intrinsic
operator symbols can be extended by such defined operations.

**Diagnostic obligation:** not-required.

**Facets:** `binary-defined-operation-forms`, `two-dummy-function-definition`, `operator-generic-interface-route`, `type-bound-generic-binding-route-left-or-right`, `dummies-compatible-with-dynamic-operand-types`, `dummy-type-parameters-match-operands`, `specific-rank-matches`, `elemental-conformable-no-other-function-route`, `binary-array-shape-match`, `intrinsic-binary-operator-extension`, `concat-defined-extension-grouping-control`, `and-defined-extension-grouping-control`, `eqv-neqv-defined-extension-grouping-control`, `generic-nonapplicability-not-syntax`.

components so the oracle is a value comparison between independently computed
parenthesisations, never a side-effect, call-count, operand-order, short-circuit, or
compiler-agreement observation.
