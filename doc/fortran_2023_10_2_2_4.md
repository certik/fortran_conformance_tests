### S10.2.2.4-001: A procedure pointer object becomes associated or disassociated according to the procedure pointer target

**Source:** 10.2.2.4 p1; J3/24-007 PDF p196. **Class:** Effect.

**Definition:** If the procedure pointer target is not a pointer or dummy argument, the procedure
pointer object becomes associated with that target. If the target is a nonpointer dummy
argument, the pointer object becomes associated with the ultimate argument of the dummy.
Otherwise the pointer object receives the association status of the pointer target and,
when that target is associated with a procedure, becomes associated with the same
procedure.

**Diagnostic obligation:** not-required.

**Facets:** `nonpointer-nondummy-target-associated`, `nonpointer-dummy-ultimate-argument-associated`, `associated-procedure-pointer-target-propagates`, `disassociated-procedure-pointer-target-propagates`.

**Oracle:** Procedure-pointer evidence must use calls through the pointer only after the source rule
requires association with a known procedure. Interface legality, characteristics,
purity, elemental status, and host-instance mechanics remain Clause 15 dependencies
except for the local pointer-assignment consequences catalogued here.

### S10.2.2.4-003: An explicit-interface procedure pointer target has matching characteristics except for pure, simple, and elemental intrinsic target exceptions

**Source:** 10.2.2.4 p3; J3/24-007 PDF p196. **Class:** Restriction.

**Definition:** If the procedure pointer object has an explicit interface, its characteristics shall be
the same as the procedure pointer target, except that the target may be pure even if the
object is not pure, may be simple even if the object is not simple, and may be an
elemental intrinsic procedure even though the object cannot be elemental.
