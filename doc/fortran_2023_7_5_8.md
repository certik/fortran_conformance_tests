### S7.5.8-001: A pointer component contributes its association rather than a copied target value

**Source:** 7.5.8, p1.pointer-component, p1.pointer-association-value; J3/24-007, 18 December 2023, physical PDF106, printed92. **Class:** Effect.

**Definition:** For a pointer component, its component value is its pointer association. A data target's
contents are not a replacement for that association, and a procedure pointer denotes its
procedure association rather than an evaluated function result. Disassociated and
associated states must be distinguished without querying an undefined association. The
operation used to observe or transfer this value retains its own pointer-assignment and
interface conditions.

**Diagnostic obligation:** not-required.

**Facets:** `data-pointer-association`, `array-pointer-association`, `procedure-pointer-association`, `disassociated-pointer-value`.

**Oracle:** Four declared runtime-effect connections each reuse the single complete
S10_2_1_3_024_valid program. ASSOCIATED compares the copied scalar/strided-array
pointers with live named targets and the procedure pointer with double_value under its
explicit interface; mutation checks scalar=41 and values(4)=43. Explicit NULLIFY
precedes the second copy and all three disassociation guards. The program retains
S10.2.1.3-024 ownership and runs once per configuration, not once per link. Declared
connections are not reviewed links or passing effects: source, case/oracle, connection
and complete per-configuration execution gates remain separate.

**Oracle limitation:** Read only defined values and independently established allocation/association states.
Keep pointer targets alive, use exact eligible procedure interfaces, guard allocation
before dependent inquiries, and do not dereference null or undefined pointers. A
component value is not an ABI layout or a byte encoding. This paragraph does not
independently prescribe how every operation copies a pointer; the canonical assignment
rules supply that operation. No allocation-address, target-value equality or opaque C
descriptor oracle is authorized.

### S7.5.8-002: An allocatable component's value includes conditional allocation characteristics and data

**Definition:** An allocatable component contributes its allocation status. When it is allocated, its
component value additionally includes dynamic type, type parameter values, bounds and
data value. The allocated-only qualification does not authorize reading absent data or
inferring an allocation's physical address. Allocation, assignment, inquiry and

**Oracle limitation:** Read only defined values and independently established allocation/association states.

### S7.5.8-003: An ordinary component contributes its data value

**Source:** 7.5.8, p1.nonpointer-nonallocatable, p1.ordinary-component-value; J3/24-007, 18 December 2023, physical PDF106, printed92. **Class:** Effect.

**Definition:** For a component with neither POINTER nor ALLOCATABLE, the component value is its data
value. This includes intrinsic data, a nested derived value and array-valued data under
their own type, parameter, shape and definedness rules. It does not make general
derived-type equality intrinsic or override a separately applicable defined assignment.

**Diagnostic obligation:** not-required.

**Facets:** `ordinary-intrinsic-components`, `ordinary-nested-derived-component`, `ordinary-array-components`.

(31,2.5)/(43,-3.5); changing the copied first array integer to -1 leaves the source at
31. Neither local derived type supplies defined assignment. The
source/fixture/connection gates and complete single-configuration run remain
prerequisites; three member occurrences do not mean three executions or three currently
qualified effects.

**Oracle limitation:** Read only defined values and independently established allocation/association states.
Keep pointer targets alive, use exact eligible procedure interfaces, guard allocation
before dependent inquiries, and do not dereference null or undefined pointers. A
component value is not an ABI layout or a byte encoding. Defined assignment can
legitimately change the destination value; S10.2.1.3-025 is not interchangeable with the
no-matching-binding case. The p2 value-set definition remains fully accounted without a
no-op execution.

Pointer observations require defined association and a live target or
procedure with the correct interface. The strided array target is nonempty
and has no vector subscript. Procedure identity is checked by ASSOCIATED,
not inferred from equal return values. Explicit NULLIFY establishes the
later disassociated states.

parameter, bounds or data access. The nonempty component bounds `-2:0` are

allocation, size and length, **not** stored empty-array bounds. The real
