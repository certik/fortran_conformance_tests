## Explicit statement versus implicit asynchronous-I/O attribute

12.6.2.5p4 supplies the actual implicit rule. For an asynchronous transfer,
the base object of a variable used as an I/O-list item, a namelist group
object or a SIZE= variable implicitly gets ASYNCHRONOUS **in the scoping
unit of that transfer statement**. An explicit declaration may confirm
that attribute. The namelist group name is not the buffer object, and
ID/IOSTAT/IOMSG variables are not included merely because they appear
in the control list.

The bounded confirmation plan has one explicit ASYNCHRONOUS statement
on a defined ordinary output buffer, an external file validly opened
with `ASYNCHRONOUS='YES'`, a constant-YES data transfer and its wait.
That one explicit statement confirms the same-scope implicit attribute;
it is not the two-explicit-specification situation governed by C815.
Conversely, removing the explicit statement while retaining the implicit
route does not produce a missing-attribute negative.

OPEN's specifier allows asynchronous I/O on the connection; the transfer
specifier chooses the operation. A YES transfer requires an external
file-unit-number and the correctly opened connection, not an internal or
merely preconnected file. The transfer specifier's value is a constant
expression under R1213/C1225, not an arbitrary runtime character variable.
The NML and SIZE routes have their own restrictions: SIZE is not a WRITE,
list-directed-input or namelist-input specifier, and NML cannot be combined
with an explicit format or item list. These conditions cannot be skipped
to manufacture a control for the implicit attribute.
For asynchronous input, SIZE's variable becomes undefined on initiation
and receives its character count at the corresponding wait operation,
not merely when the declaration or initiating statement is accepted.

If the plan is later executed, it must check connection, initiation and
completion errors, keep ID/IOSTAT/IOMSG storage separate from transfer
storage, and perform the appropriate wait before using input or changing
output buffers. The processor may complete a requested asynchronous
transfer synchronously, and an ID value of zero is permitted. Pending
data-transfer semantics and actual overlap are different concepts.
There is no mandatory nonzero request ID, concurrency, latency or
optimization result.

The original 8.5.4p2 pending-affector obligation has both scope-use and
executed-while-pending conditions. Attribute presence alone does not
establish a pending operation. The corresponding asynchronous communication
protocol is processor-qualified under 18.10.4; a Fortran stub or MPI-looking
name does not create an independently established external protocol, and
Fortran I/O WAIT is not a substitute for its completion procedure.

## Scope and entity identity

USE/HOST association can permit a local ASYNCHRONOUS specification for
the same accessible object under 14.2.2 and 19.5.1.4, with multiple-path
and other declaration rules retained. A type declaration can instead
introduce a new object and cannot be used as a same-entity repair.

An ASYNCHRONOUS statement alone is one of the BLOCK declaration
exceptions in 11.1.4/19.4: it can give a nonlocal object the attribute
within that BLOCK without declaring a new construct entity or changing
the outside specification. An ALLOCATABLE statement is not that exception.
USE inside BLOCK, separate declarations and IMPORT visibility must be
resolved by their actual scope rules.

Do not copy VOLATILE's distinct coarray specification restrictions into
ASYNCHRONOUS. Association permission also does not waive actual/dummy
typing, explicit interfaces, VALUE, coindexed-object, contiguity or pending
storage restrictions. ASYNCHRONOUS dummies require a complete explicit
interface where 15.4.2.2 says so; C1546/C1548/C1549 and their exact
conjunctions keep their own owners.

No portable attribute inquiry, unchanged printed value, no-op executable
or optimization trap is supplied by this statement. Source/interface
relations for 8.5.4-001/-002/-003 remain pending until an admissible finite
evidence mechanism is implemented and independently reviewed.

### R834: An ASYNCHRONOUS statement has an optional double colon and a nonempty object-name list

**Source:** 8.6.3 R834, J3/24-007, 18 December 2023, physical PDF135. **Class:** Syntax.

**Definition:** The ASYNCHRONOUS keyword is followed by an optional double colon and a nonempty
comma-separated list of object names. It specifies the ASYNCHRONOUS attribute for those
objects through 8.5.4, not an executable asynchronous operation. The statement supplies
no array/coarray specification or type/parameter selector; those properties follow their
own explicit or implicit rules. Scope identity and canonical eligibility are not waived.

**Diagnostic obligation:** required.

**Facets:** `double-colon-form`, `no-double-colon-form`, `multiple-distinct-object-names`, `missing-list-exclusion`, `list-separator-repair`, `whole-name-not-declarator-or-designator`, `implicit-io-confirmation-source-relation`, `use-host-block-source-identity`, `attribute-not-operation-source-gate`.

**Oracle:** Compile/positive-controls and narrowly source-isolated grammar/reporting contrasts with
minimal conforming repairs. The implicit-I/O and scope relationships need separately
reviewed finite source/interface mechanisms; they are not implemented by this catalogue.
Required reporting for a numbered syntax violation does not prescribe fatal rejection, a
printed R834 or English wording.

**Oracle limitation:** Do not use two explicit specifications in one scope as a valid control; do not treat one
explicit confirmation of the same-scope implicit I/O attribute as such a duplicate.
ASYNCHRONOUS= in OPEN and a constant-YES data transfer have different roles.
ID/IOSTAT/IOMSG are not added to the implicit attribute/pending-storage set merely
because they are control variables. The processor may perform requested asynchronous I/O
synchronously, and an unavailable feature, crash, resource error or unrelated diagnostic
earns no grammar or execution credit.

**Dependencies:** 4.1.1-.3/R401;4.2p2;5.3.2;8.2R802/R804/C810;8.5.1C815;8.5.4p1-p4;11.1.4p2;12.5.6.5;12.6.2.1R1213/C1225-C1227;12.6.2.5p1-p6;12.6.2.9;12.6.4.1p3-p7;12.7.1/.2;14.2.2;15.4.2.2;15.5.2.5C1546/C1548/C1549;18.10.4;19.4p3;19.5.1.4.
