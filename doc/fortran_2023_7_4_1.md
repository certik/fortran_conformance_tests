### R704: Intrinsic type specifications have six syntactic alternatives

**Source:** 7.4.1 R704; J3/24-007, 18 December 2023, PDF 80, printed 66, lines 7-12. **Class:** Syntax.

**Definition:** An intrinsic-type-spec admits integer-type-spec, REAL with an optional kind selector,
DOUBLE PRECISION, COMPLEX with an optional kind selector, CHARACTER with an optional
character selector, or LOGICAL with an optional kind selector. DOUBLE PRECISION is a
real specification, not a sixth intrinsic type or a form with an extra kind selector.
The integer alternative expands through R705; character selectors retain their distinct
grammar.

**Diagnostic obligation:** required.

**Facets:** `integer-alternative`, `real-default`, `real-selector`, `double-precision`, `complex-default`, `complex-selector`, `character-default`, `character-selector`, `logical-default`, `logical-selector`.

**Oracle:** Six independently executed declaration controls cover all alternatives and the four
locally displayed selector omissions/presences. Use KIND of standard default or
double-precision literals, never assumed byte-valued kind codes. Each initialized object
has an explicit value assertion.

**Oracle limitation:** These are admission controls, not full numeric, character or logical effects. Malformed
descendant syntax stays with R705/R706 or the canonical character grammar rather than
gaining a second rejection ID at this union. No DOUBLE COMPLEX extension, derived type,
BOZ or arbitrary invalid twin is added.

**Dependencies:** 7.3.2.1/R703 and 8.2/R801 supply declaration contexts. 7.4.3.1/R705, 7.4.3.2 p4-p5 (PDF
82), 7.4.3.3 p2-p3 (PDF 83), 7.4.4.2/R721-R723 (PDF 84-85), and 7.4.5 (PDF 87) retain
their specific defaults and selectors. 4.1.2 p2 and 4.2 p2(3), PDF 45-46, supply the
numbered reporting basis.

### R705: INTEGER admits an optional kind selector

**Source:** 7.4.1 R705, PDF 80, printed 66, line 13; canonical keyword restatement in 7.4.3.1 p3, line 34. **Class:** Syntax.

**Definition:** An integer-type-spec uses INTEGER and may include one kind-selector. The selector is not
a storage-size notation. Its internal syntax and value restrictions are R706 and C717;
omission denotes the default integer method under 7.4.3.1 p4.

**Diagnostic obligation:** required.

**Facets:** `without-selector`, `with-selector`.

**Oracle:** Declare one default integer and one integer explicitly selected with KIND(0). Pass both
initialized values to an explicit default-integer dummy and check their distinct values.

**Oracle limitation:** This is a finite syntax/type admission control. Default-kind and minimum-range effects
have primary ownership S7.4.3.1-004. A guessed misspelling or malformed selector is not
manufactured as another invalid case for this optional wrapper.

**Dependencies:** R704/R706/C717; 7.4.3.1 p3-p4, PDF 80; 15.5.2.5 supplies the exact intrinsic dummy
type/kind premises. Existing R702/R703 and 7.3 catalogues retain their cases and
ownership.

### R706: A kind selector encloses a scalar integer constant expression

**Source:** 7.4.1 R706, PDF 80, printed 66, line 14. **Class:** Syntax.

**Definition:** A kind-selector is parenthesized and contains a scalar integer constant expression,
optionally preceded by KIND=. The expression need not be a literal, a bare name, or
itself default integer. The value still has to meet C717. The scalar, integer and
constant expression restrictions propagate from their canonical definitions; the
selected type parameter's own default-integer kind is a different question.

**Diagnostic obligation:** required.

**Facets:** `positional-expression`, `keyword-expression`, `integer-expression-kind`, `missing-value`, `wrong-keyword`, `expression-category-diagnostics`.

**Oracle:** An unconditional runtime control uses positional and keyword forms with default-integer
arithmetic constant expressions and supported KIND inquiries. A separate expression-kind
control stores KIND(0) in an integer parameter selected with SELECTED_INT_KIND(18), but
only after the existing integer-division profile bounds that identifier to ten decimal
digits. This conservative bound guarantees the initialization conversion is
representable in the mandatory range-18 method without ordering arbitrary kind
identifiers or assuming that method is wider than default. Two compile-only pairs
respectively supply a missing expression and repair a misspelled KIND keyword by one
substitution. The misspelling is also declared as a valid supported integer constant in
both sources, preventing an undeclared-symbol fallback from masquerading as a keyword
report.

**Oracle limitation:** The selected expression kind can equal the default kind; no distinct-kind premise is
invented. A larger default kind identifier makes only the separately qualified
expression-kind witness unavailable, not the unconditional positional/keyword controls
or mandatory integer support. Grammar reports must match the exact declaration and a
case-specific expression or delimiter cause. Shared kind-selector nouns,
implementation-facility failures and unrelated magnitude reports cannot pass. The
qualified message alternatives describe observed diagnostic routes, not
standard-prescribed wording. Required reporting is not mandatory fatal rejection;
diagnose is used. Repairs are positive compile controls, not range or parameter-kind
effects.

**Dependencies:** 4.1.3/R403/C401 (PDF 45), 10.1.9.1/R1027/C1009 (PDF 183), 10.1.12/R1032/C1014 and the
constant-expression definition (PDF 187-188), C717, and 16.9.118/16.9.181 (PDF 424,
454-455). 8.5.13 p1 and 10.2.1.3 p8/Table10.9 require the initialization conversion to
be representable. 7.4.3.1 p2 supplies mandatory integer capacity independently of the
identifier-size profile; missing support is a failure, not an optional property.

### C717: A kind-selector value is nonnegative and supported for its type

**Source:** 7.4.1 C717 (R706), PDF 80, printed 66, lines 15-16. **Class:** Restriction.

**Definition:** The scalar integer constant expression in a kind-selector has a nonnegative value and
identifies a representation method available for the intrinsic type being specified.
Numeric kind identifiers are processor- and type-specific. A real kind is also available
for complex components as specified by 7.4.3.3. This R706 constraint does not replace
the distinct character-selector constraint.

**Diagnostic obligation:** required.

**Facets:** `supported-integer`, `supported-real`, `supported-complex`, `supported-logical`, `negative-integer`, `negative-real`, `negative-complex`, `negative-logical`, `absent-zero-integer`, `absent-zero-real`, `absent-zero-complex`, `absent-zero-logical`.

**Oracle:** Eight compile-only pairs cover integer, real, complex and logical independently. Four
unprofiled negatives change a supported inquiry-selected value to -1. Four further
negatives use nonnegative zero only after an independent ISO_FORTRAN_ENV kind-inventory
profile establishes its absence for that type; complex uses the real inventory. Every
repair replaces only the selector value with a supported KIND inquiry. The profiles
never compile the invalid declaration.

**Oracle limitation:** A negative selector is one defective value, though it necessarily also fails support;
the absent-zero cases separate support from sign. Zero is not universally unsupported.
On a processor supporting zero these optional witnesses are unavailable, not passes or
waivers of C717; the unprofiled supported/negative witnesses remain. Diagnostic
predicates bind the exact declaration, actual type, selector value and support cause. A
constant-expression complaint cannot corroborate these scalar integer constant
expressions, even if it mentions kind parameters. Unsupported-kind value reports remain
intended evidence, while unsupported selector syntax, unrelated implementation failures,
crashes, resource failures and summaries cannot corroborate. The qualified alternatives
are observed diagnostic routes, not standard-prescribed wording. No storage width or
universal kind-code mapping is asserted.

**Dependencies:** R704-R706; 7.4.3.3 p2, PDF 83; 16.10.2.15 INTEGER_KINDS (PDF 474), 16.10.2.20
LOGICAL_KINDS (PDF 475), 16.10.2.26 REAL_KINDS (PDF 476), and 16.9.118 (PDF 424). 4.2
p2(3)-(4), PDF 46, supplies detection/reporting capability, not a prescribed message,
severity or fatal exit. Character C724 remains outside this work unit.

### S7.4.1-001: An intrinsic KIND parameter itself has default integer type and kind

**Source:** 7.4.1 p2, PDF 80, printed 66, lines 5-6. **Class:** Effect.

**Definition:** Each intrinsic type has a kind parameter named KIND. The parameter itself is a
default-kind integer value. Its value may designate a nondefault method of its object;
that does not change the type or kind of the parameter inquiry. A KIND intrinsic result
alone is not evidence that the parameter named KIND is implemented.

**Diagnostic obligation:** not-required.

**Facets:** `integer-parameter`, `real-parameter`, `complex-parameter`, `character-parameter`, `logical-parameter`.

**Oracle:** Five independent programs inquire value%KIND, check KIND(value%KIND) against KIND(0),
and pass the inquiry to an explicit default-integer dummy that checks its value against
an independent KIND inquiry. Real and complex objects use the guaranteed
double-precision real method; no optional kind code is presumed.

**Oracle limitation:** The explicit dummy tests integer type as well as kind, which assignment conversion or
equality of numeric kind identifiers alone would not establish. These are finite
parameter-kind effects, not proof of every representation or all inquiry contexts. The
earlier S7.2-002 programs remain unchanged and retain their general parameter-name/type
ownership; this refinement is separately credited only to 7.4.1. Unsupported
parameter-inquiry implementations are failed or source-only observations, not passing
controls.

**Dependencies:** 7.2 p2-p3, PDF 76, supplies the general parameter concepts. 9.4.5/R916/C923, PDF 153,
supplies the parameter-name inquiry on initialized nonpointer/nonallocatable objects.
16.9.118, PDF 424, supplies the comparison inquiry. 15.5.2.5 supplies the explicit
dummy's intrinsic type/kind agreement.
