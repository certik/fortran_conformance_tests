### S7.5.4.7-001: Nonextended component order follows component declarations

**Source:** 7.5.4.7, p2.nonextended-declaration-order; J3/24-007, 18 December 2023, PDF 98. **Class:** Effect.

**Definition:** The component order of a nonextended type follows the order in which its components are
declared in the type definition. This is the source-defined ordering used by the named
consumers, not a numerical ordering, parameter order, address order or portable
physical-layout claim.

**Diagnostic obligation:** not-required.

**Facets:** `positional-constructor-order`, `same-statement-declaration-list`, `formatted-output-order`, `formatted-input-order`, `consumer-use-graph`.

**Oracle:** Use exact small integers and explicit-format internal records to avoid
processor-dependent list-directed whitespace, binary I/O layout and real rounding.

**Oracle limitation:** A constructor keyword changes association under7.5.10 rather than changing component
order. Unformatted aggregate representation is not generally an ordered list of
component values.

**Dependencies:** 7.5.4.7 p1/p2;R401 list convention;7.5.10 p2, PDF107;12.6.3 p8-p10, PDF263-264.

### S7.5.4.7-002: Extended component order preserves the inherited prefix and excludes parent components

**Source:** 7.5.4.7, p1.parent-components-excluded, p2.extended-parent-order-prefix, p2.extended-local-declaration-suffix; J3/24-007, 18 December 2023, PDF 98. **Class:** Effect.

**Definition:** An extended type uses its parent type component order first, then its additional
components in their declaration order. Parent components themselves do not participate
in this ordering; inherited nonparent components do. The definition applies recursively
and does not duplicate inherited data by adding a parent component as an extra
positional value.

**Diagnostic obligation:** not-required.

**Facets:** `inherited-prefix-constructor`, `multi-generation-order`, `no-new-components`, `parent-keyword-control`, `formatted-inherited-order`, `inheritance-and-consumer-use-graph`.

**Oracle:** A finite flat payload makes duplication, omission and prefix/suffix errors observable
without assuming an object layout. All consumer preconditions must be true for the
actual extended object.

**Oracle limitation:** Nonparent component order and the accessible named parent component are different
relations. Parent/ancestor constructor values require keywords, and constructor
constraints prevent double specification of inherited data.

**Dependencies:** 7.5.4.7 p1/p2;7.5.7.2 p1/p2, PDF104;7.5.10 C7102/C7103/p2/note2, PDF107-108;12.6.3 p8,
PDF263-264.
