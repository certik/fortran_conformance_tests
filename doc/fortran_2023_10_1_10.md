### S10.1.10-001: Elemental operations are intrinsic operations or elemental-function defined operations

**Source:** 10.1.10 p1; J3/24-007 PDF p185. **Class:** Effect.

**Definition:** An elemental operation is either an intrinsic operation or a defined operation whose
defining function is elemental. Intrinsic-operation classification and defined-operation
resolution remain with their own subclauses; this subclause classifies the operations to
which later elemental-operation conformability and evaluation rules apply. It does not
by itself prohibit non-elemental defined operations.

**Diagnostic obligation:** not-required.

**Facets:** `intrinsic-operation-is-elemental`, `defined-operation-elemental-function`.

**Oracle:** Future evidence for this requirement is classification/source-control evidence only: one
admitted intrinsic operation and one admitted defined operation whose defining function
is elemental. A non-ELEMENTAL defined operation is not a rejection oracle for 10.1.10
p1; any future rejection case belongs under the defined-operation, generic-resolution,
procedure-reference, or dummy-argument rule that actually makes the program invalid,
with 10.1.10 p1 cited only as a dependency.

### S10.1.10-002: Elemental binary operations require conformable operands and scalar-array expansion

**Source:** 10.1.10 p2; J3/24-007 PDF p185. **Class:** Restriction.

**Definition:** For every elemental binary operation, the operands shall be conformable. If one operand
is scalar and the other is an array, the scalar is treated as an array of the same shape
as the array operand, with every element, if any, equal to the scalar value.

**Diagnostic obligation:** context-dependent.

**Facets:** `conformable-binary-operands`, `scalar-left-expanded-to-array-shape`, `scalar-right-expanded-to-array-shape`, `empty-array-scalar-expansion`, `nonconformable-array-operands-boundary`.
