## Diagnostic policy and dependencies

The classification is not based on the presence of a prose *shall*.

* R611 and C603 are covered by the numbered-rule/constraint diagnostic
  capability in 4.2 p2(3); 4.1.2 p2 makes C603 apply at each use of R611.
* The empty-statement and placement exclusions in -001 and -005 concern
  source form under 4.2 p2(5). Read them with commentary/termination in
  6.3.2.3/5, the statement convention in 4.1.4 p1, and fixed-form placement
  in 6.3.3.5 p1.
* Duplicate labels in -002 are also covered by 19.1 p2 and 19.3.1 p1/p3,
  hence 4.2 p2(6). A BLOCK is a scoping unit, but it does **not** separate
  labels into different inclusive scopes (3.83 and 3.120). An internal or
  external subprogram does provide a separate nonblock scope.
* -003, -004, and -006 through -008 assert conforming behavior. They do not
  prescribe rejection, a trap, or any particular result for an invalid
  branch, data transfer, or DO construct.

In all cases, a required **detection/reporting capability** is distinct from
a mandatory error severity or unsuccessful compiler exit. The existing
runner's default negative-case contract is strict rejection. A failure saying
“not rejected” must therefore be read alongside the diagnostic: a warning
about an extension is not the same observation as silent acceptance.
The fixed-semicolon fixture specifically accepts the reference diagnostic
code `misc-source-extensions`, which reports that label placement is outside
the label field. This satisfies the required reporting capability without
inventing an error-severity obligation. No compiler code or generic
warning policy is changed by the fixtures.

The label-use premises were checked against 11.2.1/2 (branch classes and
inclusive scope), 12.6.2.2/C1232 (FORMAT reference scope),
13.2.1/C1301 (FORMAT labels), and 11.1.7.2/C1135-C1137 (DO terminals).
Labeled declarations in the controls are intentionally **not** branch targets.
The label-DO controls end with CONTINUE or END DO, not deleted nonblock or
shared-terminal forms.

## Case construction and limits

* Grammar negatives separate the first out-of-range value `100000` from
  a six-digit spelling such as `000001`. Padded overlength references still
  have an otherwise valid target in the same scope. Nondigit operands are isolated in GO TO
  statements whose repaired target exists.
* Each case in a shared invalid container satisfies every shared `covers`
  facet. Definition length, padded definition length, padded references,
  and nondigit references are not conflated into one container-wide claim.
* All-zero C603 definitions have lengths one through five. They label
  otherwise valid, unused CONTINUE statements. Zero references are not
  negative fixtures: no conforming target could be supplied, so an
  undefined-label diagnostic would not isolate C603. Padded nonzero
  references are positive controls instead.
* Duplicate-label negatives use unused CONTINUE statements. Their repaired
  controls change just the second label, including within BLOCK constructs.
* Label-only and comment-only lines have out-of-band metadata in
  `tests/fixtures/labels_*`. No inline error marker supplies accidental
  statement content. Fixed-form fixtures likewise preserve label columns
  and exactly 72 characters per line; their padding is commentary, not
  executable text.
* The range test uses fourteen labels including both decimal-width
  boundaries and values above signed/unsigned 16-bit limits. Label values
  are not stored in default-integer variables. It does not demand
  simultaneous storage of all 99999 possible labels.
* Valid restriction/syntax controls are labeled `positive-control`;
  semantic effect cases make explicit self-checks. Failures use ERROR STOP
  only to signal a violated test assertion, not as a prescribed outcome for
  a nonconforming program.

### R611: Label tokens contain one through five decimal digits

**Source:** 6.2.5 R611; J3/24-007 PDF p70 (printed p56). **Class:** Syntax.

**Definition:** A label token has one to five digits, inclusive. Its grammar admits neither a sign nor
the decimal point, exponent, or kind suffix of a numeric literal. The length limit
applies to the spelling, including leading zeros, and to references as well as
definitions. C603 separately excludes spellings containing only zeros.

**Diagnostic obligation:** required.

**Facets:** `one-to-five-digits`, `all-decimal-digits`, `six-digit-definition`, `zero-padded-overlength-definition`, `zero-padded-overlength-reference`, `nondigit-reference`.

**Oracle:** Execute a control with every permitted digit and each permitted length. Isolate
six-digit definitions, including 000001 whose value would otherwise be valid. Overlength
references to existing labels use six-digit zero-padded spellings in GO TO, FMT=, and
label-DO contexts. Nondigit GO TO operands have an existing label 10 as their repaired
target. Separate repaired programs compile and check their results.

**Oracle limitation:** An absent GO TO operand would primarily test the enclosing statement syntax, and an
out-of-range reference with no possible conforming target could also fail scope
resolution; neither is used as the lexical oracle. Required means a detection/reporting
capability under 4.2 p2(3), not a universal requirement to reject extensions. Negative
fixtures use the suite's strict rejection contract.

**Dependencies:** 6.1.3 (digits); 4.1.2 p2 and 4.2 p2(3); 6.2.5 C603; R1159, R1215/C1232, R1121/C1137 for
the otherwise legal reference contexts.

### C603: A label has a nonzero digit

**Source:** 6.2.5 C603 (R611); J3/24-007 PDF p70. **Class:** Restriction.

**Definition:** Every occurrence of a label includes at least one nonzero digit. Zeros are allowed
elsewhere, including before the nonzero digit. This associated constraint applies
wherever R611 is used, not just to a statement's defining label.

**Diagnostic obligation:** required.

**Facets:** `nonzero-at-each-position`, `all-zero-definition`, `nonzero-branch-reference`, `nonzero-format-reference`, `nonzero-do-reference`.

**Oracle:** Test a single nonzero digit in each of the five positions of a five-digit label.
Independently reject all-zero definitions of lengths one through five on unused CONTINUE
statements. Minimal controls replace the final zero with one in separate scopes.
Conforming branch, FORMAT, and DO references exercise padded nonzero label operands and
check their effects.

**Oracle limitation:** All-zero references cannot name a conforming definition; their rejection could instead
be caused by a missing target. These are deliberately not used as isolated C603
negatives. The reference-position facets are positive controls, not evidence that a zero
operand is diagnosed. Detection/reporting, rather than mandatory error severity, follows
from 4.2.

**Dependencies:** 4.1.2 p2 (associated constraints apply at every use of the syntax term); 4.2 p2(3);
R611; C1232 and C1137.

### S6.2.5-001: A label belongs to a nonblank statement

**Source:** 6.2.5 p2, first sentence; J3/24-007 PDF p70. **Class:** Restriction.

**Definition:** When a statement is labeled, the statement itself contains a nonblank character. A label
does not supply the missing statement, and trailing commentary does not turn an empty
statement into a nonblank one.

**Diagnostic obligation:** required.

**Facets:** `nonblank-executable`, `nonblank-nonexecutable`, `blank-statement`, `comment-only-statement`.

**Oracle:** Use conforming labeled executable and declaration statements as positive controls.
Out-of-band manifests isolate an unused label followed by a newline, and an unused label
followed only by commentary. Their minimally repaired controls insert CONTINUE; no
unresolved branch reference is introduced.

**Oracle limitation:** The diagnostic classification is based on disallowed source form in Clause 6 and 4.2
p2(5), not merely the word 'shall'. The standard requires detection/reporting
capability, not error severity or rejection. Warning-only extension handling must be
distinguished from silent acceptance in observations; the runner's reject verdict alone
is not proof of nonconformance.

**Dependencies:** 4.1.2 p3; 4.2 p2(5); 6.3.1; 6.3.2.3 (comments do not affect interpretation); 6.3.2.5
(termination).

### S6.2.5-002: Labels identify distinct statements within their scope

**Source:** 6.2.5 p2, second sentence, interpreted with 19.1 p2 and 19.3.1 p1/p3. **Class:** Restriction.

**Definition:** Two statements in one label scope cannot have the same label. Statement labels are local
identifiers of class (1), with inclusive scope: nested BLOCK scoping units do not create
independent label namespaces. Separate nonblock scopes can reuse a label. The
leading-zero equivalence in S6.2.5-003 also applies to this uniqueness restriction.

**Diagnostic obligation:** required.

**Facets:** `distinct-labels`, `independent-scopes`, `duplicate-spelling`, `duplicate-leading-zeros`, `enclosing-block-scope`, `sibling-block-scopes`.

**Oracle:** Conforming controls use distinct labels within an inclusive scope and reuse one spelling
in a main program, its internal subprogram, and an external subprogram. Isolate repeated
labels, zero-prefixed duplicates, a duplicate between a host and its BLOCK, and a
duplicate in sibling BLOCK constructs. All offending labels are on unused CONTINUE
statements: no branch legality or target lookup can mask the uniqueness test.

**Oracle limitation:** Required diagnostics follow from the explicit Clause 19 scope rules and 4.2 p2(6), not
from treating every prose restriction as a numbered constraint. The suite tests
rejection; a diagnosed extension remains distinguishable from an undiagnosed violation.

**Dependencies:** 3.83 (inclusive scope); 3.120 (scoping unit); 19.1 p2; 19.3.1 p1(1)/p3; 4.2 p2(6); 6.2.5
p2 leading-zero equivalence.

### S6.2.5-003: Zero prefixes do not change label identity

**Source:** 6.2.5 p2, third sentence. **Class:** Effect.

**Definition:** Within the permitted one-to-five-digit spelling, inserting or removing leading zeros
does not change which statement a label identifies. The resulting identity is decimal,
not an octal-literal interpretation. Nonleading digits remain significant.

**Diagnostic obligation:** not-required.

**Facets:** `padded-definition`, `padded-reference`, `decimal-identity`.

**Oracle:** Branch with an unpadded reference to a padded definition and vice versa. Distinct labels
8, 10, and 100 have different effects; using 010 must select 10 rather than 8 or 100.
All paths end in explicit checks or ERROR STOP, without relying on source order to
conceal a wrong target.

**Dependencies:** R611 and C603 bound the permitted spellings; 11.2 supplies legal branch contexts.
Duplicate equivalent definitions are tested under S6.2.5-002, not used as an additional
effect oracle.

### S6.2.5-004: Every individual label value is available

**Source:** 6.2.5 p2, fourth and fifth sentences. **Class:** Effect.

**Definition:** There are 99999 distinct permissible labels, corresponding to values 1 through 99999,
and a processor accepts any one of them as a label. This is independent of a permitted
limit on how many distinct labels occur in a single program unit.

**Diagnostic obligation:** not-required.

**Facets:** `range-endpoints`, `decimal-width-boundaries`, `beyond-signed-16-bit`, `beyond-unsigned-16-bit`.

**Oracle:** Execute a small chain using 1, 99999, both sides of every decimal-width transition, and
32767/32768 and 65535/65536. Each branch skips an ERROR STOP, so mere fallthrough cannot
pass. These large values occur as labels, never as default-integer literal expressions.
Assert the exact number of visited targets.

**Oracle limitation:** This finite boundary sample does not claim exhaustive execution of all 99999 values. It
uses fourteen labels, not a stress test demanding all possible labels simultaneously. A
documented processor complexity limit must be reviewed separately.

**Dependencies:** R611; C603; 4.2 p2(1), including implementation size/complexity limits.

### S6.2.5-005: Complete statements may be labeled subject to source-form exceptions

**Source:** 6.2.5 p3, introductory sentence, including its two exceptions. **Class:** Syntax.

**Definition:** A statement can start with a label unless it is part of another statement or follows a
semicolon on the same line in fixed form. The latter exception does not prohibit labels
after a semicolon in free form. Eligible nonexecutable statements and program boundary
statements may also have unused labels; being labeled does not make a statement a branch
target or a FORMAT or DO terminal statement. Label references are limited to the three
uses in S6.2.5-006 through -008.

**Diagnostic obligation:** required.

**Facets:** `executable-statement`, `nonexecutable-statement`, `program-boundaries`, `free-semicolon`, `fixed-initial-statement`, `fixed-semicolon-exclusion`, `embedded-statement-exclusion`.

**Oracle:** Run controls with unused declaration and PROGRAM/END PROGRAM labels, executable labels,
a free-form label after a semicolon, and an ordinary single-line IF whose action is not
independently labeled. Diagnose a label inserted before that embedded action. A
byte-preserved fixed-form pair keeps every line at 72 characters: a first statement
labeled in columns 1-5 is valid; a second statement labeled after a semicolon is not.
The fixed-form negative is repaired by deleting only the second label.

**Oracle limitation:** The exclusions are source-form restrictions, diagnosed under 4.2 p2(5), corroborated by
4.1.4 p1 and 6.3.3.5 p1. They are not tests of branching to declarations or entering
constructs. Required detection/reporting does not require every processor to reject an
extension with an error. The isolated fixed-semicolon manifest explicitly allows the
reference diagnostic code misc-source-extensions on its source, since that portability
diagnostic reports the forbidden label placement. This is not a blanket allowance for
arbitrary warnings or a change to the LFortran diagnostic contract.

**Dependencies:** 4.1.4 p1; 4.2 p2(5); 6.3.2.2 and 6.3.2.5/6; 6.3.3.1/4/5. Other labeled constructs are
legal only subject to their own statement and scope rules.

### S6.2.5-006: A branch label selects its permitted destination

**Source:** 6.2.5 p3, first bullet, with 11.2. **Class:** Effect.

**Definition:** A label on a branch target statement identifies a possible destination of a branch. This
applies only to the statement classes and control-flow contexts allowed by 11.2 and the
construct rules; a branch remains within the same inclusive scope. Merely attaching a
label to another statement does not make that statement a legal destination.

**Diagnostic obligation:** not-required.

**Facets:** `forward-branch`, `backward-branch`.

**Oracle:** A forward branch skips ERROR STOP and reaches a labeled assignment. A bounded backward
branch to a labeled assignment changes a counter exactly three times. Every target is an
action statement in the same scope, outside any construct-entry ambiguity.

**Oracle limitation:** These are assertions about conforming execution, not a demand to diagnose every
forbidden branch or trap it at runtime.

**Dependencies:** 11.2.1 and 11.2.2; 3.83; 19.1 and 19.3.1.

### S6.2.5-007: A FORMAT label selects a data-transfer format

**Source:** 6.2.5 p3, second bullet, with 12.6 and 13.2.1. **Class:** Effect.

**Definition:** A FORMAT statement's label identifies that statement as a format specification for data
transfer. A label-valued FMT= specifier refers to a FORMAT statement in the same
inclusive scope; neither an arbitrary labeled executable statement nor a label in
another scope satisfies this premise.

**Diagnostic obligation:** not-required.

**Facets:** `output-format`, `input-format`, `distinct-formats`.

**Oracle:** Use two labeled FORMAT statements for internal output and compare complete character
records with distinct exact strings. Read an internal record with a labeled integer
format and check the resulting integer. No external device behavior or list-directed
spacing is part of the oracle.

**Dependencies:** 12.6.2.2 R1215/C1232; 13.2.1 R1301/C1301. Their independent diagnostic obligations are
not reauthored here.

### S6.2.5-008: A label can identify a DO construct's terminal statement

**Source:** 6.2.5 p3, third bullet, with 11.1.7. **Class:** Effect.

**Definition:** For the forms of DO that specify a terminal label, that label identifies the matching
terminal statement. This is not a requirement that every DO be labeled, and it does not
license the deleted nonblock or shared-termination DO forms.

**Diagnostic obligation:** not-required.

**Facets:** `continue-terminal`, `end-do-terminal`.

**Oracle:** Run independent integer-counted loops ending at labeled CONTINUE and labeled END DO
statements. Check the exact accumulated sum and final loop-variable value. Do not branch
into a loop, share a terminal statement, or use an arbitrary action statement as the
terminal.

**Oracle limitation:** Label-DO is obsolescent but remains permitted. An obsolescence diagnostic does not make
the conforming execution invalid. Rejection of a malformed terminal is not inferred from
this effect requirement.

**Dependencies:** 11.1.7.2 R1121, R1133, R1134, C1135-C1137; 11.1.7.4 execution rules.

## Validation and integration

The catalogue is registered in `doc/catalogues/index.json`. Its original
worktree handoff did not approve fixtures or update the shared baseline.
Those actions were serialized after independent source/oracle review.

```sh
python3 -B tests/suite_data.py --render
python3 -B tests/run_tests.py --audit
python3 -B -m unittest discover -s tests -p 'test_*.py'
python3 -B tests/run_tests.py --reference-only \
  --reference gfortran --reference flang --timeout 20 \
  -t R611 -t C603 -t S6.2.5 --report labels-observations.json
```

Place the runner's scratch storage inside the detached worktree when the
environment disallows system temporary paths. The author observation report
is a separate handoff artifact, not an approval record. Compiler versions,
selected standard modes, strict-runner failures, and diagnosed extensions
must be considered together during independent adjudication.

## Reviewed integration snapshot

GNU Fortran 16.1.0 in F2023 mode corroborates all 47 executions. Flang 22
in its reported F2018 mode corroborates 43: it silently accepts the
six-digit zero-padded definition and three padded references. LFortran
0.65.0-397-g569035a330 passes 35 and has 12 recorded failures.

Independent review found that three original target failures were runner
format mismatches, not missing diagnostics. Manifest compilations now
request LFortran's short diagnostic format; the original source bytes and
anchors are unchanged, and all three rejection/control pairs pass.

Four valid programs now report `do-exit-index` separately from branch,
loop-total, and format assertions. Their conditions were not weakened.
These observations should not be counted automatically as four distinct
label bugs. The other target failures concern silently accepted invalid
label spellings and rejected conforming label placements.
