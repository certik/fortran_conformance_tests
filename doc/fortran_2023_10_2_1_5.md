### S10.2.1.5-001: Defined assignment is interpreted by the subroutine that defines it

**Source:** 10.2.1.5 p1; J3/24-007 PDF p193. **Class:** Effect.

**Definition:** The interpretation of a defined assignment is provided by the subroutine that defines
that assignment. Observable assignment behavior therefore comes from executing the
defining subroutine, subject to the procedure-call and argument rules.

**Diagnostic obligation:** not-required.

**Facets:** `explicit-subroutine-effect`, `type-bound-subroutine-effect`, `intrinsic-assignment-not-used-for-top-level-effect`.

**Oracle:** The plan may observe subroutine-specified state changes, but must not infer operand
evaluation order beyond the procedure-reference dependencies. Defined assignment
interface eligibility is owned by 10.2.1.4 and 15.4.3.4.3.

**Oracle limitation:** This source-only catalogue records pending plans only. It creates no Fortran test
program, invokes no processor, approves no fixture or oracle, and claims no coverage.
Future fixtures must use independently derived literal, inquiry, or source-relation
oracles; must not infer assignment evaluation order, processor temporaries, or function
call counts; and must not rely on compiler agreement, emitted code, undefined values,
resource exhaustion, or a processor-dependent value.

**Dependencies:** 10.2.1.4;15.4.3.4.3;15.5 procedure references;15.5.4 subroutine references.

### S10.2.1.5-002: Elemental defined assignment over an array is performed element by element on corresponding elements

**Source:** 10.2.1.5 p2 first sentence; J3/24-007 PDF p193. **Class:** Effect.

**Definition:** If a defined assignment is elemental and the assignment variable is an array, the
defined assignment is performed element by element on corresponding elements of the
variable and expr.

**Diagnostic obligation:** not-required.

**Facets:** `rank-one-correspondence`, `rank-two-correspondence`, `different-lower-bounds-correspondence`, `noncontiguous-section-correspondence`.

**Oracle:** No fixture may require a particular element execution order, simultaneity, temporary, or

### S10.2.1.5-003: Scalar expr in elemental defined assignment is treated as a same-shape array of scalar values

**Source:** 10.2.1.5 p2 second sentence; J3/24-007 PDF p193. **Class:** Effect.

**Definition:** For an elemental defined assignment with an array variable and scalar expr, expr is
treated as if it were an array of the same shape as the variable with every element
equal to the scalar value of expr.

**Diagnostic obligation:** not-required.

**Facets:** `scalar-to-rank-one-array`, `scalar-to-rank-two-array`, `scalar-expression-snapshot-value`.

**Oracle:** The scalar treatment is an interpretation of eligible elemental defined assignment. It
does not permit a nonconforming elemental assignment that fails 10.2.1.4 rank,
uniqueness, or conformance conditions.

program, invokes no processor, approves no fixture or oracle, and claims no coverage.

call counts; and must not rely on compiler agreement, emitted code, undefined values,
