### S7.5.4.5-001: NOPASS specifies that there is no passed-object dummy argument

**Source:** 7.5.4.5 p2; J3/24-007, 18 December 2023, PDF 96, printed 82, lines 4-5. **Class:** Effect.

**Definition:** NOPASS on a procedure-pointer component or a type-bound procedure means that it has no
passed-object dummy argument. Its ordinary dummy arguments are not removed from the
interface and still require proper argument correspondence. C765 is a restriction on a
passed-object dummy, not a blanket restriction on every argument of a NOPASS procedure.

**Diagnostic obligation:** not-required.

**Facets:** `component-nopass`, `binding-nopass`.

**Oracle:** Separate component and binding runs use NOPASS with an ordinary INTEGER dummy supplied
explicitly. The component is associated before invocation; the binding needs no pointer
association. Typed results and an independently initialized member distinguish absence
of a hidden object from ordinary argument handling.

**Oracle limitation:** NOPASS does not permit a wrong ordinary argument list. Type-bound NOPASS and procedure
component NOPASS have different syntax owners. Unsupported binding/component features
cannot weaken these planned runs to compile-only.

**Dependencies:** R741-R742/C761-C764 (PDF 94); R749/R752/C774/C784/C786 (PDF 100); 10.2.2.4 (PDF 196);
15.5.2.1-.2 (PDF 337-338); 8.5.14 and 19.5.2 (PDF 131, 556-557); 4.2 p2(1) (PDF 46).

### S7.5.4.5-002: The default or unnamed PASS selects the first dummy argument

**Source:** 7.5.4.5 p3; PDF 96, printed 82, lines 6-7. **Class:** Effect.

**Definition:** If neither PASS nor NOPASS is present, or PASS has no argument name, the first dummy of
the procedure-pointer component or type-bound procedure is the passed-object dummy. The
rule selects a role; that dummy still must satisfy C765. A reference supplies the
data-ref as the corresponding actual argument under 15.5.2.2.

**Diagnostic obligation:** not-required.

**Facets:** `component-default`, `component-bare-pass`, `binding-default`, `binding-bare-pass`, `inherited-context-link`.

**Oracle:** Four runs distinguish default and bare PASS in procedure components and bindings. They
use first-position scalar CLASS(record) self, a separate defined INTEGER tag and actual
calls whose observations check each role. The inherited-interface source-use link
remains pending.

**Oracle limitation:** An arbitrary first INTEGER or procedure dummy does not become a valid passed object just
because it is first. Missing dummy/type errors do not establish this effect. Inheritance
retains inaccessible entities without making them accessible; no private-binding
override or private type-identity question is silently resolved.

**Dependencies:** C762/C765 (PDF 94, 96); 7.5.5 and 7.5.7.2-.3 (PDF 100-105); 15.5.2.2/.4/.5 (PDF
338-340); 19.6.5 p1(6) (PDF 563); 4.2 p2(1) (PDF 46).

### S7.5.4.5-003: Named PASS selects the named dummy in the particular binding context

**Source:** 7.5.4.5 p4; PDF 96, printed 82, lines 8-9. **Class:** Effect.

**Definition:** PASS(arg-name) selects the dummy with that name as the passed-object dummy of a
procedure-pointer component or named type-bound procedure. It need not be the first
dummy. Selection is per component or named binding context, not an intrinsic permanent
role of one dummy in the underlying procedure.

**Diagnostic obligation:** not-required.

**Facets:** `component-second-dummy`, `binding-second-dummy`, `shared-procedure-contexts`.

**Oracle:** Component and binding runs select a second-position self and check the separate explicit
tag. A third run binds one module function in two ordinary types using PASS(a) and
PASS(b), supplies the other initialized object explicitly, and checks both typed member
values.

**Oracle limitation:** C763 and C785 retain component/binding name constraints. A missing name, ordinary
argument mismatch or wrong-subject diagnostic cannot stand in for selection behavior. No
invalid twin is invented from an effect.

**Dependencies:** C763 (PDF 94), C765 (PDF 96), C774/C785 (PDF 100); 15.5.2.1-.2 and argument association
(PDF 337-340); 7.3.2-.3 (PDF 77-79); 4.2 p2(1) (PDF 46).

### C765: The selected passed-object dummy has specified category, type, parameter and attribute properties

**Source:** 7.5.4.5 C765; PDF 96, printed 82, lines 10-13. **Class:** Restriction.

**Definition:** The passed-object dummy is a scalar dummy data object, not POINTER or ALLOCATABLE, with
the declared type of the type being defined. All length parameters of that dummy's type
are assumed. It is polymorphic exactly when the defining type is extensible, and it has
no VALUE attribute. These restrictions apply to the selected dummy in a procedure
component or type-bound procedure, not to every ordinary dummy or to length parameters
of nested character components. Inherited interfaces retain their canonical declaration
context.

**Diagnostic obligation:** required.

**Facets:** `dummy-data-object`, `scalar`, `nonpointer`, `nonallocatable`, `same-declared-type`, `all-lengths-assumed`, `extensible-polymorphic`, `nonextensible-nonpolymorphic`, `no-value`, `parameter-scope-boundary`, `other-dummy-attributes`.

**Oracle:** Eighteen compile pairs isolate the selected dummy's data category, rank,
POINTER/ALLOCATABLE, declared type, each of two nonassumed LEN parameters, extensible
polymorphism, nonextensible polymorphism and VALUE. The other-type binding pair has a
separate non-passed CLASS(record) witness in both sources to satisfy C784; self remains
first and selected by default PASS, and only self changes from CLASS(other) to
CLASS(record). Repairs retain complete interfaces and change only the relevant
declaration property; VALUE cases use INTENT(IN). The nonextensible pair completes a
public-component SEQUENCE type, declares seed, then imports seed in a later abstract
interface, changing only CLASSOF to TYPEOF. Four actual admissions exercise both assumed
LEN parameters, a nonpolymorphic SEQUENCE component, OPTIONAL self and TARGET self with
valid states and lifetimes. The reviewed parameter-scope graph remains pending.

**Oracle limitation:** Broad dummy/type/kind/constant/attribute/function words, even at an allowed line, cannot
identify the actual role. Opposite attribute or already-assumed parameter reports must
not count. Required reporting does not demand fatal rejection. Unsupported F2023
TYPEOF/CLASSOF/PDT facilities, crashes, verifier/resource failures and invalid controls
are not the intended cause. The layouts are source-qualified, not fixture-approved. No
private-SEQUENCE identity, numerical kind identifier, VALUE ABI or undefined-state
assertion is introduced.

independent defining-type dummy premise of bindings (PDF 100); R703/C705-C714 and 7.3.3
(PDF 77-79); 7.5.3/7.5.7 and R754-R755/C795-C7100 (PDF 91-92, 104-106); C701/C702 (PDF
