### S7.5.7.1-001: Extensibility excludes BIND, SEQUENCE and the two intrinsic C pointer types

**Source:** 7.5.7.1 p1; J3/24-007, 18 December 2023, physical PDF104, printed90, lines3-4. **Class:** Effect.

**Definition:** A derived type is extensible when it is neither C_PTR nor C_FUNPTR from intrinsic
ISO_C_BINDING and has neither BIND nor SEQUENCE. These are exclusions by actual
type/attribute, not by a guessed layout or the local spelling of an identifier.
Extensible means eligible for extension; it does not mean already extended. C737 and
C705 own the corresponding EXTENDS and CLASS admission restrictions.

### S7.5.7.1-002: EXTENDS identifies the extended type and its immediate parent

**Source:** 7.5.7.1 p2; PDF104, printed90, lines5-6. **Class:** Effect.

**Definition:** A type bearing EXTENDS is an extended type, and its parent is the type named in that
EXTENDS type-attribute specification. A parent is immediate; a more remote ancestor is
reached recursively, not selected arbitrarily from the ancestry chain. The name may be a
local USE rename, but renaming does not change the selected entity.

**Diagnostic obligation:** not-required.

**Facets:** `prior-parent-source-use`, `renamed-parent-source-use`, `immediate-versus-ancestor-source-use`.

**Oracle:** This is a definition/source-use wrapper. The inspected renamed-parent control has an
exact inherited-value observation, but only its original ownership is credited.
Immediate-parent and component-name observations have separately identified future
owners.

**Oracle limitation:** Do not infer the parent-component spelling from a successful inherited-field access. A
type is not its immediate parent merely because extension is reflexive; root types have
no parent.

**Dependencies:** R728/C737 (PDF88); 3.144.5/.7/.10 (PDF40); 14.2.2 (PDF318-320); 7.5.7.1 NOTE1 and p3,

### S7.5.7.1-003: Extension is reflexive and follows the recursive parent relation

**Source:** 7.5.7.1 p3; PDF104, printed90, lines7-8. **Class:** Effect.

**Definition:** An extensible type without EXTENDS is an extension type only of itself. An extended type
is an extension of itself and of every type for which its parent is an extension. Thus a
child's relation to an ancestor is directional and transitively inherited; siblings are
not extensions of one another merely because they share a parent. This relation is not
the same as the unary extensibility property or general assignment/argument
compatibility, and it is not a claim about identical storage.

**Diagnostic obligation:** not-required.

**Facets:** `root-reflexivity`, `extended-reflexivity`, `direct-and-indirect-ancestry`, `reverse-direction`, `sibling-and-unrelated-boundaries`, `dynamic-effective-type`, `kind-and-absent-state-source-use`.

**Oracle:** One shared matrix M evaluates all25 ordered pairs once using five concrete, nonpointer,
nonallocatable extensible objects. Literal expected rows TFFFF/TTFFF/TTTFF/TFFTF/FFFFT
are independent of every inquiry result. Direct calls avoid an incompatible CLASS(root)
helper for unrelated other. The separate dynamic case passes a live grand actual to
CLASS(root), obtains true against a child MOLD, and independently checks that a real
root object gives false against the same MOLD. All payloads and local markers are
defined by named assignments.

**Oracle limitation:** EXTENDS_TYPE_OF requires extensible declared type or unlimited polymorphism, and forbids
undefined association status for polymorphic pointers. Nonextensible declared-type
objects cannot simply be passed to obtain false; unrestricted wrappers can instead
encounter processor-dependent dynamic-type cases. Initial plans use neither pointers nor
unlimited polymorphism. No private-SEQUENCE identity assertion.

**Dependencies:** 3.144.7 (PDF40); C737/C738 (PDF88); 7.3.2.3 p5 and 7.3.3 (PDF79); 16.9.86 including
continuation (PDF409-410); 11.1.11.2 p3 (PDF225); 15.5.2.4/.5 (PDF339-341); 19.6.1/.5
(PDF562-563).

### S7.5.7.1-004: ABSTRACT defines abstractness independently of a mandatory local deferred member

**Source:** 7.5.7.1 p4; PDF104, printed90, line9. **Class:** Effect.

**Definition:** An abstract type is a type with ABSTRACT. The attribute does not require a local
deferred binding, and an extension is not automatically abstract just because its parent
is abstract. C738 supplies the obligation when deferred bindings are contained or
inherited; C739 supplies extensibility. Canonical object/type-specifier constraints, not
the informative example alone, prevent creating ordinary abstract objects.

**Diagnostic obligation:** not-required.

facets. The concrete-child control has an exact tag/payload observation; its existing ID
and role remain intact.

**Oracle limitation:** NOTE2 is informative. Its dynamic-type wording is not promoted into assertions about
unallocated/disassociated polymorphic placeholders, or permission to designate a whole
abstract parent component. Canonical C738/C739 reporting does not mandate fatal
rejection or printed codes.
