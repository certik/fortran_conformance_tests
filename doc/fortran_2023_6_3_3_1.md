### S6.3.3.1-001: Default-kind fixed source lines have exactly 72 characters

**Source:** 6.3.3.1 p1; J3/24-007, 18 December 2023, PDF page 72, printed page 58, lines 33-34. **Class:** Restriction.

**Definition:** A fixed source line containing only default-kind characters has exactly 72 characters,
not merely an upper bound of 72. Otherwise the maximum character count is processor
dependent. This specifies source characters, not a portable file-record encoding,
filename suffix, tab expansion, or command-line convention. The field-placement rules
are defined by the later fixed-source subclauses.

**Diagnostic obligation:** required.

**Facets:** `exact-72`, `content-in-column-72`, `short-source-line-report`, `overlong-source-line-report`, `nondefault-character-limit`.

**Oracle:** The exact-width control has 72 default-kind ASCII characters on every physical record.
Its character literal closes in column 72; all 58 A characters and the final Z are
checked against independent values. Other new fixed_source fixtures use the same
explicit width and manifest form selection. No source-line-length or padding option is
passed.

**Oracle limitation:** The byte witness assumes the ordinary ASCII source interface of the observed processors,
not an ASCII collating value in the Fortran program. Acceptance of a short or long
external record alone does not establish which source line the processor constructed.
Those two diagnostic facets and the nondefault branch remain explicitly pending, not
silently counted as covered by green controls. Compiler size/complexity limits remain
subject to 4.2 p2(1).

**Dependencies:** 6.3.1 p1/p3 (line definition and processor-dependent form selection), 6.1.1 and 7.4.4.2
(character kinds), 7.4.4.3 (literal representation), 6.3.3.3 and 6.3.3.5 (fields), and
4.2 p2(1)/(5), PDF page 46. The preserved fixed_form fixture has CRLF records shorter
than 72 bytes and remains a source-interface calibration, not proof of this exact-width
obligation.

### S6.3.3.1-002: Fixed-form blanks are insignificant outside character context

**Source:** 6.3.3.1 p2; J3/24-007 PDF page 72, printed page 58, line 35. **Class:** Effect.

**Definition:** Blanks outside character context can be inserted or removed without changing the
interpretation of fixed source. This includes positions inside tokens, unlike free form.
Blanks in a character literal or character string edit descriptor remain characters of
that context. Column fields, comment recognition, and statement termination still apply:
insignificant blanks do not move a physical continuation indicator or label to another
field.

**Diagnostic obligation:** not-required.

**Facets:** `keyword-interiors`, `name-interiors`, `constant-interiors`, `operator-interiors`, `format-spacing`, `literal-blanks`, `edit-descriptor-blanks`.

**Oracle:** The tokens control inserts blanks in PROGRAM, IMPLICIT NONE, INTEGER, a variable name,
12, the power operator, and .NE.; its integer result must be 145, not merely equal to a
second implementation of the same expression. A separate FORMAT control checks I2
spelled I followed by blanks and 2 against the exact internal record ' 7'. The two
character contexts preserve 'a  b' using independent single-character positions and a
repeated single blank, with initialized output storage and guarded IOSTAT. The oracle
does not merely compare two literals whose blanks could be identically misparsed.

**Oracle limitation:** These are finite lexical classes, not every Fortran token. Neither a tab nor a Unicode
space substitutes for a blank. Name, label, literal and FORMAT grammar retain their
canonical owners; only fixed-source blank handling is credited here. Physical trailing
padding outside a character context is insignificant, but padding inside a continued
literal is data, tested separately under continuation.

**Dependencies:** 3.21, PDF page 21, defines both character contexts. 6.2.2/R603 and C601, 7.4.3,
R1008/R1014, 7.4.4.3, and 13.2.1 p1/R1301/R1302/C1301 provide the otherwise conforming
tokens and FORMAT. 6.3.3.3/6.3.3.5 retain physical field ownership.
