### S7.5.4.3-001: An individual coarray specification determines a component's corank before CODIMENSION

**Source:** 7.5.4.3 p1; J3/24-007, 18 December 2023, PDF 95, printed 81, lines 2-4. **Class:** Effect.

**Definition:** A component is a coarray if its declarator has a coarray-spec or the statement has a
CODIMENSION clause. An individual coarray-spec determines its corank when present;
otherwise the statement specification determines corank. Components have deferred
coshape and ALLOCATABLE under C751. Array rank and runtime cobounds are separate from
the corank selected here.

**Diagnostic obligation:** not-required.

**Facets:** `individual-corank`, `shared-corank`, `individual-corank-override`, `array-rank-independent`.

**Oracle:** Four actual corank runs guard NUM_IMAGES()==1 before allocation. Each uses a saved
scalar nonpointer noncoarray containing object, deferred component declarations,
reviewed small collective allocations, STAT handling, successful allocation before
LCOBOUND, defined payloads and matching deallocations. SIZE(LCOBOUND(component))
determines corank independently from array rank; a type-only compile cannot replace the
run.

**Oracle limitation:** Each run must actually meet its one-image guard and complete collective
allocation/deallocation; an independently recorded GNU -fcoarray=single execution
establishes a setup premise, not blanket processor conformance. Missing facilities,
launcher failures, allocation failures, crashes, verifier failures and timeouts stay
failures, never optional-unavailability skips. LCOBOUND is used only after allocation on
a final part with nonzero corank; no remote access or opaque team value is needed.

**Dependencies:** C751-C753 (PDF 93); R809-R811/C822-C828 (PDF 121-122); allocation R929-R941/C936-C955
and 9.7.1.2 p3-p5 (PDF 160-163); deallocation (PDF 165-166); LCOBOUND (PDF 425-426);
ALLOCATED (PDF 379-380); 19.6 (PDF 562-563); 4.2 p2(1) (PDF 46).
