### R731: SEQUENCE is a statement in a derived-type definition

**Source:** 7.5.2.3 R731; J3/24-007, 18 December 2023, PDF 89, printed 75, line 19. **Class:** Syntax.

**Definition:** A sequence-stmt is the SEQUENCE keyword. R726/R729 place that statement in a
derived-type definition before components. It is not a type-attr-spec spelling in the
TYPE header; the SEQUENCE attribute and sequence-type terms follow from its use under
p1.

**Diagnostic obligation:** required.

**Facets:** `sequence-statement-admission`.

**Oracle:** A nonempty nonparameterized SEQUENCE record has defined integer member checks. This is
statement admission, not storage-layout proof or intrinsic equality on the whole derived
value.

**Oracle limitation:** No arbitrary misspelling negative is manufactured for this one-token rule. Do not infer
numeric sequence classification from the word SEQUENCE alone or treat every
procedure-related component as a prohibited binding part.

**Dependencies:** R726/R728/R729/C740/C743 (PDF 88-89); C745 and p1 (PDF 89-90); 7.5.11 (PDF 109).

### C745: SEQUENCE constrains component presence, declared data types, parameters and bindings

**Source:** 7.5.2.3 C745 (R726); PDF 89, printed 75, lines 20-22. **Class:** Restriction.

**Definition:** A type with a SEQUENCE statement has at least one component. Every data component is
declared intrinsic or of a sequence type, the type has no type parameters, and no
type-bound-procedure-part appears. KIND and LEN parameters are both excluded. This does
not prohibit all POINTER/ALLOCATABLE data components or procedure-pointer components:
the data-component type condition and the distinction between R741 components and R746
binding parts still apply. Presence of CONTAINS already introduces the prohibited
binding part, even when that part has no bindings.

**Diagnostic obligation:** required.

**Facets:** `nonempty-type`, `intrinsic-and-sequence-data`, `nonsequence-derived-data-exclusion`, `enum-data-exclusions`, `kind-parameter-exclusion`, `length-parameter-exclusion`, `binding-part-exclusion`, `pointer-allocatable-procedure-component-admission`.

**Oracle:** Minimal pairs isolate empty type, ordinary/enum/enumeration data component types,
KIND/LEN parameters and empty/specific binding parts. They preserve other declaration
and interface premises. Run controls initialize all permitted intrinsic/nested data and
separately establish pointer, allocatable and procedure-pointer components without a
type-bound-procedure part. The latter is a general sequence type, not numeric/character
sequence and not an EQUIVALENCE operand.

**Oracle limitation:** No field is interpreted by an assumed storage layout or intrinsic == on the whole
derived value. Required diagnostics follow C745/4.2 p2(3); each must identify the actual
component, parameter or binding-part subject. Generic type/constant/function/expected
strings, mismatched END TYPE recovery, crashes, ASR failures and unsupported facilities
are ineligible.

**Dependencies:** R726 and R731 (PDF 88-89); R732-R734/C746-C747 (PDF 91-92); R736-R742/C749-C764 (PDF
93-95); R746 and C774/C784 (PDF 99-100); 7.6.1-.2 (PDF 109, 111-113); procedure-pointer
assignment and interface characteristics (PDF 196, 324, 333-334); 19.5.2/19.6 (PDF 556,

### S7.5.2.3-001: SEQUENCE component order specifies a storage sequence

**Source:** 7.5.2.3 p1, first two sentences; PDF 89, printed 75, lines 23-24; cross-reference in 7.5.1 p7, PDF 88. **Class:** Effect.

**Definition:** A SEQUENCE statement gives the type the SEQUENCE attribute, and its component-definition
order specifies the storage sequence for its objects. Canonical storage-association
rules express sequence objects through ordered ultimate-component storage sequences. The
portable witnesses below use those actual association and definition-status rules; they
do not equate symbolic numeric/character storage units with bytes or infer a physical
bit layout from arithmetic/model inquiries.

**Diagnostic obligation:** not-required.

**Facets:** `numeric-storage-order`, `nested-numeric-storage-order`, `character-storage-order`, `general-sequence-storage-evidence`.

**Oracle:** Four local typed EQUIVALENCE runs observe two default integers, a nested three-integer
sequence, default-character lengths 1/2, and the same character sequence with a
zero-sized member. No TARGET, pointer/allocatable object, nonsequence type,
initialization, coarray, BIND or use-associated equivalence object is present.
Executable same-type component and element/substring writes establish definition status
before reading the associated values; no zero-length substring is equivalenced. General
sequence-storage realization remains separate pending evidence.

**Oracle limitation:** Do not weaken run effects when a compiler lacks SEQUENCE/EQUIVALENCE support.
EQUIVALENCE is obsolescent, not a universal invalid program. The canonical restrictions
forbid many seemingly convenient overlays and do not imply conversion or mathematical
equivalence between different types. No unknown value, padding bit or unavailable
storage interpretation is asserted. The real BOZ needs-oracle member supplies no
representation premise.

**Dependencies:** 7.5.1 p3/p7 (PDF 87-88); C745 and p1 classification (PDF 89-90); 8.10.1/C8110-C8120 (PDF
146-148); 19.5.3.2 p2(1)/(3)/(5)/(7), p3 and 19.5.3.4 (PDF 559-561); 19.6.1-.2 and
19.6.5 p1(12)/(15), 19.6.6 p1(1)/(9) (PDF 562-565). 4.2 p2(1)-(2) (PDF 46) distinguishes
