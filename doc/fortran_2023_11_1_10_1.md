### S11.1.10.1-001: SELECT RANK selects at most one block based on an assumed-rank variable rank

**Source:** 11.1.10.1 p1; J3/24-007 PDF p222. **Class:** Effect.

**Definition:** A SELECT RANK construct selects at most one constituent block for execution based on the
rank of an assumed-rank variable. A name is associated with that variable in the same
way as for ASSOCIATE; detailed matching and execution are owned by 11.1.10.2, and
general associate-name attributes remain bounded by 11.1.3.3 where that section applies.

**Diagnostic obligation:** not-required.

**Facets:** `at-most-one-rank-block-selected`, `assumed-rank-selector-rank-controls-selection`, `associate-name-associated-with-selector`.

**Oracle:** Which block executed is observable through distinct sentinels; evaluation of the
selector or inquiries such as RANK are not used as the oracle.

**Oracle limitation:** This source-only catalogue records pending plans only. It creates no Fortran test
program, invokes no processor, approves no fixture or oracle, and claims no coverage.
Future SELECT RANK fixtures must preload targets with sentinels distinct from every
value any block could write and observe only final values to prove which block executed.
They must not infer selector evaluation from side effects, call counts,
short-circuiting, deliberate errors, temporaries, or evaluation order. They must not use
the RANK intrinsic as the oracle for rank selection; expected execution must follow from
the declared dummy/actual association controlled by the fixture and the selected block
sentinel. Assumed-size, assumed-rank, and sequence-association cases require Clause 15
dependencies before execution approval.

**Dependencies:** 11.1.10.2 in this packet;11.1.3.3 already registered for general associate-name
attributes;8.5.8.7 assumed-rank registered;15 dummy argument and argument association
