### S10.1.5.2.4-001: Execution of numeric operations with results undefined by processor arithmetic is prohibited

**Source:** 10.1.5.2.4 p1 first sentence; J3/24-007 PDF p177. **Class:** Restriction.

**Definition:** A program shall not execute a numeric operation whose result is not defined by the
arithmetic used by the processor.

**Diagnostic obligation:** context-dependent.

**Facets:** `integer-division-by-zero-boundary`, `integer-overflow-boundary`, `real-overflow-or-invalid-boundary`.

**Oracle:** Negatives need exact source attribution to the executed numeric operation and
independent proof that the result is not defined by the processor arithmetic. Positive
controls must be identical except for the defining operand change and must use exact or
otherwise portable results.

**Oracle limitation:** This source-only catalogue records pending plans only. It creates no Fortran test
program, invokes no processor, approves no fixture or oracle, and claims no coverage.
Future fixtures must use independently derived literal, inquiry, or source-relation
oracles and must not infer evaluation order, short-circuiting, which operand was
evaluated, or whether an operand was evaluated. They must not rely on compiler
agreement, address arithmetic, TRANSFER, emitted assembly, undefined reads, or any
numeric result that 10.1.5.2.4 permits to differ through mathematically equivalent
rewriting. Floating-point tolerance is not an escape hatch for a value that is not
portably determined.

### S10.1.5.2.4-002: Raising a negative real value to a real power is prohibited

**Source:** 10.1.5.2.4 p1 second sentence; J3/24-007 PDF p177. **Class:** Restriction.

**Definition:** A numeric operation that raises a negative real value to a real power is prohibited.
This is separate from integer powers and from complex bases or powers.

**Diagnostic obligation:** context-dependent.

**Facets:** `literal-negative-real-real-power`, `variable-negative-real-real-power`, `integer-power-separation`.

**Oracle:** Attribute only cases with real base value known negative and real exponent. Negative
integer bases, integer exponents, and complex exponentiation belong to other

### S10.1.5.2.4-003: Numeric rewrite latitude is limited by mathematical equivalence and parentheses integrity

**Source:** 10.1.5.2.4 p2-p3; J3/24-007 PDF p177. **Class:** Restriction.

**Definition:** After the interpretation of a numeric intrinsic operation is established, the processor
may evaluate a mathematically equivalent expression only if the integrity of parentheses
is not violated. Numeric expressions are mathematically equivalent when their
mathematical values are equal for all possible values of their primaries, but
mathematically equivalent numeric expressions can produce different computational
results.

**Diagnostic obligation:** not-required.

**Facets:** `parentheses-integrity-boundary`, `computational-difference-oracle-boundary`.

**Oracle:** No fixture may require a processor to choose or reveal an alternative form. Parentheses
tests must use source expressions where the standard interpretation is independently
fixed and the expected result is not a floating value that a permitted rewrite could
alter.
