### S7.5.4.2-001: A component's individual array specification takes precedence over DIMENSION

**Source:** 7.5.4.2 p1; J3/24-007, 18 December 2023, PDF 94, printed 80, lines 23-26. **Class:** Effect.

**Definition:** An individual component-array-spec or a statement-level DIMENSION clause makes the data
component an array. If the individual declarator has a specification, that specification
determines rank and, for explicit shape, bounds; otherwise the DIMENSION specification
does so. The containing object can be scalar while the component is an array. The rule
does not give unallocated or unassociated deferred-shape arrays defined bounds.

**Diagnostic obligation:** not-required.

**Facets:** `individual-shape`, `shared-dimension`, `individual-rank-override`, `individual-bound-override`, `zero-extent`.

**Oracle:** Five initialized runs check individual and shared rank/bounds, per-component rank and
bound overrides, and a zero-extent array beside a defined scalar. Nonzero arrays have
exact small LBOUND/UBOUND/SHAPE checks. The empty array is never indexed and is not
given a false declared-lower-bound inquiry expectation.

**Oracle limitation:** Every written component-array-spec must independently satisfy R740/C750/C754/C755 even
if an individual suffix overrides a shared specification. A valid active shape does not
legalize an invalid unused one. Deferred-shape allocation/association and default
initialization are canonical dependencies, not new obligations manufactured from the
notes. Preserve runs if implementations lack the feature.

**Dependencies:** R738-R740/C750/C754/C755 (PDF 93); 8.5.8.2-.4 (PDF 125-126); RANK, SHAPE, SIZE, LBOUND
and UBOUND with their zero-extent and allocation/association qualifications (PDF 449,
456, 459, 425, 469); 7.5.4.6/R743/C767 (PDF 96-98); allocation/association (PDF 160-165,
195-196); 19.6.1-.2/19.6.5 (PDF 562-563); 4.2 p2(1) (PDF 46).
