### S4.3.8-001: DATA initialization from a default real constant does not use extra default-real precision

**Source:** 4.3.8 p1 first list item; J3/24-007, 18 December 2023, physical PDF 51. **Class:** Effect.

**Definition:** When a default real constant is used to initialize a double precision real data object
in a DATA statement, the processor does not use more precision from that default real
constant than can be represented in a default real datum.

**Diagnostic obligation:** not-required.

**Facets:** `default-real-data-initialization-rounded-before-double`.

**Oracle:** The plan compares the DATA-initialized double value only with the value obtained by
first forming a default real datum, using a model guard to avoid vacuity on processors
where the chosen decimal spellings do not distinguish default and double precision. The
explicit double literal is a mutation sentinel, not the expected value.

**Oracle limitation:** No existing main catalogue was found that specifically owns this historical
DATA-initialization precision rule; doc/catalogues/data_statement_8_6_7.json covers DATA
syntax and many DATA effects but not this extra-precision prohibition. The guarded plan
avoids requiring a particular real model or decimal conversion beyond a proven
distinguishing branch.

**Dependencies:** Confirmed existing related catalogue opened: doc/catalogues/data_statement_8_6_7.json.
Numeric model inquiries from clause 16 may be used only to select a nonvacuous guarded
branch.
