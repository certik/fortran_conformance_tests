### S7.5.7.2-001: Extensions inherit parent entities with their original attributes

**Source:** 7.5.7.2 p1; PDF104, printed90, lines11-14. **Class:** Effect.

**Definition:** An extended type acquires all parent type parameters and components and the
nonoverridden type-bound procedures, retaining their attributes. Inaccessible
components/bindings are inherited without becoming accessible in unrelated scopes.
Additional parameters, components and bindings are permitted but not required. Inherited
procedure-pointer components remain components; FINAL bindings have their own
noninheritance/finalization rules and are not silently treated as methods.

**Diagnostic obligation:** not-required.

**Facets:** `inherited-public-components`, `inherited-private-component-identity`, `all-parameters-order-source-use`, `retained-data-attributes-source-use`, `nonoverridden-bindings-source-use`, `retained-private-binding-source-use`, `deferred-and-nonoverridable-source-use`, `additional-entity-union-source-use`, `zero-additions-source-use`, `final-binding-boundary-source-use`.

**Oracle:** Two runtime cases observe inherited public values (3,7) with marker41 and independent
private/public homonym values (7,9). The private provider setter writes only its
CLASS(parent) dummy's own hidden field; the unrelated child's public hidden is set
separately. The getter result and public field are checked after the calls return. No
modified overlapping actuals, private client selectors or constructor-order setup are
used.

**Oracle limitation:** The private-component setter writes through its CLASS(parent) dummy without reading an
undefined old value; all observations occur after return. Type extension is not module
descent. Parameter order, component order, initialization and finalization are not
duplicate local oracles.

**Dependencies:** 3.84 (PDF29); 7.5.7.2 notes and 7.5.7.3 (PDF104-106); 7.5.3.1/.2 (PDF91-92); 7.5.4.7/.8

### S7.5.7.2-002: The implicit parent component is scalar, nonpointer and nonallocatable with parent parameters

**Source:** 7.5.7.2 p2, first sentence; PDF104, printed90, lines15-16. **Class:** Effect.

**Definition:** Every extended type has a scalar, nonpointer, nonallocatable parent component of the
parent's type and type parameters. This component is not an independently allocated
object or a pointer to a separately copied parent. Its scalar nature does not make an
array parent's component selection scalar: data-ref rank still depends on the full
selector. Initial whole-parent observations use nonabstract parents.

**Diagnostic obligation:** not-required.

**Facets:** `scalar-parent-type-observable`, `parent-parameter-values`, `nonpointer-canonical-pair-plan`, `nonallocatable-canonical-pair-plan`, `array-designator-boundary`, `abstract-whole-parent-source-use`.

**Oracle:** Three runtime cases observe a scalar parent component through RANK=0 and an explicit
TYPE(parent) helper yielding17; keyword-instantiated abstract parameters k=2,n=3,m=5
through the actual parent selector; and rank1 for an array parent designator versus
rank0 for one element's parent. Objects and markers are defined before inquiry or calls.
No pointer/allocatable-absence or storage-layout property is inferred.

**Oracle limitation:** Do not generalize RANK(child%parent)=0 to an array data-ref. A nonpointer dummy can
associate with a pointer's target, so that call alone would not prove nonpointer status.
Abstract whole-parent references have the independent C911 barrier even though
inheritance itself is legal.

### S7.5.7.2-003: The parent component takes its parent name and original defining-module accessibility

**Source:** 7.5.7.2 p2, second/third sentences; PDF104, printed90, lines16-18. **Class:** Effect.

**Definition:** The parent component's name is the parent type name used for the extension, which can be
a local USE rename. If the extended type is defined in a module, the parent component
has the accessibility that the parent type has in the module where that parent type was
defined. This is not the child's component default, an importing module's changed
accessibility for the local type alias, or the parent components' individual
accessibility.

**Diagnostic obligation:** not-required.

**Facets:** `ordinary-parent-name-source-use`, `use-alias-component-name`, `original-module-public-access`, `private-parent-component-source-use`, `parent-access-not-component-access`, `outside-module-condition-source-use`.

**Oracle:** One shared N case compiles provider, extension and client in order. Provider original
and its payload are PUBLIC; extension alias is PRIVATE and its child has a PRIVATE
component default. An owner CLASS(original) setter defines payload17 through the actual
parent type, independently from the client object%alias%payload selector. The
child/object/initializer are exported, and no private local marker or unavailable type
name is used by the client.

**Oracle limitation:** N uses a nonabstract parent and legal module compilation order. No private type-name
constructor or private representation is accessed. Multiple imported aliases require the
selector associated with the chosen EXTENDS parent name; unrelated spelling/layout
equivalence is not an oracle.

**Dependencies:** 7.5.7.1 p2/NOTE1 and R728 (PDF104/88); 3.144.10 (PDF40); 7.5.2.2, 7.5.4.8 and 8.5.2

### S7.5.7.2-004: Parent-component views are inheritance associated and ancestor components recurse

**Source:** 7.5.7.2 p2, final sentences; PDF104, printed90, lines18-20. **Class:** Effect.

**Definition:** Components of the parent component are inheritance associated with their corresponding
inherited components. An ancestor component is either the immediate parent component or
an ancestor component of that parent component. The recursive ancestor-component
relation is not reflexive in the way extension of types is: the whole child is not its
own parent component. Association does not imply independently copied fields or an
observable processor storage layout.

**Diagnostic obligation:** not-required.

**Facets:** `direct-associated-views`, `recursive-ancestor-views`, `persistence-and-private-source-use`, `constructor-order-boundary-source-use`.

**Oracle:** Two sequential runtime cases observe direct parent/inherited paths sharing3, then7,
then11 while marker41 persists, and recursive root paths sharing31 then37 while mid/leaf
markers41/43 persist. Each mutation completes before any comparison; no overlapping
actual arguments, address comparison or positional constructor supplies the result.

**Oracle limitation:** Only accessible nonabstract paths are designated. Writes through an associated dummy, if
a later helper is used, occur only through that dummy and are observed after return;
simultaneous aliasing would violate 15.5.2.14.

**Dependencies:** 3.7.4/3.30.2 (PDF19/22); 19.5.4 (PDF561); 9.4.2 (PDF151-152); 10.2.1.3 (PDF190);
15.5.2.14 (PDF347-348); 19.6.1/.5 (PDF562-563); 7.5.4.7 (PDF98); R756/C7103/C7104/C7107

### S7.5.7.2-005: A same-spec inherited generic is extended, subject to canonical generic restrictions

**Definition:** A local generic binding with the same generic-spec as an inherited binding extends that

inherited generic. A specific member may separately be overridden; that is not generic
overriding or permission to re-add an inherited member. Generic selection uses the

**Diagnostic obligation:** not-required.

length alone does not distinguish. No S-owned policy violation or unrelated generic
