### C850: A shared explicit intrinsic generic and accessible generic interfaces agree on procedure class

**Source:** 8.5.11 C850, physical PDF130, printed116 **Class:** Restriction.

**Definition:** When an intrinsic generic name is explicitly declared INTRINSIC and is also the name of
one or more generic interfaces accessible in the same scoping unit, the intrinsic
generic and every procedure in those interfaces must all be functions or all be
subroutines. The explicit declaration, shared generic identity, accessibility and scope
conditions are retained.

**Diagnostic obligation:** required.

**Facets:** `function-extension-control`, `subroutine-extension-control`, `intrinsic-function-subroutine-conflict`, `intrinsic-subroutine-function-conflict`, `multiple-accessible-interfaces`, `explicit-premise-and-C1514-source`.

**Oracle:** Complete homogeneous-class controls and source-qualified cross-class negatives, with
exact generic identity, accessible scope and independently valid repairs. C1514 overlap
remains an explicit causal-analysis gate.

**Oracle limitation:** Required reporting capability does not mandate fatal exit, specific English or a printed
constraint code. Generic ambiguity, unsupported intrinsic facilities, duplicate
unrelated entities, missing interfaces and native compiler failures are not
interchangeable with the class mismatch.

**Dependencies:** 15.4.3.4.1;15.4.3.4.5p1/C1514;15.4.3.7;16.7;19.3;4.2p2.

### S8.5.11-001: A specific intrinsic used as an actual argument requires explicit INTRINSIC specification

**Source:** 8.5.11 p2 explicit-declaration sentence, physical PDF130 **Class:** Restriction.

**Definition:** When a specific intrinsic name is used as an actual argument, it must be explicitly
specified INTRINSIC. Eligibility remains restricted to the allowed specific intrinsic
functions and compatible dummy-procedure characteristics. The attribute is not a way to
pass a generic-only name, a Table16.3 restricted specific or any arbitrarily named
procedure.

**Diagnostic obligation:** context-dependent.

**Facets:** `allowed-specific-actual`, `generic-specific-name-overlap`, `explicit-declaration-mechanisms`, `restricted-specific-canonical-owner`, `other-intrinsic-context-boundaries`, `missing-declaration-reporting-source`.

**Oracle:** Meaningful eligible specific-procedure positive controls and finite
declaration/eligibility source relations. Specific characteristics and callback results
come from the standard, not compiler agreement.

**Oracle limitation:** No compulsory S-level rejection without a separate diagnostic basis, no arbitrary
generic dispatch through a specific actual and no new intrinsic-result effect owner.
