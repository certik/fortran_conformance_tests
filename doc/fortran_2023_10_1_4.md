### S10.1.4-001: An intrinsic operation requires the values of its operands

**Source:** 10.1.4 p1; J3/24-007 PDF p174. **Class:** Effect.

**Definition:** When an intrinsic operation is evaluated, the operation requires the operand values for
that intrinsic operation. This value requirement does not impose a left-to-right operand
evaluation order and is subject to later rules that permit omission of unneeded
expression parts.

**Diagnostic obligation:** not-required.

**Facets:** `unary-intrinsic-operand-value`, `binary-intrinsic-both-operand-values`, `array-intrinsic-element-values`.

**Oracle:** Use operands whose values are established before the expression and whose literal result
would change if an operand value were different. Do not use function side effects,
undefined values, or evaluation counts as the oracle.

**Oracle limitation:** This source-only catalogue records pending plans only. It creates no Fortran test
program, invokes no processor, approves no fixture or oracle, and claims no coverage.

### S10.1.4-002: Function-reference side effects in a statement are restricted except in listed controlling contexts

**Source:** 10.1.4 p2; J3/24-007 PDF p174. **Class:** Restriction.

**Definition:** A function reference in the logical expression of an IF statement, the mask expression
of a WHERE statement, or the concurrent-limits or concurrent-steps of a FORALL statement
is permitted to define variables in the corresponding subsidiary action, WHERE
assignment, or FORALL assignment statement. Except in those cases, function-reference
evaluation within a statement shall neither affect nor be affected by evaluation of any
other entity in the statement, and an actual argument that the function defines or
undefines, or any associated entity, shall not appear elsewhere in the same statement.

**Diagnostic obligation:** context-dependent.

**Facets:** `if-controlling-expression-permitted-definition`, `where-mask-permitted-definition`, `forall-control-permitted-definition`, `function-affects-other-entity-restricted`, `function-affected-by-other-entity-restricted`, `defined-actual-argument-reappears-restricted`, `associated-entity-reappears-restricted`.

**Oracle:** Positive exception controls may observe reached literal values in the listed controlling
constructs. Restriction negatives need exact same-statement source relations and
independent valid repairs; do not infer an order of evaluating expression entities.

### S10.1.4-004: Elemental binary operations on arrays are applied element by element

**Source:** 10.1.4 p4; J3/24-007 PDF p174. **Class:** Effect.

### S10.1.4-005: Elemental unary operations on arrays are elementwise, same shape, and order-flexible when pure

**Source:** 10.1.4 p5; J3/24-007 PDF p174. **Class:** Effect.

**Definition:** When an elemental unary operator operates on an array operand, the operation is
performed element by element and the result has the same shape as the operand. If an
elemental operation is intrinsically pure or implemented by a pure elemental function,
the element operations may be performed simultaneously or in any order; that latitude is
not an observable ordering requirement.

**Diagnostic obligation:** not-required.

**Facets:** `intrinsic-unary-array-values`, `unary-result-same-shape`, `pure-elemental-function-array-values`, `pure-element-order-latitude`.

**Oracle:** Only element values and shape are observable here. The pure-element order sentence is a
permission: tests may ensure their expected value is order-independent but must not
assert a particular order or simultaneity.

### S10.1.4-006: Conditional expressions test scalar logical expressions in order and evaluate the chosen expression

**Source:** 10.1.4 p6; J3/24-007 PDF p174. **Class:** Effect.

**Definition:** Evaluation of a conditional-expr evaluates each scalar-logical-expr in order until one
is true or none remain. If one is true, its subsequent expr is chosen; otherwise the
final expr is chosen. The chosen expr is evaluated and its value is the value of the
conditional expression.

**Diagnostic obligation:** not-required.

**Facets:** `first-true-selects-subsequent-expr`, `later-true-not-selected-after-earlier-true`, `no-true-selects-last-expr`, `chosen-expr-value-result`, `condition-order-without-side-effects`.

**Oracle:** Conditional-expression selection can be checked by distinct literal result values. Do
not use side effects in conditions or branch expressions to prove skipped evaluation,
despite the source rule about chosen evaluation.

### S10.1.4-007: Conditional-expression declared and dynamic properties come from its expr operands and chosen expr

**Source:** 10.1.4 p7; J3/24-007 PDF p174. **Class:** Effect.

**Definition:** The declared type, kind type parameters, and rank of a conditional-expr are the same as
