### R745: The private component default statement is the bare PRIVATE form

**Source:** 7.5.4.8, R745; J3/24-007, 18 December 2023, PDF 99. **Class:** Syntax.

**Definition:** A private-components-stmt consists of PRIVATE alone. It is the statement inside a type
definition that supplies a component default, not a type-header access attribute, a
per-component access-spec or a named module access statement.

### C771: A private component default statement requires a module specification context

**Source:** 7.5.4.8, C771, C771.private-components-statement, C771.type-definition-context, C771.module-specification-part; J3/24-007, 18 December 2023, PDF 99. **Class:** Restriction.

**Definition:** A private-components-stmt is permitted only when its type definition is within the
specification part of a module. A procedure body does not become that specification part
merely because its procedure is contained in a module.

**Oracle:** All body components and type endings are valid. The intended condition is the
private-components statement context, not type-name accessibility.

**Oracle limitation:** Do not silently interpret every physically enclosing module as its specification part or
claim unexamined interface/submodule boundary cases. Every planned negative needs a

### S7.5.4.8-001: Local component accessibility follows explicit attributes or the defining type default

**Source:** 7.5.4.8, p1, p1.local-component-part, p1.private-default-condition, p1.public-default-otherwise, p1.explicit-access-spec, p1.default-when-unspecified, p1.original-defining-type; J3/24-007, 18 December 2023, PDF 99. **Class:** Effect.

**Definition:** Components declared in a type component-part are private by default when the definition
contains a private-components-stmt and public otherwise. An explicit component
access-spec takes precedence; without it, the component uses the default of the type
definition in which it was declared. Type-name accessibility and type-bound binding
accessibility are separate properties.

**Diagnostic obligation:** not-required.

**Facets:** `public-default-client-use`, `private-default-owner-use`, `public-overrides-private-default`, `private-overrides-public-default`, `inherited-original-default-graph`, `type-name-and-component-independence`, `private-default-constructor-link`.

**Oracle:** Accessible runtime paths have explicitly defined values and complete separate
module/client contexts. Inaccessible paths need their own canonical diagnostic
obligation or a separately labelled processor policy.

**Oracle limitation:** An accepted owner-side reference alone does not prove foreign inaccessibility. A private
type name, hidden binding or retained inherited attribute cannot substitute for the
actual local component default.

**Dependencies:** 7.5.4.8 p1;R745/C771;7.5.7.2 p1, PDF104;7.5.10 C7107, PDF107;14.2, PDF318-321.

### S7.5.4.8-002: Private component names are accessible only in the defining module and its descendants

**Source:** 7.5.4.8, p2, p2.private-component-name, p2.defining-module-access, p2.descendant-access, p2.only-these-scopes; J3/24-007, 18 December 2023, PDF 99. **Class:** Restriction.

**Definition:** A private component name is accessible only within the module containing its type
definition and within descendants of that module. Access to an object or public type
name does not by itself expose the private component name. Whole-object operations and
name-based component access are distinct.

**Diagnostic obligation:** not-required.

**Facets:** `defining-module-reference`, `child-submodule-reference`, `grandchild-submodule-reference`, `foreign-constructor-exclusion-link`, `whole-object-control`, `component-name-use-graph`.

**Oracle:** Use complete modules and descendant module-procedure definitions, not textual proximity
as a visibility proof. Opaque client-side objects are observed only through valid
whole-object operations and owner-accessible procedures.

**Oracle limitation:** This source restriction alone does not manufacture the4.2 p2(3) diagnostic obligation
for every illegal component reference. A compiler extension or missing submodule
implementation is not its oracle.

**Dependencies:** 7.5.4.8 p2;14.2.2-.3, PDF318-321;7.5.10 C7107, PDF107;9.4.2, PDF151-153;19.5 host/use
association.
