### S10.1.11-001: Specification expressions default to constant expressions outside listed specification contexts

**Source:** 10.1.11 p1; J3/24-007 PDF p185. **Class:** Restriction.

**Definition:** A specification expression is an expression limited for specifications such as length
type parameters and array bounds. A specification-expr shall be a constant expression
unless it appears in an interface body, the specification part of a subprogram or BLOCK
construct, a derived type definition, or the declaration-type-spec of a FUNCTION
statement.

### S10.1.11-003: Specification functions are pure nonintrinsic external/module functions with no dummy procedure argument

**Source:** 10.1.11 p4; J3/24-007 PDF p186. **Class:** Effect.

**Definition:** A specification function is a pure function that is not a standard intrinsic function,
not an internal function, not a statement function, and has no dummy procedure argument.
This requirement records the classification criteria for being a specification function;
it does not by itself prohibit use of a non-qualifying function. When such a function
appears where a restricted expression requires a specification function, C1011 is the
owning restriction.

### S10.1.11-006: Same specification-part dependencies used by specification inquiries are specified previously
