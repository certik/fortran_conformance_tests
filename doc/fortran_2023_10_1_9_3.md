### S10.1.9.3-001: Intrinsic operation result type comes from Table 10.2 and result shape follows the operand-shape rule

**Source:** 10.1.9.3 p1; J3/24-007 PDF p184. **Class:** Effect.

**Definition:** For an intrinsic operation [x1] op x2, the result type is specified by Table 10.2. The
result shape is the shape of x2 if the operator is unary or if x1 is scalar, and
otherwise is the shape of x1.

**Diagnostic obligation:** not-required.

**Facets:** `intrinsic-result-type-table`, `unary-result-shape-from-operand`, `scalar-left-binary-result-shape-from-x2`, `array-left-binary-result-shape-from-x1`.

**Oracle:** Use typed assignment contexts and SHAPE inquiries with expected extents derived from
declarations. Do not infer shape from element counts after an illegal nonconforming
operation.

### S10.1.9.3-007: Numeric same-family binary result kind follows same-kind, greater-range, greater-precision, or one-operand rules

**Source:** 10.1.9.3 p4 bullet 4; J3/24-007 PDF pp184-185. **Class:** Effect.

**Definition:** For a numeric intrinsic binary operation with operands of the same type and kind, or
with one real and one complex of the same kind, the result kind is identical to each
operand's kind. For two integer operands of different kinds, the result kind is that of
the operand with greater decimal exponent range when the ranges differ; when the ranges
are equal, the processor-dependent result kind is the same as one operand kind. For real
and complex operands with different kinds, the result kind is that of the operand with
greater decimal precision when precisions differ; when precisions are equal, the
processor-dependent result kind is the same as one operand kind.

**Diagnostic obligation:** not-required.

**Facets:** `same-type-same-kind-result-kind`, `real-complex-same-kind-result-kind`, `integer-different-range-greater-kind`, `integer-equal-range-one-operand-kind`, `real-complex-different-precision-greater-kind`, `real-complex-equal-precision-one-operand-kind`.

**Oracle:** The equal-range integer and equal-precision real/complex cases are intentionally weak
one-of-operand-kind oracles because the standard leaves the choice processor dependent.
Unambiguous cases must dynamically establish distinct RANGE or PRECISION before
expecting the greater one.
